# 声学检查前的本地候选与正式请求

后台 0.15.64 候选修复自动声学检查的一处边界：普通 VAD 开始收集本地语音时，`TraceBook` 已创建尚无结果的记录，但它还可能未唤醒、未送 ASR、未绑定回答代次。此前检查器把这类候选与真正进行中的请求一起立即拒绝。该行为可以用真实 `TraceBook` 和原 `SmokeRun.acoustic_probe` 离线复现，并不说明设备服务卡死。

新检查最多以 2.5 秒预算观察这类候选。只有 origin 为 voice、无回答代次、阶段仅含本地起音／断句、没有唤醒／ASR／任务等准入信息的记录可等待。原待观察记录必须持续可见，最终明确以 `rejected + wake_closed` 结束。被取消、因其他原因拒绝、消失、未知或变成正式请求的记录均不能当作空闲。观察中新增并快速完成的正式请求也会阻止测试。

健康回执新增只读 `capture_generation`：正在采集时取已有会话快照的回答／取消代次，停采时为 null；它不是设备标识，也不启动采集。观察要求同一后台实例、代次、USB、等待唤醒状态，且本地唤醒／语音 ASR／播放参考计数保持。停止、换路、重开麦克风或新请求改变这些条件时拒绝。旧后台没有这个字段时，仍保留原拒绝行为，不猜测归属。各 RPC 原有期限保持；慢 RPC 即使越过观察预算，也只能失败，不能迟到后准许播放。

等待结束后，检查器会在原生状态和可选探针准备完成后再读一次诊断与健康状态。记录集合变化或录音归属失效时，不播放测试问句。原生限时采集、Home 停采、维护重开不自动开麦和失败收尾保持。这里没有改变普通对话的 VAD、唤醒、ASR、插话或播报策略。

`pre_probe_idle_evidence` 只含 schema、固定 state、观察时长和各次候选／请求／未知记录计数，不复制 ID、正文、来源字符串、异常消息或录音。`settled` 表示曾观察到候选，随后在预算内明确结束；`owner_activity`、`unknown_pending`、`unsupported`、`capture_changed`、`evidence_lost`、`timed_out` 均不准播放。没有候选时保持 null，不虚构一次等待。离线复核兼容旧报告；新报告的未结束等待、矛盾计数或扩展字段不能支持通过结论。

同一离线组件输入下，原后台63检查器在零秒以 `owner_request_pending` 停止、零次刺激；新检查器等到 0.5 秒的本地拒绝后，只产生一次模拟刺激并完成原问答／20秒观察检查。使用真实记录器和原执行分支，设备、扬声器、麦克风和云服务均未调用。另覆盖未绑定代次的 ASR、快速完成的新任务、记录消失、取消、晚到 RPC、换路、前置准备期间变化及不留正文等边界。实机观察另记，不据此确认此前第三轮的唯一原因。

## 既有实机证据与缺口

冻结后台61的三轮组在 2907.133 秒结束，结果为失败。前两轮分别在 908.704、908.649 秒确认实际黑屏，随后各完成一次中文唤醒、ASR、Dot 回答与播完，观察 20.002、20.010 秒，零暂停。第三轮在 909.406 秒确认黑屏，但播放刺激前即遇 `owner_request_pending`；没有播放第三条问句，也没有启动该轮探针。因此只计两轮完整通过，第三轮不能记为通过或漏唤醒。

独立终审确认原后台61、APK／配置保持，资源关闭、模型子进程与测试自有 caffeinate 退出、停采计数稳定。收尾后的 11 条诊断均为完成或拒绝，但失败当时的那条 pending 记录没有被保留，不能唯一判定其阶段。两轮探针仍为 unavailable，不冒充三路声学匹配。原后台58第三轮漏唤醒记录继续保留。

随后后台63完成两批合并升级及一次同公开问句的六项实机检查；[当前部署记录](CURRENT_DEPLOYMENT.md#01563code90-dot-通信边界与组合计划)明确其版本和范围。本候选不自动重复已失败的长组，也不启动72小时验收。
