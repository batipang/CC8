# P0-05：只读运行观察（0.13.2 候选）

新版可显式加 `--expect-backend 0.14.5`，每次health轮询都核对后台自报版本，报告保存期待值。不同版本、缺失或非法版本记录固定 `backend_version_mismatch`，不计入成功资源点，整轮不得completed；只保留固定错误码，不存任意服务字符串。默认不指定仍兼容旧后台。它绑定自报后台版本，不证明源码/二进制身份、APK全时一致或声学功能；初始来源仍须单独核对，进程变化仍按分段呈现。

`cc8 observe` 在指定期限轮询 owner-only health IPC，记录连接/工作线程状态及 Mac 后台自己的 RSS、峰值 RSS、Python 线程、文件描述符和累计 CPU 时间。它不打开设备、麦克风或相机，不交办 Dot，不重启或调整服务，不替代真人/物理验收。

## 启动与停止

先把受测版本和现场条件按 TODO 固定，再在实际运行目录执行：

```sh
# 最长 72 小时，默认每分钟读取一次；保持该终端/进程运行
./cc8 observe

# 新版候选的独立窗口，防止混入旧后台采样
./cc8 observe --expect-backend 0.14.5

# 短轮检查或故障实验，用新文件保存，已有文件不会覆盖
./cc8 observe --seconds 600 --interval 10

# 从另一份代码只读观察旧运行目录，必须显式指定 owner socket
./cc8 observe --seconds 60 --socket /实际运行目录/device-access/private/voice-runtime/announce.sock
```

Ctrl+C 会保存取消时已有数据并退出 130；没有自动创建定时任务或后台监控。JSON 默认保存在忽略的 device-access/private/observations/，目录 0700、文件 0600；每 5 分钟及正常退出/取消原子更新，异常退出可能只留下上一个检查点。用 --output 可指定已有 owner-private 目录内的新 JSON，不改外部目录权限，不覆盖旧文件/链接。

期限为 0.05～259200 秒，间隔 0.05～300 秒；计划采样最多 6000 条，72 小时默认 60 秒约 4320 条。超出容量组合会在读 IPC/建报告前拒绝。查询使用整体剩余预算且单次不超过 5 秒；一次不可用不会结束全轮，继续留下故障和恢复的证据。

标准 `voice-runtime/announce.sock` 观察从开始到写完最终报告持有共享的 `automation-test.lock`。设备检查、服务故障检查和隔离界面重放使用同一文件的独占锁，两类操作需要错开，冲突时命令立即退出。标准运行目录必须已存在且仅当前用户可访问。其他名字的外部测试 socket 仍可独立采样，报告用 `automation_lock_held` 区分。

该保护适用于新版启动的观察。之前已启动的 0.14.20 窗口继续使用原进程，人工拔插、手动操作或独立部署命令仍须避开观察窗口。

## 指标与缺口

候选 health 附加随机运行实例标识（重启改变）和资源快照；快照最多每秒一次，只查询自身 PID 的数值 RSS，不保存 PID/进程参数/文件名。RSS 由固定 /bin/ps 的 rss 字段按 KiB 换成 bytes，峰值 RSS 对 Darwin/Linux 单位分别处理。Python 线程数**不包括全部 native 线程**；FD 扫描可能包括探测自身的描述符。不可取得的值为 null，不能用零冒充。

报告不保留实例标识、识别/回答、提供方正文、密钥或设备标识，只给本轮 segment 序号与白名单数据。每个实例分段计算资源首/末/最小/最大/差值和线性斜率；不跨进程重启比较内存或 CPU。CPU 百分比按本进程累计时间差/观察间隔计算，以一核为 100%，多核时可超过 100%；不是整个 Mac 的 CPU 使用率。

旧后台没有资源和实例字段时仍可读取连接曲线，但 resource_coverage_incomplete_polls 明确增加，无跨进程斜率/CPU 推断，整轮为 partial。等待唤醒状态也是可选字段，不猜旧版本的状态。

- errors：IPC 不可用 / 非法快照；不记录异常原文，也不把不可读时间当健康。
- unhealthy_polls：模型初始化/识别 worker/回答 worker 未就绪的采样点。
- poll_gaps：间隔超过 5 秒和三个轮询周期中的较大值。wall_clock_discontinuities：同一区间内墙钟与单调时钟的增量差超过同一阈值。两项都检查窗口开始到首次采样、相邻采样，以及最后采样到终止时间。收尾使用报告里的同一组时钟读数，不增补 health 样本。原因可能是休眠、进程调度或调时。
- uptime_discontinuities：同实例 uptime 倒退，另起分段，不能把缺口接成完整连续运行。
- disconnected_polls：未连接设备的采样点；它不自动解释拔插的物理原因或是否应连接。

退出 0 仅表示规定窗口内采集及所需资源字段完整，**不是功能验收通过**。遇到故障/缺字段/采样缺口为 partial、退出 2；被取消退出 130。报告固定不声称通过物理切换、待机唤醒或长时验收，资源斜率也不自动等于泄漏/无泄漏结论。两个轮询之间的瞬时故障可能漏采。

## 独立核验 72 小时报告

观察结束后，用既有私有 JSON 和该轮固定的后台版本执行：

```sh
./cc8 audit-observation /实际私有目录/observe.json --expect-backend 0.14.20
```

复核要求计划时长 72 小时、单调时钟和墙钟均已满 72 小时、轮询间隔至多一分钟，以及同一进程分段的健康、已连接和资源齐全的采样。命令从原始样本重算首段、末段及相邻采样之间的缺口，用保存的汇总计数补充毫秒舍入可能遗漏的情况。进程重启、断连、缺字段和未完成检查点均退出 2。报告缺少逐样本版本时使用采集器的版本约束字段，不能据此证明运行二进制或设备 APK 的身份。

复核另从原始时间重算采样节奏。首次查询应在 5.2 秒内收到回执，后续相邻采样和末次采样到结束的间隔上限为配置间隔加 5.2 秒，其中 5 秒为 IPC 预算。超出时记录 `sample_cadence_gaps`，并报告 `max_sample_gap_seconds`。这项检查独立于旧的三周期缺口计数，可发现单次漏采，支持旧版已保存的报告。运行中的检查点仍不可当作完整 72 小时。

核验器还比较同一分段内后台运行时长与采样单调时钟。两者差值的最大跨度须在 5.2 秒内，给单次 IPC 最多 5 秒和计时舍入留出余量。固定不变或缓慢偏离的运行时长都会使验收失败，资源趋势也不再按这一分段汇总。现有旧版报告无需补字段，核验直接读取已有样本。

退出 0 表示已保存的后台观察窗口符合上述条件。输出只含数字趋势与固定原因，不改写输入，也不访问服务或设备。内存和线程趋势仍须结合负载审查，采样之间的瞬时故障、Android 资源趋势、待机唤醒和物理切换由各自证据确认。输入报告的来源仍需通过原观察进程和部署记录核对。

## 软件验证和真实测试边界

新增 11 项回归覆盖单位/缓存/无凭证 ps 环境、资源失败为 null、实际自身进程数值、实例分段与 CPU/内存斜率、旧后台缺字段、采样/墙钟/uptime 缺口、严格类型与容量、异常后继续、取消/边界、真实私有 Unix health fixture 和最小 PATH root CLI。未操作真实 CC8 或生产服务。

2026-11-04 的窗口边界回归模拟首次查询延迟、最后一次轮询后双时钟跳变和只有墙钟跳变三种情况。旧工具三种都漏记，新工具保留真实样本并返回 partial、退出 2。另用两个独立 Unix health 服务，以最小 PATH 启动原版和修复版 CLI，最后一次轮询后暂停并恢复各自进程。约 5.62 秒的无采样间隔让旧版返回 completed、退出 0，修复版记录一次 poll_gaps 并退出 2。此变更适用于新启动的观察。已有运行的报告可以用首末 `samples` 的双时钟读数和 `observation` 的最终双时钟读数独立核对窗口边界。

另外，在隔离 native eval 进程向实际双 KWS 连续输入 30 分钟 seed=20261102、RMS 0.002 的 16k/20ms 合成噪声，约 40.589 秒加速处理、native 累计 40.061 秒，无触发。采样峰值约 112.3 MiB，最后 20 分钟模拟音频对应的三点 RSS 均约 88.5 MiB，未见该轮持续增长。没有麦克风/云请求或音频文件；不是 30 分钟实际挂钟、真人负样本、4 小时误唤醒或 72 小时运行结果。

仍待部署后的 20 次物理 USB/Wi-Fi 往返、3 轮真实 15 分钟应用内黑屏唤醒、72 小时真实观察和服务登录/睡眠联调。不能用本工具的合成 fixture 关闭这些项目。当前运行安装未改变。
