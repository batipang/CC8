# 明确保存与恢复汇报补播进度

后台0.16.21／助手0.9.91 code128的软件候选，尚未部署。当前实际运行仍为0.16.19／code124；本批包含前一候选的只读原聊天队列。此功能补齐重启后的补播基线，不是原聊天续办，也不把已播摘要当成任务完成或已验证。

## 使用与保存范围

1. 选择所需的摘要聊天或已登记汇报范围，正常读取或播报工作汇报，然后暂停语音。在“设置 → 工作汇报来源 → 汇报选项 → 补播进度：明确保存／恢复”查看当前进度。
2. 点“保存当前进度”，核对来源、北京时间起点／上次读取截止、设备已确认播完的摘要数量和待补播数量，再明确确认。核对窗口两分钟有效，来源、线路、请求、语音上下文或真实播完记录变化后拒绝旧确认。只持久化确认时的进度；此后的播报不会自动更新已保存记录。
3. 最多8份，每份最多256项，总计256KiB，容量满时拒绝新保存，不自动淘汰。独立私有`work-report-progress.json`保留至手动删除，目录0700、文件0600，采用跨实例文件锁、修订检查和原子替换。保存的必要数据包括来源／登记成员、基线时间、结果标识、已读摘要、有限工具回执计数及已播标记；不保存完整聊天、录音、图片、原始工具输出、绝对项目路径或模型上下文。
4. 在同一入口选择已保存记录可查看范围和计数、明确删除单份或清空。删除只作用于这份私有存储，不撤销原任务、不删除来源登记或历史汇报快照，也不隐式清空当前内存进度。已保存的历史汇报仍使用独立的[快照管理](SAVED_WORK_REPORTS.md)。

## 恢复与后续查询

启动、连接恢复、打开列表均不自动恢复进度、选择来源、读取聊天、开启麦克风或播报。重启后先明确选回同一个聊天或登记成员范围，再查看记录，点“恢复补播进度”并确认。聊天标识／名称、登记成员标识／聊天／名称／项目须一致；无关登记增删造成的列表修订变化不冒充来源变化，但删除或重新登记原成员不能从旧记录恢复。

恢复替换当前内存补播基线和已播标记，清除旧编号快照与旧播放计划，保留当前明确选定来源和摘要接续对象。旧播放回执不能写入新进度。恢复不会追加、恢复、取消或重启原任务，也不立即查询或播报。

随后明确说“汇报上次汇报后的工作”，沿用原起点重新读取到当前时间，重新核验结果版本、补齐迟到收集与未播摘要，已确认播完且内容未变的摘要不会重复；内容更新重新汇报。原未播摘要若本次没有重新读到，继续明确标为“引用上次快照，当前未重新核验”，并保留覆盖不足提示。超过31天或时钟回退仍沿用原澄清规则，不静默丢弃旧待播结果。

恢复失败、存储损坏、修订冲突或保存耐久性未确认时，重新查看实际状态，不自动重试。设备只提交服务器提供的临时保存编号或已保存记录编号、修订与明确确认，不能提供正文、路径或任意目标聊天。

## 验证边界

自动检查使用实际汇报读取器与设备播完令牌、真实私有文件与跨实例锁、原控制器／协议，以及编译后的原生对话框。覆盖重建存储、部分播完、更新／迟到／未核验结果、来源隔离、旧确认／线路／播放回执、取消、容量、损坏、链接、并发CAS和耐久性未确认；这些软件检查不调用真实聊天或模型、不采集麦克风或相机。受保护CI、组合部署和真实来源验收分别记账；完整P1-01／P1-02／P1-10及最终72小时验收保持开放。
