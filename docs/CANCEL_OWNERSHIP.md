# 取消与后来请求的归属

后台 0.15.54 候选修复 P0-02 / P0-06 的关联并发边界，保留原签名 APK84、MiniMax ASR / TTS、Dot 与停止采集规则。已执行的工具动作不会因取消而回滚；已完成任务的结果仍保持完成。

## 同一事务内核对设备按钮

任务按钮原来先查任务 ID / running / generation，再调用取消。看图取消先核对当前 generation 或 nonce，再取消。设备线程与桌面文字 IPC 并行，检查之后可能已接纳新请求，旧按钮因此取消新一代工作。

现在两种按钮都在会话 guard 内完成匹配、取消和状态提示。Workspace 快照的内部锁在返回后释放；取消仍使用同一把可重入会话锁。这样可以先取消旧任务再接纳新请求，或先接纳新请求并拒绝旧按钮，不能把两种顺序拼接成对新任务的误取消。

## 模型取消与请求准入串行

会话失效先在 guard 内推进 generation、停止输出并清理旧状态。播放等待者随后在 cancel 首段内部临界区之后被唤醒。原实现之后直接取消大脑和语音 Provider；若新请求已在该间隙完成准入，旧清理会取消新的 Dot turn / MiniMax 请求。大脑取消与语音取消之间也可能插入新请求。

现在在取消 Provider 前重取会话 guard，核对仍由本次 generation 持有取消权；若已有后继取消，Provider 清理由后继负责。两个 Provider 的取消保持同一准入事务，原大脑取消异常时仍尝试语音取消的 finally 保留。播放 Condition 通知保留在 cancel 首段内部临界区之后，未移入新增的 Provider 临界区；调用方原已持有 guard 的路径仍可重入。允许的次序继续是会话 guard → 完成 Condition，完成等待不持 Condition 进入会话取消。

默认 Provider 的 cancel 只标记当前请求、唤醒自己的网络 I/O 或启动有界中断线程；模型执行和网络响应不在此等待。会话 guard → Provider 自有锁的次序与既有文字请求 / 识别准入路径一致，没有引入反向的回调获取顺序。网络超时、任意第三方工具的停止和物理播放结束仍有各自的边界，不能由这一锁修复作广泛保证。

## 复现与验证范围

`test_cancel_ownership` 用两条受控线程固定四个交错点：旧任务按钮、旧看图取消、播放等待者通知后的清理，以及大脑与语音取消之间。原版 `93aefe6` 的四项断言均失败，零夹具错误；修复后四项及两个控制通过。Provider 检查实际使用 DotBrain / Turn 与 MiniMax Transport / RequestSlot 的取消实现，不发网络或模型请求，也不打开设备。

两个控制分别验证当前任务可以正常停止且保留已完成结果，以及终态任务 / 不匹配看图按钮不会影响当前请求。116 项关联回归通过，覆盖清理失败、过期自检、看图、插话、播放锁、工作区与 Dot 回执。整批回归 / CI 与实机执行中验证分别留证；本节不把内存并发测试当作实际工具取消、系统睡眠或登录验收。
