# 每句收音与门控的无内容观察

本页起源于 0.14.10 源码候选，在原 `diagnostics`／`cc8 measure` 里补充可选 `capture` 和 `gate`，用来定位连续测试发现的额外回合，当时设备仍是 0.14.8。以下保留早期发现；最新 0.14.86 已部署的成句前统计见字段说明和 [当前部署](CURRENT_DEPLOYMENT.md)。这些统计未改变 VAD、AEC、唤醒、识别服务、阈值、打断规则或工具权限，不表示额外回合问题已经修复。

## 自动测试发现

0.14.8已完成三轮真实15分钟黑屏、合成声学唤醒及新问答播完确认。后续30问句原型先因将拒绝候选当成新请求而中止，原报告保留；修正测试判定后另开一次，首问完成，但播放第二个刺激之前出现了未由脚本交办的已准入语音回合，因此再次停止，最后确认设备前台、双端麦克风与相机关闭。没有继续重试，也没有将两次失败改写成30问通过。

额外回合当时标记echo_risk=true，文字/本地参考ASR比较没有将其拒绝；现有记录没有足够声学证据判断来源。下一轮需要按同一request ID对照捕获与门控观察，不能直接把它当成真人输入或声称已证明是自播报回声。私有证据：`voice-sequence-5c22cc9a.json`、`voice-sequence-8de02db4.json`及`automated-qa-findings-1793684222.json`；不提交识别/回答正文或录音。

## capture：已收尾句子的数值摘要

| 字段 | 含义 |
| --- | --- |
| frames | VAD开始报告句首到句尾的10ms帧数，不含开始报告前的preroll |
| voiced_frames / credible_frames | 现有近端检测器的voiced / credible帧数，非人工语音真值 |
| max_credible_run_frames | 0.14.83 起记录本句最长连续 credible 帧数。无确认帧、静音或相邻收音时钟差超出 8～12 毫秒时会中断连续段。 |
| credible_with_render_frames / credible_without_render_frames | 0.14.83 起按同帧播放参考是否高于 −60dBFS 分别累计 credible 帧，两者相加等于 credible_frames。参考电平代表数字参考覆盖，扬声器的实际声音仍须单独验证。 |
| device_vad_tail_ms | 最后一个标记为有声的帧结束到断句帧结束的间隔，取两者的设备收音时间差。没有有声帧或帧时钟不连续时缺测。 |
| render_frames | 当前帧数字参考音量大于−60dBFS的帧数，不证明扬声器实际发声 |
| pause_requested_frames / voiced_after_pause_request_frames | 逻辑暂停请求仍有效时的帧数/其中voiced帧数，不冒充暂停ACK或声学停播之后的时长 |
| raw_correlated_frames / residual_correlated_frames | 当前参考有效且原检测器滚动相关性分别大于0.78/0.60的帧数，沿用已有检测器数值，不增加决策阈值 |
| max_raw_correlation / max_residual_correlation | 句内已观察到的原始/残差滚动相关性最大值，保留四位小数 |
| raw_peak_dbfs / cleaned_peak_dbfs / render_peak_dbfs | 原始/处理后/参考的最高10ms帧数字电平，非校准SPL；三个峰值可能来自不同帧，不能相减当ERLE或SNR |
| echo_risk / during_playback / local_wake | 已有句子级风险、句首逻辑播放状态、本地唤醒命中标志，非说话人身份 |

0.14.86 另提供可选的整组 `onset_prefix_*` 计数：`frames`、`credible_frames`、`render_frames`、`credible_with_render_frames`。它们只覆盖 VAD 报告句首之前、紧邻本句的连续本地 voiced 帧，最多 49 帧，属于既有 500 毫秒音频预卷范围；不包含当前开始帧，不加到上表的本句计数。连续性同样要求设备帧间隔为 8～12 毫秒，静音、断点及生命周期重置丢弃旧标记。前段只保留每帧两个布尔标记及一个核对连续性的最近时间戳；报告不包含音频、文字或绝对时间戳。

这组数据用于区分“VAD 成句后的参考缺失”和“成句前是否已有参考覆盖”，不证明真实说话人或声学出声。四项必须齐全、各在 0～49 范围且交集计数一致；旧后台缺少整组时保持未知。严格插话报告另保存 `onset_prefix` 摘要，但通过条件仍只读取原 `credible_with_render_frames`；即使前段重叠为正，本句严格计数为零仍失败。0.14.86 已部署；实机新问题的前段 13 帧中 12 帧有有效参考、credible 为 0，本句原统计的可信重叠也为 0，严格检查保留失败。尚不能区分早期近端刺激与回声，现场数据及收尾见 [当前部署](CURRENT_DEPLOYMENT.md#01486code74-成句前观察)。

只累计标量，不复制/保留音频帧。句尾一次性提交；重置会话、通道、VAD活动或本地停止时丢弃未完成的计数。固定字段、有限数值、帧数上限2000及子计数关系均校验；旧后台缺测即缺字段，不补零。

0.14.80 的联网批次第 25 轮出现累计六帧 credible 的额外准入。0.14.83 补充上述三个计数，便于核对确认帧是否连续、是否覆盖播放参考。新采集入口接受旧报告缺少整组三项的情况；部分提供、超限和矛盾计数会被拒绝。旧版严格采集器需要更新后读取新增字段。该批软件只提供定位数据，现场来源和误打断修复继续验收。

0.14.55 将 `device_vad_tail_ms` 纳入已准入语音的阶段统计。10 毫秒帧的相邻设备时间差须在 8～12 毫秒内。离线用真实断句代码处理 80 帧连续无声尾部，得到 800 毫秒，数据随同一识别任务移交。该数字基于近端判定与设备估算的收音时钟，只用于分解软件断句前的等待。实体麦克风最后一个可听音节、Mac 到达时间以及扬声器出声由各自的证据衡量。

## gate：识别入口作出的分类

`accepted`表示本句已通过原语音门控，**不表示真人判断、工具授权或任务成功**。其他固定枚举为`empty`、`echo_text`、`echo_render`、`wake_closed`、`wake_only`、`wake_sleep`、`calibration`、`stale`、`error`。没有识别正文、参考正文、向量、文件名或提供方响应。

终态之后可补齐当时的观察，不能改变任务/播报结果；同一观察一经提交不能改写。采集器严格重建字段，拒绝未知内容、错误来源、非有限数值、被删除/修改的既有观察；整次快照原子接收。schema仍为1，新字段可选，新采集器兼容旧后台；旧严格采集器会拒绝新字段，因此部署前须先更新采集入口。

## 播报完成回执与成句回声门控

后台 0.15.16 候选复用唤醒检测已有的三秒播放完成窗口。即使没有收到对应参考帧，窗口内开始或覆盖的收音仍按回声风险送入成句判定，不在 VAD 起点立即取消当前代次。已有回声文本比对会处理与播报匹配的转录，独立的新问题仍可完成识别并提交。诊断分别保留回声风险和参考帧数，可以区分有风险但未收到参考的样本。

离线回归从实际 VAD 成句走到识别线程，覆盖窗口内的匹配转录、窗口内的独立新问题及窗口外的同句重问。该回归使用固定输入和识别回执。实机验证另行进行，较长播后观察中的额外候选声源仍未确认。

## 跨段停止词

后台 0.15.17 候选按播放顺序拼接仍有效的上一段和当前段，再检查本地检测到的停止词。旧顺序会漏掉跨段的“停一下”，也可能将原先不相邻的字拼成同一个停止词。收音入口的离线回归使用固定检测结果，检查这两种错误及上一段参考过期后的行为。检测阈值和参考保留时长沿用原设置，实际扬声器和真人停止词仍需实机验证。

## 收音断点与未完成插话

后台 0.14.33／APK 0.9.18 code53 候选把设备读缓冲停顿标到具体录音 epoch 和下一包序号。后台在该包经过既有参考缓冲时分段，避免事件提前结束尚在缓冲中的有效音频。缺包和不可用的 PCM 帧也会结束未交付的断句。旧 APK 的读停顿事件没有包身份，保留原有日志和诊断行为。

未完成的语音记录会明确取消，断点后的语音重新成句。只有被舍弃的这段语音自己发起的临时暂停才会恢复。已经交给 ASR 的句子和它持有的暂停继续由原识别任务管理。近端投票、本地停止词和唤醒流在断点清空，不延长已开启的唤醒窗口。回声参考和语音电平阈值保持原设定。

自动测试覆盖真实 Java 读取工作线程、协议入口、缓冲顺序、旧 epoch／错包、断句分段和暂停归属。现场版本与长时观察保持运行，真实录音停顿和声学表现仍需实机验证。

## 超长语句与断句恢复

同一连续语句达到 1,200 帧的音频缓存上限后，断句器继续观察 800 毫秒静默，收音和对应播放参考都保持有界。若在完整停顿前还有语音越过上限，整段以 `utterance_too_long` 结束。尾段继续丢弃，直到满足同样的静默边界，后续明确起句再进入识别。0.15.36 在安静聆听时通过现有可见的错误提示显示「这句话太长了，请分成几句说」，麦克风保持开启。插话场景只恢复该段自己发起的暂缓播放。

离线回归覆盖连续超长、短暂停后继续、完整静默后另起一句、上限处正常停顿，以及暂缓播放的归属。原版把一段 1,300 帧连续语音变成两份识别输入。部署后用固定合成试音确认一次拒绝、零 ASR、提示可见和同一会话接续短句并播完。 [超长语句实机检查](CURRENT_DEPLOYMENT.md#01536-超长语句实机检查)

## 识别为空时的重说提示

0.15.38 候选在已有的空识别重说条件成立时，使用 CC8 可见的错误提示显示「刚才没听清，请再说一遍」。安静聆听中须已有可信近端人声、当前对话已唤醒且无回声风险。麦克风和当前会话继续可用。低证据、回声风险和已知非语音转录沿用通用聆听状态，播报中的空转录沿原暂停恢复路径处理。协议回归确认提示阶段、录音归属及弱证据场景，实体屏幕待专项核对。

只更新后台的维护与独立只读复核通过，原 APK、配置和服务定义保持，未启动采集。[部署记录](CURRENT_DEPLOYMENT.md#01547code80-停止词换线边界)。

0.15.47 已部署，在录音线路改变时，清空本地停止词解码流的历史，并保留该录音会话的累计样本与计算计数。此前换线会重置断句、近端检测和唤醒流，却保留停止词历史。使用确定性解码后端、实际 `FastStopDetector` 流适配器及 Bridge／端点调用链，可复现旧线路上的前半句与新线路上的后半句拼成停止词，取消新回答。
