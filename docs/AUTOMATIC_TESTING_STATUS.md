# 无需重复人工操作的自动测试

2026-11-09 调整：以 [TODO 中的自动化复核与非阻塞验收队列](TODO.md#自动化复核与非阻塞验收队列2026-11-09) 为当前排期依据。能自动执行的步骤随相关功能批次运行；需一次环境布置或真实登录／睡眠事件的项目，条件具备后自动验证，尚缺条件时不阻塞独立特性。必须真人判断的部分留到功能开发后的集中验收。最终 72 小时仍在全清单最后，不自动启动。下文历史结果保留原版本范围，当前部署以 [CURRENT_DEPLOYMENT](CURRENT_DEPLOYMENT.md) 为准。

用户要求自动测试并保留已完成的人工验收。已有人工结论作为其当时版本的记录；正常软件回归、设备状态/播放回执、逻辑连接切换、合成声学问答、真实计时待机及运行资源观察尽量由Mac执行。测试后的状态应为助手前台、麦克风关闭；重连不得重新开麦。相机不属于这些语音测试。

## 入口

在仓库根目录运行，`--runtime-root`必须指向实际后台目录，而不是另一份源码：

```sh
# 以下两条默认仅显示计划，不打开设备或采集
./cc8 verify-device --runtime-root /absolute/runtime
./cc8 verify-device --runtime-root /absolute/runtime \
  --capture --playback-evidence --clock-evidence

# 真正执行需明确追加 --execute；采集只在显式 --capture 用例中有界开启
```

最终 72 小时的只读观察入口见 [RUNTIME_OBSERVATION](RUNTIME_OBSERVATION.md)，单独排在全清单最后；上述日常检查不附带启动长时验收。

完整采集/待机前先核对已装版本、唯一USB目标、空闲工作回执、前台和对应能力，持有运行目录的自动测试互斥锁。普通自动检查的设备采集限额为180秒，真实待机用例为1200秒；退出执行Home停采、维护重开和双端关麦核验。失败保留原报告、停止后续有副作用动作，不能把重试成功覆盖原失败。具体选项见 [设备检查](AUTOMATED_DEVICE_CHECKS.md)。

ASR、Dot、TTS 的失败和恢复用例可以用开发 Python 执行 `./cc8 verify-failure-ui --host-only --execute`，一次运行 48 项，无需连接 CC8。详见 [本机故障检查](AUTOMATED_FAILURE_UI.md#mac-本机故障和恢复检查)。

### 固定设备验收批次

```sh
./cc8 verify-device --runtime-root /absolute/runtime --capture --p0-device-suite
./cc8 verify-device --runtime-root /absolute/runtime --capture --p0-device-suite --execute
```

第一条仅列计划。第二条使用同一实际后台实例、同一个 USB 目标和一把贯穿全程的测试锁。六轮依次为双语自播报及连接测试、插话及录放证据、独立清醒问答、三轮真实 15 分钟待机和唤醒问答。清醒问答在确认回答播完后观察至少 20 秒。清醒问答和三轮待机各保存本轮新回答的同段起播与播完时间，缺少配对证据即停止批次。插话前用于唤醒助手的简短问答单独标记。每轮使用自己的限时录音并核对收尾停采。任一轮失败、中断、缺回执或清理未确认即停止，后续轮次标记未执行，原结果写入同一个私有检查点。预留至少 45 分钟的真实待机时间，校准、播报和设备检查另计。

批次通过要求六轮均按计划执行。72 小时长稳、实体拔插、真人准确率和可听停声时延继续单独验收。

后台 0.14.60、APK code 69 或更新组合可选扩展批次。

```sh
./cc8 verify-device --runtime-root /absolute/runtime --capture --p0-device-suite --extended-voice-evidence
./cc8 verify-device --runtime-root /absolute/runtime --capture --p0-device-suite --extended-voice-evidence --execute
```

扩展批次在插话后增加独立的“停一下”轮次，并在随后的清醒问答中要求室内声音对照。七轮共享原有测试锁，逐轮停采并确认清理。停止词的本地命中、云端识别计数、设备停播和清醒问答声学证据有任一缺项，批次即停止并保留已测结果。30 轮回答时延采样仍可单独运行。测试与实际正在运行的观察互斥，但当前开发不等待尚未启动的最终长稳验收。

批次结束后可以离线复核私有报告。

```sh
./cc8 audit-device-suite /absolute/private/device-suite.json --expect-backend 0.14.60 --expect-apk-code 71
```

复核重查每轮的固定计划、源码摘要一致性、APK 版本、停采和已记录的时点，检查三轮待机是否各自实际达到 900 秒。30 轮时延报告从单轮结果重新计算分位数。工具不连接设备或修改报告。复核通过只表示报告记录满足相应自动批次的条件。

若测试中确认后台实例已变化，旧测试停止操作设备并把收尾标为未确认。健康查询失败且尚未发现实例变化时，仍尝试紧急 Home 停采。原失败与收尾原因分别保存，实例标识不写入报告。[设备收尾说明](AUTOMATED_DEVICE_CHECKS.md#固定合成语句插话)

基础批次需要后台 0.14.50 或更新版本。旧后台仍可使用独立检查项，缺少同段计时只记缺测。后台 0.14.60／APK code 69、当时现场 code 49 和回退 code 70 的原签名校验，以及 code 71 的停止词声画检查均为历史版本记录；当前更新按实际候选准备同源 QA 包和原签名恢复包。设备、后台恢复和故障界面检查随受影响批次执行，实体拔插与真人声学证据按范围独立记录。[版本与构建回执](RELEASES.md)

## 历史结果：0.14.20／code49

当时冻结26cf5fd、后台0.14.20／原签名APK0.9.14（code49）。八项设备检查66.993秒、同回合两段播报29.192秒、清醒状态合成问答55.662秒均通过。问答完成一个准入请求和一次真实回答/播放，播后20.006秒无额外候选或暂停；所有结束检查确认停采。各报告和摘要见 [当前部署](CURRENT_DEPLOYMENT.md)。这两条现场结果来自固定场景私有驱动。清醒问答已有通用入口 `verify-device --capture --awake-dialogue` 和离线回归；后续按受影响行为决定是否复跑，不默认重复此历史用例。

前版0.14.19／code48固定三轮、每轮真实15分钟以上黑屏/合成唤醒/回答/20秒观察全部通过，共3022.412秒。更早版本的监督故障10轮和独立TLS故障UI48组各有报告；均保留各自冻结版本和覆盖边界，不混称为当前APK的全部验收。

候选后台 0.14.41 补齐了两段分别核对的回执和通用入口 `verify-device --multi-clause`。旧两段报告保留为整次播报完成的实机记录，新增逐段检查待候选现场复跑。

旧版只读观察已按 2026-11-05 调整后的顺序收尾，报告保留为基线。先继续功能开发及短时实机回归，待产品功能稳定后，再启动完整的 72 小时观察。见 [当前部署](CURRENT_DEPLOYMENT.md)。

## 自动化的实际边界

- 软件控制的 Wi-Fi 接管／USB 优先不等于真实硬件断链。后续已有专用集线器的 20 次硬件往返记录，见[硬件端口往返](AUTOMATED_DEVICE_CHECKS.md#集线器硬件端口往返)；它验证真实 USB 链路中断，不改称人工移动线缆。新增场景自动补测，线缆接触／供电差异的人工抽查放到最后，不阻塞功能开发。
- 公开合成声学刺激经过真实扬声器/麦克风、ASR、Dot和设备播放，可以发现链路问题；不证明一般真人、远场/电视/轻声、中英文唤醒准确率。
- 播放回执和固定窗口相关结果不等于首个可听声音或人声起点到实际停播的延迟。
- 不向用户重复发起整轮人工验证；新缺口先用自动化定位，无法自动验证的部分保留未验，不冒充通过。
