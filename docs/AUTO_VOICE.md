# 打开助手自动开始语音

Android **0.5.3 / versionCode 21**、Mac 后台 **0.8.2** 起，从桌面大黄蜂入口、通知或应用图标主动打开助手，默认等待连接后自动开始语音。首次仍须允许系统麦克风权限；已授权时不需要再点击“开始语音”。请等待约 6 秒参考音校准完成，再按当前唤醒模式说“大黄蜂”或“Bumblebee”。

开启后右上角显示「麦克风开启」，底部按钮显示「停止语音」，表示已经处于开始语音 / 监听状态；不需要再点按钮。普通启动、桌面入口和通知默认使用此行为。

## 开关和边界

- 一次打开只提交一次启动请求。已在录音的同一前台会话不会创建第二条并行录音；若打开动作引起实际前后台切换，仍按离开前台停止、新打开重新开始处理。
- 没连上 Mac 时，界面提示连接后自动开始，可点“取消自动开始”；等待最多 30 秒，超时后需要手动开启或重新打开。
- 点“停止语音”后，本次打开期间保持关闭。连接恢复、USB / Wi-Fi 切换、普通 onResume 不会重新提交自动启动请求。
- 返回桌面、离开前台或两条通信通道全断，仍停止采集。之后从桌面入口主动重新打开，才产生新的自动启动请求。
- 桌面入口服务本身仍不使用麦克风、摄像头或音频网络通道；它只打开 MainActivity，由前台界面按用户的设置启动语音。

## 只打开界面或只启动后台

安装检查、维护和只播报场景不要使用默认打开路径，因为它现在会按用户要求开麦。从仓库根目录执行：

```sh
# 只启动 / 复用 Mac 后台，不打开 CC8 页面
python3 cc8-assistant/host/launch.py --no-open

# 打开页面，但不启动新的麦克风会话
python3 cc8-assistant/host/launch.py --no-auto-voice
```

`--no-auto-voice` 不提交新的录音请求；它不是强制静音命令，前后台切换仍按原规则停止录音。已经在前台的助手无需重复打开。需要主动关闭时使用界面的“停止语音”。直接启动 Activity 的维护代码可附加 `--ez auto_start_voice false`。本机 `cc8-announce` 技能的准备步骤也已改用这两个选项，避免只播报时意外启动录音。

## 实现

`OpenVoiceGate` 管理一次性请求和连接超时；MainActivity 的创建 / 明确新打开 Intent 才能建立请求。请求在权限 / 录音尝试前消费，拒绝权限或录音失败不形成循环。CC8 可能在打开过程中短暂暂停 / 恢复界面；未消费的请求在这类切换中保留，但暂停时不能采集，原 30 秒期限不因普通恢复延长。真正 onStop 或手动停止取消请求；普通恢复不重新武装已经消费的会话。生命周期依据见 [Android Activity 接口说明](https://developer.android.com/reference/android/app/Activity#onNewIntent(android.content.Intent))。

链路选中时，设备先将 device_ready / session_rebind 放入发送队列，再通知界面连接就绪，避免界面自动录音与连接握手交错。后台对相同录音 epoch 的 session_start / session_rebind 做幂等处理，避免初次录音线程与双通道切换交错时重复启动校准。

后台 0.14.38 候选在同一 Mac 进程内保留已停止状态。手动停止、设备确认已停采或所有通道断开后，后续链路报告的 `session_rebind` 不能重建本地收音和校准；收到设备前台录音流程的下一条 `session_start` 才会恢复。仍在运行的同一录音可随通道切换继续，Mac 进程首次接入设备已有录音的流程仍可用。

回归复现四种停止顺序，并核对迟到重连不改代次、不创建 AEC、不接纳旧录音帧，新的开始事件仍可进入校准。该检查在 Mac 测试进程完成，候选未部署。

## 验证

实际设备验收结果见 [VALIDATION.md](VALIDATION.md)。单元回归运行真实的 Java 门控类，覆盖等待连接、仅前台启动、一次消费、手动停止、已有录音、超时及新打开重新授权；其余语音回归和 Android 编译 / lint 同步执行。未改动音色、识别服务、大脑或摄像头启动策略。
