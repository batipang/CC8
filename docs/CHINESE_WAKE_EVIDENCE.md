# 中文待机的固定声源与阶段计数

后台 0.15.60 候选补齐 P0-01 / P0-03 / P0-05 的诊断边界。此前三轮实际待机有两轮完整通过，第三轮收到明显语音却停在 `wake_closed`；报告没有本轮中文关键词和复核的独立增量，因此不能定位到唯一模块。本批不修改唤醒门槛、模型、音频前端或云端准入。

`cc8 verify-device --capture --standby-suite` 仍默认只打印计划。显式加 `--execute` 后，三轮真实 15 分钟待机共用一份提前生成的公开中文问句 WAV，不再每轮直接调用 `say` 重新生成。音色为已确认安装的 Tingting，问题为既有固定第一题，文件保留在临时私有目录并在批次收尾删除。播放前仍由 `PreparedSpeech.play` 核对实际文件摘要；录音、Home 和维护重开沿用原套件。失败不自动重跑，第三轮失败保留前两轮和原始失败状态。

批次的 `prepared_chinese_input` 记录 PCM/WAV 摘要及固定格式，`prepared_chinese_input_cleaned` 记录清理结果；各轮还必须记录相同摘要和 `chinese_fixture_played`。这证明运行中复用了同一音频文件。播放命令成功不能证明声波到达了设备，既有 `acoustic_playback_confirmed=false` 保留，收音形状仍需专用探针核对。

普通声学问答与待机报告增加 `chinese_wake_counters`，比较播放边界前到当前观测的健康计数：

| 字段 | 含义 |
| --- | --- |
| `local_wake_chinese_candidates` | 中文流式关键词候选 |
| `local_wake_chinese_rechecks` | 中文整句复核调用 |
| `local_wake_chinese_recheck_hits` | 中文整句复核通过 |
| `local_wake_chinese_unavailable` | 中文复核无有效结果 |

计数仅表示这个观测窗口，可能包含环境输入，不能直接认定每次都来自测试句。缺字段的旧后台为 `unavailable`，计数回退为 `invalid`；不把未知伪装成零、不保留识别正文或音频。新增计数读取本身不会打开麦克风、修改录音状态或唤醒设备；显式执行声学套件仍会按原流程启动有界采集。

离线 `audit-device-suite` 对 0.15.60 起的待机批次要求固定源、清理、逐轮播放与计数回执。旧报告保持可读，但不会因此被标记为已验证同源。三个完整轮次全部通过后才会返回 `same_chinese_stimulus_verified=true`；已有第三轮失败不会变成通过。

另一次离线诊断用同一公开 Tingting PCM，在现用中文关键词模型中比较新建流与保留 0、900、900.37 秒数字静音的流。六个后缀都命中，静音段零触发，25.180 秒完成。它只说明数字静音历史本身没有在这三组条件复现现场失败；没有经扬声器、CC8、云端，不证明房间输入正确或漏唤醒已经解决。后续按固定声源与本轮阶段计数定位，避免无证据改阈值。

本批是诊断软件改进，P0-03、P0-05 的真人与真实待机验收仍开放；72 小时验收保持全清单最后，不自动执行。
