# 文字请求的提交、替换与失败收尾

后台0.15.70已部署，关联P0-02／P0-06。文字请求继续使用已有owner私有IPC和认证设备入口，保持原模型、工具权限、麦克风状态、APK和协议版本。当前已部署版本另见[部署记录](CURRENT_DEPLOYMENT.md)。

## 输入在取消之前验证

JSON转义允许出现无法编码为UTF-8的孤立代理码位。此前这些文字能越过输入检查，先取消正在执行的工作，再在设备事件或TTS编码处失败。普通文字任务和逐字播报现在使用同一份验证：分别保留6000和500字符上限，仍允许换行／制表符、正常中英文及emoji；不合法Unicode在取得请求归属、取消旧任务、发送事件或构造播报前拒绝。错误不含输入原文，owner IPC仍返回原有 `invalid_request`。

## 一次提交的归属

有效请求仍在原会话锁中取消旧回合、建立本次文字归属、创建无内容诊断并发送开始通知，再进入原回答队列。取消、亮屏和通知可能同步触发线路变化或更新请求，因此每个边界都重新核对原代次与文字归属。

原请求已被替换时，返回 `{"ok": false, "generation": <原代次>, "status": "superseded"}`。此回执表示本次旧请求没有取得最终提交确认，不自动重试或撤销新任务。普通成功仍为 `{"ok": true, "generation": <本次代次>}`，只确认提交，执行结果仍以真实任务回执为准。设备入口继续显示最新请求，不为已被替换的旧请求抛出迟到提交错误。

取消发布期间新请求已进入时，旧调用不会再写回自己的文字归属；通知回调中连续出现两个更新请求时，旧调用也不能继续入队、挤出最新任务或让其一直等待。被替换的诊断保留取消终态，已经完成的结果保持原终态。

## 失败与后续请求

开始通知或亮屏发送失败记在transport阶段，诊断建立或入队失败记在runtime阶段。失败收尾先清除原文字归属，再结束诊断并取消仍属于本次的代次；即使队列已收到任务后才抛错，迟到任务也因旧代次失效而不能开始执行。设备沿用原cancel事件清除文字等待和播放状态，录音启停规则保持。

诊断或取消清理再次失败时只记录固定阶段和异常类型，调用者仍收到原始失败；若清理过程中出现新归属，旧收尾不取消新工作。没有后台重交任务或补执行。下一次明确请求可以独立提交。

## 只读健康状态

owner健康查询增加 `session_generation` 和 `text_request_active`，分别表示当前会话代次及是否保留文字请求归属；没有文字、音频或设备标识。前者是控制回合计数，不作为采集凭据，原 `capture_generation` 的采集范围保持；后者与识别／回答worker是否存活分开。读取不启动采集、模型或新请求。

## 验证与范围

同一组14项新增测试在原69源码复现17处断言失败、零fixture错误。修复后的定向检查覆盖实际SessionController、Bridge、回答队列／worker，以及Unix socketpair上的真实owner IPC解析和回执。包含录音状态开／关、开始通知／亮屏失败、队列先入账后抛错、取消／诊断清理错误、取消及开始通知中的多级替换、孤立代理码位、正常emoji和多行文字。新输入验证模块加入固定strict类型检查。

这些检查使用固定公开文字与受控提供方，没有调用设备、模型或麦克风。整批host 1735项通过（4项既有私人录音opt-in未启用）、工具158项通过；固定格式／静态检查、15个严格类型模块和既有Java格式通过。受保护CI、部署和现场验证按各自实际记录补充；P0-06为新增入口缺陷重新开放，原故障矩阵记录保留，不把软件提交恢复当作真人语音准确率、物理换线或最终72小时验收。

0.15.70正式运行IPC的三项固定无效Unicode输入均被拒绝，未改变会话代次或文字归属，没有新任务、ASR或音频活动；独立复核确认停采与原配置。该轮未注入生产启动故障，已有任务保留和更新归属仍按上述离线范围记录。相关逐字播报入口的后续修复见[播报提交](ANNOUNCEMENT_ADMISSION.md)。
