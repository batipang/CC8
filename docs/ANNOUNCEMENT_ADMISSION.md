# 逐字播报的提交与完成收尾

后台0.15.71源码候选关联P0-02／P0-06。继续使用既有owner私有IPC、提醒和显式播放探针入口；MiniMax逐字播报、原音色、普通语音启停与原签名APK90保持。当前现场为[后台70](CURRENT_DEPLOYMENT.md#01570code90-文字提交与异常输入)。

## 提交与失败

取消旧回合后，播报只取得返回代次的归属。建立诊断、准备探针和入队后再次核对；这些边界上已经出现更新请求时，返回已结束的 `interrupted` 播报回执，不再排入旧任务、清除新归属或自动重试。IPC完成回执格式保持原样。

诊断建立、准备或入队失败时，先释放原播报归属，记录无内容的runtime失败，再使仍属于本次的会话代次失效。队列可能先入账再抛错；仅清除播报标记不能阻止正在收音时的旧任务，因此必须作废原代次。实际回答／播报worker继续检查会话归属，不允许这个未确认任务产生语音或工具副作用。

诊断或取消再次失败只记录固定清理阶段及异常类名，不泄露正文或替换原始异常。清理回调已产生新请求时，不取消新回合。原 `Announcement queue busy` 错误保持；下一次明确请求可以独立提交，提交失败本身不触发重交；已有提醒的调度规则保持。

## 完成与等待者

开始通知及状态发布与原会话锁协调，防止旧通知被替换后继续显示「正在准备播报」。结束时先按原归属清理和结束诊断；已经失效的旧播报不更新当前设备状态和最近播报指标。已完成结果保持完成，停止朗读仍不撤销已执行的任务。

等待者的完成事件在最外层finally释放。即使结束通知、诊断、指标或状态写入失败，IPC／提醒调用方仍能取得本次终态，不会因可选收尾错误一直等待。没有新锁、常驻线程或额外队列。
