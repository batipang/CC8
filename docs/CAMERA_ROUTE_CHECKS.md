# 相机预览中的连接中断检查

这是 P0-05／P1-04 的显式自动入口：一次布置后，自动确认真实预览、逻辑线路中断、对应取消回执、相机释放以及恢复 USB 后不自行重拍。默认只输出规划，不连接设备或创建报告；只有当次明确请求执行，才可打开镜头。当前为后台0.16.25候选，实际运行仍为0.16.24／原APK code134；本批只做软件回归，没有执行真实取景。

先将助手保持前台并暂停语音，确认 USB 与已配对 TLS Wi-Fi 都可用。镜头无需摆放识别物品，本项不判定画质或调用 Dot。规划入口（系统 Python 3.9／最小 PATH 可用）：

```sh
./cc8 verify-camera-routes --runtime-root /Volumes/AI/Codex/CC8-P0
```

当次明确授权后，使用已配置的 Python 3.11+ 运行；以下命令会最多打开两次可见5秒预览，并短暂逻辑关闭线路：

```sh
.toolchains/cc8/dev-venv/bin/python cc8 verify-camera-routes \
  --runtime-root /Volumes/AI/Codex/CC8-P0 --execute
```

可加 `--case wifi_handover` 或 `--case all_routes_lost` 只运行一项；不选时依次运行两项，失败即停止，不重拍、不自动重试。旧后台缺少 `camera_metadata_only_supported` 时在接触 Android 或申请测试锁前拒绝，必须先完成正常后台升级。

- 在首个可见画面5秒保持期内确认实际相机打开及对应代次，再触发12秒逻辑USB抑制或10秒逻辑全断。过晚、预览缺测或请求提前结束均失败，不用一次完整拍照冒充取消测试。
- 核对同一请求的 `interrupted` 回执，双端相机关闭、抓帧计数不增加，之后 USB 优先恢复；再观察3秒，确认相机不自启、旧帧不回流。换路和恢复均核对双端线路。
- 请求以实例ID和初始代次在服务端锁内校验后才开镜头。重启或新请求改变上下文时拒绝；关闭工具的专属 socket 只取消它自己的取景，不发送全局 Stop 或关闭别人的麦克风。
- 收尾继续核对原服务归属、音频／ASR计数、原配置与完整 LaunchAgent 字节及七类私有存储摘要。数据有变化只报未确认，不回写旧数据。最后核对前的中间报告保持 `running`；Ctrl+C 记录 `interrupted`，退出130，清理未确认不能记成功。

报告写入调用代码根目录的 `device-access/private/camera-route-checks/`（目录0700、文件0600），只含请求归属、阶段、计数与失败分类；不保存照片、base64、录音、聊天内容或原配置正文。正常桌面 Dot 明确拍照并返回当前聊天的入口保持原行为。

此项不是物理拔线、电源扰动、20样本画质／OCR、真实声学或完整P0验收。不能用合成状态机或本地socket通过证明实体相机已通过。真实取景需要当次明确请求后另行记账；没有该条件不阻塞独立软件功能，72小时验收仍最后。

软件检查覆盖真实本地 Unix socket 的元数据回执与取消、错误实例／代次、超限／含图／坏回复、换路和恢复双端状态、迟到图像、权限失败、用户中断，以及最终归属／存储变化不能提前标通过。开发中首次 socket 关闭未及时唤醒 macOS 接收等待，已改为0.2秒有界等待并观察本请求停止信号；原失败保留，未改全局 socket 策略。新增完整执行夹具首次缺少报告父目录而失败，修正夹具后通过，没有在真实设备运行该夹具。
