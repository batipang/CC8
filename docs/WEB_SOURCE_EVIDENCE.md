# 联网来源的证据与时间

Dot 和 MiniMax 在开始处理每轮问题时记录北京时间，作为解释“今天”和“明天”的依据。MiniMax 等待补充城市等条件时，保留原问题及其提问时间。CC8 来源详情显示查询参考的北京时间。来源列表仍分别显示 MiniMax 的检索返回时间或 Dot 的回答来源汇总时间。旧后台未提供查询时间时，详情省略这一行。

后台 0.16.15／助手 0.9.79（code116）软件候选在原来的「来源」入口展示链接依据。原头像、光环、字幕及默认 Dot／MiniMax 分工不变，设置与查看不会启动录音或拍摄。

| 显示 | 实际依据 | 仍未知的内容 |
| --- | --- | --- |
| 仅回答中的链接 | 本次最终回答包含这个公网链接 | 是否读取正文、发布日期、事件日期 |
| 有页面操作完成回执 | 同一 thread／turn 的 `item/completed` 携带 `openPage`／`findInPage` 与这个 URL | HTTP 成功、正文内容、事实是否得到验证 |
| 页面操作失败 | 同一回合收到明确失败／拒绝／中断状态 | 正文、事实与日期 |
| 搜索服务返回 | MiniMax 搜索接口通过状态校验并返回此条目 | 是否获取全文、事件日期；搜索摘要不能冒充正文 |

Codex 当前 [App Server 官方接口](https://learn.chatgpt.com/docs/app-server) 的 `webSearch` item 只提供查询／操作元数据，没有文章正文、引用对应事实或发布日期。这里据实记录操作，不伪造这些字段；内部 ref ID 不是公网 URL 时也不猜测原网址。无回执链接仍可在用户明确点击后打开，但显示读取状态未知。

每个模型回合最多记录 64 个页面操作，最多展示六条有效链接，重复 item 不刷新时间，上一回合的回执不能给本次链接背书。比较 URL 时忽略片段、ASCII 主机名大小写、显式默认端口及空根路径与斜线的差异。协议、非默认端口、其他路径和查询仍须一致。等价来源只展示一次，保留首条链接的写法，不增加页面读取次数。

回答结束后汇总链接的时间显示为「回答来源汇总时间」；MiniMax 实际搜索返回时的记录显示为「检索返回时间」。兼容旧后台时明确显示时间依据未提供。单条搜索结果的原始日期只标为「来源标注日期」，不转成事件日期，不用 URL 中的日期补全；事件日期未知时保持未知。Dot 指令要求区分发布日期、发生日期和查询时间，今天／明天按当次提供的北京时间解释；这不是对模型事实准确率的保证。

设备把条目复制为不可变元数据，不保留可被网络线程修改的 JSON 引用。前台与当前线路、代次、快照身份共同决定是否显示和打开；新结果、取消、Home 或换线清除旧来源并关闭窗口。已排队的旧 UI 回调、浏览器不可用时的备用链接窗口和旧点击都受同样隔离。显式点击才调用浏览器，无法打开时仅展示可选中文字，不重试或自行换网址。

当前自动检查覆盖实际 RPC 过滤、实际 ResponseWorker 时间依据传递、实际 Java 展示与点击方法、不可变字段、数量／长度边界、私网及非标准 IP 链接、取消／Home／换线和无浏览器备用显示；全部使用合成文字与假回执，不调用真实模型或设备采集。正常时效事实与冲突／失效来源对照、正式包界面与完整 P1-08 验收继续开放，最终 72 小时未启动。

本机整批 2139 项后台测试通过（4 项原有私人音频按显式选择规则跳过），安装器 24 项、工具 178 项、Java 76 项通过。原签名 Android assemble／lint 与 483 个 Python 文件的格式／静态检查、18 个严格类型模块通过。116 项关联回归包含同图追问依赖，合并时保留了两套状态清理与断线边界。旧错误反馈夹具因缺少新的来源回调端口曾编译失败，更新端口后全部原断言通过，首次结果保留；该模拟接口不作为来源展示本身的证据。

## 公开页面核对（0.16.32／code158 候选）

Dot 新增 `cc8_read_source` 只读工具，可在当前事实查询中读取实际采用的公开 HTTP(S) 页面。每个回答最多四次，每次共用八秒截止时间、最多三次重定向、完整响应最多 1MiB；返回最多两万字符的页面文本供 Dot 核对。优先权威原始来源的指令随原有配置保留，模型、技能、MCP 与审批策略不替换。网页中的文字和元数据均为不可信资料，不能授权工具动作。

每跳先核对全部 DNS 地址，再通过 [curl 官方的连接目标映射](https://curl.se/docs/manpage.html#--connect-to)将连接固定到公网地址，HTTPS 时仍核对原站点身份；不使用代理、登录凭证、Cookie、用户 curl 配置或自动重定向。取消会停止等待／回收自有下载子进程，DNS 等待也有界，至多两个 DNS 工作线程。只支持无需 JavaScript 的 UTF-8 HTML／纯文本；PDF、其它编码、压缩响应、超限、无可读文本及失败明确返回，不能冒充已读。读取不落盘、不改变设备麦克风或摄像头。

只有该回合真实工具返回的页面内容才产生「HTTP 页面已读取，事实仍需核对」。只将最终回答引用的匹配地址关联到来源；重定向的最终地址同样可追溯。来源详情展示读取时间、最多两千字符的文本摘录、最终地址及 `article:published_time`／`datePublished`／`dc.date.issued` 原始日期标注。多个日期并列，不擅自选一个；URL、HTTP Last-Modified、搜索摘要和普通模型文字都不生成页面日期或事件日期。文本只是有界页面摘录，包含页面导航等文字，不是完整文章解析或事实认证。

来源列表先显示简短条目，点击查看详情；只有再点「打开网页」才启动浏览器，旧窗口、换线、新回合和 Home 继续撤销入口。页面详情受 56000 字节来源包预算约束，省略内容有提示；不会为展示自动抓取其它网址，也不会在重新打开页面时重查。

自动检查、正式构建、受保护 CI 和实际部署分别记录；正常时效问题与冲突来源的完整 P1-08 验收仍开放。最终 72 小时继续排在所有功能和常规验证之后。

本批已通过一次独立临时 Dot 上下文的真实公开页面测试：模型实际调用新工具、获得 HTTP 200，并在最终来源中返回读取回执；原 Codex 配置与启动代理字节保持。没有开麦、拍照或合成语音。该测试在未提交开发源码上进行，只证明新工具链路可用，不冒充正式部署或完整事实质量验收。

## 读取范围与失败原因（0.16.35／code164 候选）

来源详情使用当前回合的实际页面读取回执，显示接收页面数据的字节数、本次保留给 Dot 的页面文字字符数以及 CC8 当前展示的摘录字符数。字符按 Unicode 码点计数，包含收到的空白；摘录会规范空白／控制字符并限制为 2000 字符。它们不是完整文章字数，也不证明关键事实已经核实。

读取器明确返回是否因两万字符上限截断：达到上限且被截断时提示后文未核对；明确没有因该上限截断时仍保留页面解析与事实核对提示。旧版、缺失或类型不符的标记保持未知，不能因为文字短就推断全文。详情因来源包预算被省略时，设备按实际收到的摘录计数并显示原有省略提示。

失败来源展示固定原因分类与可核对的 HTTP 响应。超时、域名解析、读取条件、跳转、响应格式／编码、空正文与大小限制分别说明；未取得或无效的状态明确未知。HTTP 200 的解码、格式或空正文失败继续显示未取得可用正文。此前跳转的响应不当作后一个失败地址的 HTTP 状态。

只接收固定错误代码，未知内部异常改为一般读取失败，第三方／文件路径等原始错误文字不进入来源卡。后一次失败会清除旧正文与覆盖元数据；失败原因不会增加抓取次数、自动重试或读取其它地址。原先每回合四次／每次八秒／1MiB／来源包 56000 字节等约束保持，日期和事实核实状态也保持各自证据边界。

当 curl 自己先达到计时或大小限制时，来源卡也显示“读取超时”或“响应超过大小上限”。分类依据进程退出码，页面、响应头或第三方错误文字不能改变这个分类。

本批自动检查使用本地合成 HTTP、真实工具归属与事件、不可变原生来源类，覆盖读取器截断与屏幕摘录分别计数、Unicode、未知字段、HTTP 200 无正文、重定向后失败、错误文字过滤及包大小。正式构建、受保护 CI、组合交付及真实时效／失效／冲突问题的最终验收分别记录；设备正在使用时先推进独立软件，不启动采集或打断对话。

若一次公开读取经过跳转后失败，回执同时关联原始链接和最后实际尝试的公网地址。后一次失败会清除这两个引用所关联的旧正文。被拒绝的跳转目标不参与关联，HTTP 状态仍只来自实际取得的终点响应。

回答同时引用原始网址和跳转后网址时，如果两条引用对应同一次读取，来源列表只展示一张卡，保留列表中先出现的链接和实际终点。若两条链接各有独立的最近读取回执，例如一次跳转成功后又单独读取终点并收到 404，两张卡分别展示。

来源详情也可显示 [Schema.org `datePublished`](https://schema.org/datePublished) 的原始日期标注。读取器最多检查四段内联 JSON-LD，每段最多 16,384 字符，只考虑声明 Schema.org 上下文的 `Article`、`NewsArticle` 或 `BlogPosting` 对象及顶层 `@graph` 内的文章。跨这些块核对文章的 `mainEntityOfPage`，缺少时用 `url`，优先采用唯一指向本次实际读取最终地址的文章。若整页只识别到一篇且没有这两个字段，仍保留它的日期标注。显式指向其他地址或无法从多篇中确认归属时省略结构化日期。HTML 日期与结构化日期不同时并列显示，`dateModified` 和事件日期各自保留原有语义。重复字段、无效日期和超限段落会被忽略。JSON-LD 只按数据解析，日期以外的内容不加入正文摘录，不请求外部上下文。

部分新闻页用 [Parse.ly `parsely-pub-date`](https://docs.parse.ly/installation-resources/parsely-integration/metadata/metatags/) 标注发布日期。符合 ISO 日期格式的值按原时区显示。`og:updated_time` 和未明确标为发布日期的 `time` 元素不进入发布日期列表。NASA 新闻稿实测读取到 `2026-04-11T02:31:50Z`，页面另标有 5 月 7 日更新时间。[NASA 新闻稿](https://www.nasa.gov/news-release/nasa-welcomes-record-setting-artemis-ii-moonfarers-back-to-earth/)

来源详情将页面标注的发布日期和更新日期分行显示。更新日期仅来自明确的 HTML 标记或已匹配正文的 JSON-LD 文章，保留原时区和相互冲突的值。无效字段不影响已读取的正文；HTTP `Last-Modified`、推荐文章的更新和未标明用途的日期均不进入该字段。重新读取失败后清除旧标注，事件日期继续单独显示。见 [Open Graph 文章属性](https://ogp.me/#type_article) 与 [Schema.org `dateModified`](https://schema.org/dateModified)。

成功和失败的公开页面读取均显示读取器实际记录的结束时间，使用北京时间，与提问参考时间和回答汇总时间分别展示。结束时间缺失或无效时显示未知。无效的发布日期条目会被忽略，已取得的正文与其余有效标注仍可查看。
