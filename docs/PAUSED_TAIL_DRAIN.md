# 暂时暂停后的短句尾部排空

## 实机定位

0.14.12／原APK0.9.3通过三批补齐固定30个Mac合成问句：30个指定问题正文匹配、Dot任务完成，29次播报完成，第13次播放失败保留。首批校验器错误地要求去掉“大黄蜂”前缀，第二句实际已完成；原失败报告不改写，单独只读核对其已知正文后从未执行的第三句继续。没有重跑失败的第13句；后续17句全部完成。三批不是单轮连续30问通过，不统计真人准确率或声学延迟，回答语义本身也未做自动判分。

第13句中，播报期间有一个参考文字门控拒绝的候选，随后恢复并收到设备IOException。追加固定短句、外部同文合成声的四时点计划：两组较早暂停恢复并播完，第三组较晚暂停后复现排空失败，第四组未执行。实际触发从render ACK观察点起0.317／0.352／0.935秒，包含轮询调度，并非设定偏移或声学起点。失败组恢复后播放头连续约三秒停在20992，按单段参考的render累计差推得语音尾点22849，仍余1857帧。原始失败、未执行和清理结果分别保留，不把同文外部刺激计作无真人说话的误暂停率。

[Android AudioTrack官方文档](https://developer.android.com/reference/android/media/AudioTrack#play())说明流式播放需要设备相关的最低缓冲量，underrun后也可能需要重新填充；可调起播阈值API从31才提供，本机SDK27不能使用。结合本轮播放头观察，缓冲不足是待验证的解释，不把文档直接当作厂商固件根因证明。

## 候选修复

后台0.14.13／APK0.9.7、code42源码候选（继承首候选0.9.5/code40的同一修复）在原AudioTrack排空环节使用可独立测试的PlaybackDrain：仅在已恢复且全部语音已写入后，按当前缓冲与播放头补入必要的有界静音，累计最多一段缓冲、拒绝异常大缓冲；每次恢复只处理一次。兼容minSdk21，真实buffer查询有API23保护。普通播放不添加这段补齐。

静音追加在原语音之后，不改变语音written、字幕总长、有效参考帧或嘴型封套；AEC对原语音尾点之后已按零参考处理。真实播放头必须达到原语音尾点，才可发play_done；超时、取消、负写入或写入失败仍失败，不伪造完成。保留三秒排空预算及暂停等待扣除，不通过延长超时或重新朗读掩盖故障。快照仅增加当前/上一段的语音帧与静音补齐帧数，不留音频或正文。

同时让每个pause token固定关联发起它的voice trace，Endpoint移交到识别队列后仍可正确记ACK；新partial或新owner不能吸收旧ACK。暂停事件显式带原generation，取消发生于发布间隙时不会暂停新请求。三个实际线程/控制器回归在旧0f2fbc7复现三处断言失败，修复后通过。该诊断关联缺口不是已证明的硬件播放失败原因。

Java自动回归使用真实PlaybackDrain与PcmPump，模拟短尾不足起播、短写、二次恢复、普通播放、三秒不前进、取消、五秒暂停及异常缓冲；检查仅写零、保留语音计数、未播完不能成功。真实CC8验证与部署另外留证，候选通过不代表已解决所有误暂停或P0验收。

最终源码检查：installer23 / host664（4项旧私有音频未显式启用而跳过）/ tooling100 / Java15、固定质量检查、原签名Android assemble/lint通过。APK0.9.5/code40为本候选，另准备原0f2fbc7功能、仅改release元数据的恢复包0.9.6/code41（源码6abc238）；原签名API27只读核验与真实部署结果分别留证，未因此安装任何恢复包。

首次code40切换在完整就绪检查未确认后已实际恢复code41／后台0.14.12，尚未实机检验新排空逻辑；异常未保存固定码，不能判定是音轨或APK失败。后续code42候选补充工具的启动等待，保留全部就绪检查并记录固定失败码。恢复后的立即/等待冷启动对照均正常，未复现该次失败。
