## 修复内容

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 录音线程归属与资源并发 | 快速停止 / 重开时，旧线程可能取到新 epoch、覆盖 recorder，或在新会话后发送停止事件 | 启动前固定 epoch，停止立即使旧 epoch 失效；串行化 AudioRecord 生命周期，旧线程不能改变新会话；停止事件携带 epoch，Mac 忽略旧会话停止；UI 读取当前录音状态 |
| Android 旧生命周期的连接任务 | 快速离开 / 返回时，旧 USB 监听线程可能抢占端口；后台连接任务可能在暂停后重新取得 Wi-Fi 锁 | 生命周期检查与监听绑定受路由锁保护；移除重连线程中多余的 Wi-Fi 锁获取；串行化连接尝试，暂停取消在途 socket，认证和注册前复核生命周期；配对配置处理再次检查前台状态 |
| 旧校准覆盖新会话 | 通道切换 / 取消与 AEC 对齐交错时，旧校准可能重建新会话的 AEC 或提前结束其校准 | 对齐和状态提交按 generation 核验，并与取消串行化 |
| Dot 工具请求跨轮次 | 新 turn ID 尚未返回时，原代码仅检查 thread ID，晚到的旧工具调用可能被接受 | 等待 turn/start 确认，严格匹配 thread ID / turn ID，同时检查当前轮次与取消状态 |
| 云端响应无完整大小边界 | SSE 长行、多行累积或非 SSE 错误 JSON 可在校验前占用大量内存 | 从原始字节分帧，限制单行 / 单事件 8 MiB、整流 32 MiB，错误 JSON 2 MiB；错误 UTF-8、非对象事件和错误状态结构转换为明确错误并关闭请求；即使只有 keepalive 也检查取消 |
| 凭证源与文件权限 | 自定义官方地址可使用额外端口 / 路径；本地 Key 文件未检查其他用户的访问权限 | 只接受官方 HTTPS 源、默认 443 端口与根路径；凭证文件必须属于当前用户且其他用户无权限；运行私有目录设为 0700 |
| 启动器误认进程 | 旧 PID 被复用，或另一工作区恰有同名 bridge.py 时，可能停止错误进程 | 校验进程 UID 及脚本参数的准确绝对路径，不再按文件名后缀匹配 |
| 连接启动失败与关闭竞态 | TCP 已绑定但 UDP 绑定失败时泄漏端口；关闭期间晚到的连接仍可能注册 | 初始化失败时清理所有监听 socket；关闭后的 hub 拒绝并关闭晚到连接 |
| 音频事件边界 | 停滞 / 倒退的麦克风时间戳可造成前视队列增长；任意旧完成 ID 会永久积累；字段错误可能抛出未处理类型异常 | 前视队列限制 64 包并检查单调时间戳；只保留当前轮次完成标记；异常事件统一为协议错误，由主循环关闭对应连接 |
| APK 成功判定 | 安装后哈希不可读取仍可能以成功状态退出；助手哈希输出为空时出现 IndexError | 安装文件必须有单一有效路径和一致 SHA-256；无法验证时非零退出、不继续启动，不自动卸载；空哈希为明确错误且仍清理临时助手 |
| 临时安装助手的共享目录替换 | 哈希核验后、app_process 加载前，共享存储的其他应用仍可能替换 JAR | 默认只使用受保护 shell 目录并核验权限、0400 文件模式；本固件实测拒绝写入，默认明确停止。旧路径仅在显式 `--shared-staging` 下可用，仍有替换风险，不能声称已实现安全装载 |
| 检索来源边界 | Dot 来源未复用搜索模块的公网 URL 筛选；浏览器可把 `127.1` 等地址解释成回环地址 | Dot 来源统一走公网 URL 筛选，拒绝私网、凭证、额外端口及缩写 / 八进制 / 十六进制 IPv4 地址 |
| 诊断与清理健壮性 | AudioTrack 释放与状态查询并发时可抛异常；USB stderr 全量读取及重复连接清理不完整 | 播放状态查询容忍已释放资源；stderr 分块丢弃并关闭管道；清理未使用导入和变量 |

补充的设备检查只核验了普通 Android UID、目录权限，并尝试创建 / 清理随机命名的临时助手文件；两个受保护位置均返回 Permission denied，未执行安装助手或安装 APK，未修改 SELinux / 固件。

主要代码在 `cc8-assistant/host/`、Android 的 `VoiceSession.java` / `MainActivity.java` 及 `device-access/cc8_install.py`。新增回归集中于 `host/test_review_boundaries.py` 和 `device-access/tests/test_install.py`；原有 MiniMax 测试适配真实的字节分片读取。

## 第二轮检查：后台 0.11.1

日期：2026-11-01。基线：b70bf3c，Android 0.8.6 / 后台 0.11.0。修复只涉及 Mac 后台和测试，Android 版本保持 0.8.6。

本轮复查语音识别 / 插话 / 播放收尾、USB / TLS 切换、Dot 流式结果、任务回执、提醒存储与调度、相机请求释放和本地播报 IPC，并检查安装器、构建脚本与 Android 生命周期。先运行原有测试，再用无设备、无云端调用的用例复现确认的问题；没有新增路线图中的功能。

| 问题 | 可复现的影响 | 修复 |
| --- | --- | --- |
| Dot 完成回退没有区分过程说明 | turn/completed 成功但只有 commentary 时，原代码会把过程说明当最终回答；阶段明确与不明确混合时同样可能误选 | 只有整个协议消息不含阶段信息才采用旧版完成回退；有阶段信息时必须取得 final_answer；完成消息省略阶段时沿用该 item 已确认的开始阶段 |
| 先发布成功回执，后校验最终文本 | 流式片段与权威最终文本不一致时，先发出 dot_result，再抛异常，任务已经被标成完成 | 先校验 item ID 与文本前缀一致性，通过后才发布最终结果与来源 |
| 断线使后台线程永久退出 | text_done 收尾或噪声后 playback_resume 抛 EOFError，会退出回答 / 识别线程；心跳只捕获 OSError，也可能停止提醒与待机检查 | 每个回答任务的异常处理包含完整收尾；识别恢复发送失败被隔离；心跳对断线、存储与暂时不可用错误记录类型并在下轮重试，不重新开麦 |
| 播报 / 拍照等待者未必收到终态 | 保存状态失败或发送 vision_done 断线，可能跳过 job.done，使桌面调用一直等到超时 | 用 finally 保证完成信号；成功结果不依赖诊断文件或最后一次界面通知是否写入 |
| 任务回执受显示连接影响 | 初始 workspace 发送失败可留下永久 running；实际 Dot 已完成但 dot_result 通知失败，会误记任务失败 | 初始化通知纳入任务收尾；先记录真实完成回执，再通知设备；停止朗读仍不撤销已完成工作 |
| 旧提醒回执覆盖新提醒 | 播放过程中修改 / 稍后提醒，旧成功回执会直接结束同 ID 的新提醒，旧失败回执会添加错误重试时间；重复回执还可能影响下一次周期 | 每条提醒和每次播放绑定 revision；编辑、取消、重试和周期推进均更新 revision；只处理匹配版本的回执，包含“编辑后改回原值”的情况 |
| 提醒异常数据穿透校验 | 极端带时区时间在转换北京时间时产生未捕获 OverflowError；重复 ID 或非法 retry_after 可在后续调度才暴露 | 时间溢出转换成明确参数错误；读取时验证顶层结构、唯一 ID、revision 与重试时间；旧文件缺少 revision 时按 0 兼容，错误文件不自动覆盖 |

修复位置：[bridge.py](../cc8-assistant/host/bridge.py)、[dot_client.py](../cc8-assistant/host/dot_client.py)、[workspace.py](../cc8-assistant/host/workspace.py)。新增 / 补强用例：[线程与异常恢复](../cc8-assistant/host/test_worker_recovery.py)、[最终回答流式处理](../cc8-assistant/host/test_dot_stream.py)、[任务与提醒](../cc8-assistant/host/test_workspace.py)。
