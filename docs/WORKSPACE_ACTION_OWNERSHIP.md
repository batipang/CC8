# 任务与提醒操作绑定原连接

APK0.9.11/code46／后台0.14.16／协议2已按冻结867ff19部署，见
[当前部署](CURRENT_DEPLOYMENT.md)。下方软件回归与源码候选阶段分开留证，
不能把其Java夹具结果当成物理设备或完整P0验收。

[前一批回调隔离](WORKSPACE_ROUTE_OWNERSHIP.md)防止旧快照覆盖当前界面，
但已经打开的列表、详情、编辑表单和二次确认按钮仍可能保留旧对象。原按钮
点击时只看linked或当前isConnected，再把旧ID交给当前连接；重连后可以把
旧任务停止、提醒修改/稍后/取消或结果保存/删除发到新激活。即使是同一Mac，
旧表单也可能覆盖重连期间已经更新的同一提醒。

现在列表、详情、提醒表单及保存/删除确认传递原routeEpoch。在新连接或Home
后拒绝旧操作，给出重新打开并核对结果的固定提示。过期提醒表单不被静默当作
已提交并关闭；现有头像、时钟、字幕、字体和任务终态逻辑保持。

真正入队时还在routeLock内核实前台、激活、就绪及连接状态，不能仅依靠UI
之前的检查。任务停止、提醒动作和保存结果请求只尝试一次原连接入队；队列
不可用时关闭该通道并返回未入队，不使用音频包原有的备用通道重投路径。
返回true只表示本次已入队，保存/删除等操作仍以Mac回执为准，不生成成功
回执、撤销已执行步骤或自动重交。普通音频、协议和模型配置不变。

已保存结果的请求/响应也绑定原激活：旧列表不能从新连接取同ID项目，旧删除
确认不能删除新激活的记录；旧响应不重新打开页面。拒绝旧按钮在close之前
完成，不能顺便清除新连接的pending请求或等待窗口。当前连接的正常查看、
明确保存/删除和本地摘录复制保持；没有扩大持久化范围。

18项定向自动检查编译真实MainActivity列表、详情、提醒表单/回调，完整
SavedTasksDialog，以及VoiceSession发送方法/入队边界；最小Android接口
仅保存控件值和点击回调，Link仅记录固定公开请求或注入队列失败，不操作设备、
真实任务/提醒、文件存储、剪贴板或模型。覆盖旧列表、停止、保存两层确认、
提醒稍后/取消/表单、保存记录查看/删除、旧响应及pending隔离，三种写请求
构造期间切换、失败不重投，以及当前正常操作的对照。
