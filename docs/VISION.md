# 大黄蜂的眼睛：CC8 → Dot

Android **0.7.0 / versionCode 24**、Mac 后台 **0.10.0** 支持按次看图。保留 MiniMax ASR、MiniMax 大黄蜂音色、本地 AEC / 插话及原有 Dot 模型、推理、技能、工具和权限配置。

## 明确保留与本张照片追问（0.16.14／code114 软件候选）

默认仍不保留可供下一次问题读取的图片。要追问，请先在「看图设置」勾选「允许追问：首次回答后在 Mac 内存保留这张照片 2 分钟」，再明确拍摄一次。设置仅在当前 Activity 内存中生效，不拍照、不开麦。只有本次授权和设备提交都明确允许时，成功分析后才保留一张 JPEG；失败任务不产生可追问照片。桌面请求拍照的导出例外不获得这项保留授权。

长按「看一看」或进入设置，选择「追问最近照片」。页面显示本张编号、实际尺寸及保留规则，输入问题后只提交一次；「清除照片」在后台确认后才显示已清除。取消输入只丢弃草稿，不提交模型或重新拍摄。页面随照片到期、请求变化、Home 或换线关闭，未确认的提交不自动重试。

如果拍摄时语音已经开启并保持同一次收音，可说「大黄蜂，追问这张照片，上面写了什么？」；也支持「追问刚才的照片，……」。这条语句必须先通过现有唤醒、回声、近端人声和工具测试检查，才会引用同一张图片。普通「这个多少钱」不隐式选择旧图；没有可用照片或只有引用没有问题时给出明确提示，不重新开相机。独立按钮追问不自动开启语音；后来新开启的收音会话不继承旧照片。

两分钟从首次成功分析后计算，后续追问和语音候选不会延长原期限。传输只发布编号、代次、尺寸和剩余时间；JPEG 留在 Mac RAM，不写状态、日志、相册或仓库。一次追问原子消费该编号，成功后发布新编号但沿用原到期时间。普通已接受对话、停止、Home、换线、全断、新收音归属或新任务清除保留；缓存和已排队但尚未处理的图片均有独立到期清除，不依赖再次读缓存或工作线程取得空位。模型服务已经收到的图片上下文遵循原 Dot 会话边界，不承诺删除服务商的记录。

本批本机最终 2128 项后台回归通过（4 项原有私人音频按显式选择规则跳过），安装器 24 项、工具 176 项、Java 76 项通过；479 个 Python 文件格式与静态检查、18 个严格类型模块及原签名 Android assemble／lint 通过。32 项新增图片测试包括实际 RecognitionWorker 准入、原图字节对应、真实定时到期、并发消费、排队失效、旧回调隔离和不重拍；设备协议由实际 Java 方法编译执行。首次整批在两个原播放夹具缺少新接口时失败，更新夹具后最终后台全套通过，原失败保留。排队图片超期已先复现再修复；这些证据不代替正式包界面、镜头画质、云端 OCR 或真人语音效果。

## 高清、拍后核对与识字（0.16.13／code112 已合并软件）

### 固定样本对照

`python3 tools/score_camera_ocr.py --cards` 显示 20 张公开测试卡的文字，包含物品标签、数字、中英混排和多行内容。用同一张卡、位置和光照分别拍标准与高清两次。记录实际交给 Dot 的 JPEG 尺寸和原样转录，保留 `[无法辨认]` 标记。比较画质时避免裁剪，以便两次取景对应同一张卡。

先在权限为 0700 的本机目录，用 `--template --output /absolute/private/input.json` 建输入模板。每种模式的 `status` 可为 `recognized`、`failed` 或 `not_run`。成功取得转录时填写 `text` 和 `[宽, 高]` 的 `dimensions`，失败或未执行保留空文字和 `null` 尺寸。用 `--input /absolute/private/input.json --output /absolute/private/score.json` 生成新报告。

报告保留每张卡的替换、遗漏、插入、无法辨认标记和失败数，以及两种模式均取得有效转录时的字符错误率。空白不计，数字、大小写、标点和字符顺序参与评分。`[无法辨认]` 不按字面计入转录，缺字计遗漏。高清若落回标准尺寸，或像素数未超过同卡的标准图，会单独计数并排除出成对对照。报告不写入转录、照片或输入路径。方向、模糊、实际 USB／Wi-Fi 传输和拍后释放继续按镜头验收记录核对。

保留默认「标准、取景 5 秒后直接分析」。设置 → 看图设置可以选择高清，并单独开启「拍后核对，可重拍／裁剪」；长按看一看也可进入。设置仅在本次 Activity 内存中生效，设置本身不打开镜头。返回桌面、换线或全断关闭相关页面与拍摄；重连不拍照。

高清使用 Camera1 实际支持的 NV21 预览尺寸，取固定上限内的一档：最长边 1280、总像素不超过 1280×960、JPEG 最多 768 KiB。旧后台或不支持高清的镜头退到标准范围，并显示原因与实际尺寸；不能把声明上限称为已验证传感器画质。标准上限仍是 640／640×480／384 KiB。每次请求固定版本与上限，连接能力变化不会扩大已经开始的授权；封包及 12 KiB 分块不变。

开启核对时，拍完先关闭相机，仅在内存显示这一张。可发送、重拍、拖选裁剪、还原整图或取消；每个任务最多拍三张，每次重拍都重新等待首个可见画面满 5 秒。整项操作最多 70 秒，不因重拍延期；Mac 对这类固定授权等待最多 75 秒。发送／取消／超时／Home／换线会清除图片及过期回调，裁剪工作线程独立持有正在读取的像素。默认直发仍是设备 11 秒／Mac 16 秒。显式桌面拍照维持自动 5 秒返回，不等待核对，避免改变当前聊天拍照命令的超时语义。

设置 → 识别图片文字，或长按看一看 → 识别图片文字，提交一次明确的 OCR 拍摄。Dot 按原顺序保留换行，看不清标记 `[无法辨认]`，不补全姓名、金额、日期和数字，不执行画面中的指令。旧后台没有明确能力时入口拒绝，不静默改成普通看图或换模型。

唤醒后也可以说「读一下这张纸上的字」或「识别镜头里的文字」。明确的当前镜头识字请求使用相同的转录提示和五秒可见预览流程。普通看图仍按场景描述处理。

隔离开发快照在真实 CC8 上完成七项无相机／麦克风／联网权限的合成图片检查，含 1280×960 解码发送、触摸裁剪实际编码为 401×320 且像素对应选区、逐字节还原原 JPEG、三张上限、取消、替换旧解码与 Home 后不复用。231.331 秒完成并移除测试包，原助手／实例／配置和私有存储保持，双端停采。首次完整源码隔离包因删权限后的未使用联网代码 lint 失败；首次 UI 倒计时刷新导致无法取得 idle，收尾误用不支持的 pm 卸载命令失败，后用 cmd package 清理并核对，原失败保留。修复 UI 无效刷新后只包含图片组件的无权限包通过。该证据不代表真实镜头、云端 OCR 准确率、正式发布包 UI 或完整 P1 验收。

高清软件经 [PR #461](https://github.com/batipang/CC8/pull/461) 与 [main 八项 CI](https://github.com/batipang/CC8/actions/runs/42628032290) 通过。首次更新在空闲预检阶段停止，未停服务或安装；随后有界观察未取得维护空闲窗口，保留原结果，正式运行仍为 0.16.12／code110。与本张照片追问合并为下一次组合更新，不单独重试中间版本。普通文字历史不等于仍可读取旧图像素；P1-04 整项保持开放，待正常光照 20 个固定物品／标签／文本的对照及 OCR 字符错误统计，软件、隔离图片测试与真实镜头效果分别记录。

## 使用

- 在助手前台点击底部「看一看」，即使麦克风关闭也可使用。首次需要授予 CAMERA 权限，随后再点一次。
- 语音已经开启时，可以说「大黄蜂，看看我手里是什么」「看看镜头前有什么」「读一下这上面的字」。先把物品放到镜头前，并保证光照。只有通过现有唤醒和回声过滤的明确看图语句才触发，普通「看看新闻 / 项目代码」不会开启摄像头。
- 语音和按钮触发共用 5 秒实时预览：从第一帧真正显示时开始倒计时，显示「调整画面 · N 秒后拍摄」，期间可移动物品或调整角度。满 5 秒才取一张当前画面，随后即释放摄像头，再由 Dot 分析并以 MiniMax 音色回答；字幕 / 嘴型沿用实际播放进度。相机打开 / 预览 / 采集最长 11 秒；Mac 发出取图请求后等图最多 16 秒，尚未开始取图的排队请求会在 15 秒后退出。
- 「停止看图」、预览上的「取消拍摄」、打断按钮或返回桌面均能取消。已有语音会话可继续普通插话；独立看图不会自动开启麦克风。
- 普通对话选择 MiniMax 时，看图仍明确交给 Dot，完成后原文字对话选择不变。长按头像仍可进入原来的 20 秒纯本机检测页。

当前是一次请求、一张画面，不是连续视频，也不会在启动、重连或后台自动拍摄。Dot 的回答可能有误，看不清时应说明；当前模型若不接受图像或任务失败，不会换模型或把旧图片冒充新画面。

0.14.5 / APK0.9.2源码候选补齐画面获取、Dot、TTS分类失败及安全相机错误代码；清理控件不覆盖本次错误，不以通用错误文字代替真实Dot结果。详情见 [失败反馈](FAILURE_FEEDBACK.md)。当前运行版本仍见 [TODO](TODO.md)，不把源码回归当作已部署或实机故障验收。

## 数据流

1. 设备按钮生成本地 nonce；或 Mac 处理已识别的明确视觉语音请求。Mac 建立新的回答 generation 和随机 request ID，设备只接受前台、当前代且匹配授权来源的拍摄。
2. Camera1 在独立线程打开前置镜头，默认使用标准 NV21 预览；原设备已实测 640×480，新候选按实际支持列表与当次授权选择。屏幕实际可见满 5 秒后编码当时的一帧 JPEG，按传感器／屏幕方向旋转。高清编码为满足当次字节上限可降低 JPEG 质量；提交或拍后核对前释放摄像头。图片不是拍照尺寸列表中的高分辨率静态照片。
3. 图片沿现有 USB 优先／已配对 TLS Wi-Fi 通道传输。保持原 64 KiB 封包上限和 12 KiB 分块，JPEG 按当次标准 384 KiB／已协商新版 768 KiB 固定上限检查；同时校验顺序、总长、SHA-256 和本次授权尺寸。不同代、不同 ID、过期、重复或过大的传输不能进入 Dot。
4. Mac 在 RAM 中组合当次图片，以 `turn/start` 的 `image` data URL 输入同一个独立临时 Dot 会话，不创建图片文件或公开图片链接；沿用用户配置和已有登录，不新增服务商或 API Key。接口依据 [Codex App Server](https://learn.chatgpt.com/docs/app-server)，并核对了本机 CLI 导出的 UserInput 定义。
5. Dot 的文字结果经 MiniMax TTS 播报。图片不交给 MiniMax；语音／按钮分析流程不把图片写入状态、日志、录音、相册或仓库。Dot 模型服务会处理该图片，其临时会话可能保留图像上下文；这不等于完全离线识别或对服务商留存作保证。

取消、退后台、通道切换及全断会使旧代失效；没有成功获得新图时明确失败，不用上次图替代。图片中的文字按内容处理，不能授权额外的工具操作；不因看图扩大 Dot 工具审批范围。

## 开发与验证

- Android：`SingleFrameCamera` 负责可见的单帧采集和资源释放；`MainActivity` 提供按钮、权限和预览；`VoiceSession` 管理授权、状态及分块发送。
- Mac：`vision.py` 负责明确意图识别、限时分块组帧和校验；`bridge.py` 管理取消 / 回答生命周期；`BrainRouter.vision_clauses` 固定走 Dot；`DotBrain` 使用内联图片输入。
- 自动测试覆盖误触发、取消和过期、乱序 / 坏哈希 / 大图 / 尺寸不符、旧代取消不能影响新图片、无麦克风看图、Dot 原生图片输入与路由、失败时不分析旧图。
- 实机结果见 [VALIDATION.md](VALIDATION.md)。只提交非图像验收结论，不提交原始图像或私人检测文件。

明确从桌面 Dot 请求「拍照并显示在这里」时，新增独立入口会返回照片文件用于当前聊天展示；这是内存图片默认策略的按请求导出例外，详见 [DOT_CONTROL.md](DOT_CONTROL.md)。
