# 当前录音内的本地中文复核恢复

后台 **0.15.58 候选**，APK 保持 **0.9.51／code88**。本批关联 P0-02、P0-03、P0-06 和 F-20，只恢复已明确开启录音时的整句中文复核子进程；MiniMax ASR／TTS、owner Dot、五秒模型加载和一秒整句解码期限保持。

## 恢复策略

只有当前有效录音帧推动恢复，无后台定时器，构造和健康查询均不能启动模型或麦克风。一次显式录音拥有独立预算：每簇最多三次启动，包括首次启动；失败后分别等待两秒和五秒，连续就绪三十秒才补充预算。仍在加载或尚未回收的旧子进程不能被重复创建；超出加载期限与一秒清理宽限仍占用的进程进入明确失败状态。长期运行后才失去就绪，从该次失去就绪重新计算清理宽限。

停止、Home 和全部认证线路丢失撤销原录音及待重试状态。重连不会重新开麦。预算耗尽后显示暂停／重新开始的指引，只有明确的新录音能开启新的预算。模型退出、解码超时或错误不会重放原音频、自动重交 ASR 或 Dot 工作。

## 并发和状态

候选凭据增加模型代次；排队前取得的旧候选和解码中的旧结果不能借用替代子进程。最终归属检查与亮屏／唤醒状态修改共用短锁，创建／关闭进程和活动／路由回调都在该短锁之外。有效帧在会话锁与原生解码锁之外推动恢复，随后重新核对原录音归属。已唤醒对话仅维护模型，不将对话音频送给关键词流。

健康报告 `chinese_complete_recovery` 为有界的状态、累计启动次数、当前预算和剩余退避毫秒；没有 PID、路径、原始错误或音频。报告读取不可变快照，不等待子进程启动／关闭。安全等待状态显示恢复提示，就绪后清除，播放或已有任务期间不覆盖原状态。沿用设备已有的可恢复错误详情区，避免 listening 阶段的固定标签隐藏实际指引；恢复就绪后回到普通倾听。

## 验证与限制

定向检查覆盖有限退避、稳定补充、手动停止、长期健康后故障、无法回收及关闭错误、健康查询不阻塞、旧模型凭据、解码中换代及活动回调取消。隔离真实子进程验证死亡后回收／替代、一秒解码超时丢弃与随后新请求，以及停止后不再启动；强制线程交错核对最终提交不能被模型换代切开，路由回调不持模型提交锁。

这些测试不采集设备音视频、不开云模型，也不代替部署后的真实模型故障恢复或完整待机验收。上一版固定声源实机通过和待机收尾失败见 [整句中文复核](COMPLETE_CHINESE_WAKE.md#01557-实机对照和明确启用)。不重复未受评分规则改动影响的 544 条固定模型对照。完整 P0 仍以各自验收门槛为准，最终 72 小时保留在全清单最后。

本机后台全量 1618 项通过（4 项既有私人录音 opt-in 未启用），定向唤醒 142 项通过，固定质量检查通过（386 个 Python 文件、14 个严格类型模块及既有 Java 格式）。提交前调用方审阅另外发现 listening 的提示会被当前 APK 固定标签隐藏，改用既有可恢复错误阶段，并补对应断言。最终提交及实际 CI 另核对精确源码，不把本机软件结果写作实机故障恢复。
