# 完整语句的本地唤醒复核

后台 0.15.51 候选为 P0-03 增加补充路径。保留实时中英文唤醒和原有双路英文流；当它们漏检时，只对当前 VAD 已完整结束、没有播放风险的等待唤醒语句，创建一个独立的本地英文流再判断。使用已载入模型、原有八条解码路径和近音竞争词，不改阈值、增益或 ASR/TTS 服务。

## 授权与资源边界

- 在 VAD 开始时绑定唤醒序号、任务代次和实际最早前卷采样时间；不能把进入等待状态前的音频带入新授权。
- 候选走已有两项有界识别队列，但先做本地关键词判断。只有本地准确输出 `Bumblebee`，并在会话锁内再次确认归属后，原句才可进入 MiniMax ASR，再交 Dot；普通讲话保持本地拒绝。没有通用云端唤醒兜底。
- 停麦、断帧、换线、更新唤醒状态或播放 / 校准风险使旧判断失效；本地每帧复核当前归属，native 解码期间不持有会话锁。使用独立流和已有模型锁，不重置正在工作的实时流。
- 临时 float32 副本在所有退出分支清零，原句不会被改写；正常内存生命周期后释放，不写录音或文本。超长、缺失或非有限样本不建立解码器。
- 复核成功的已完成任务自己消费名字前缀，下一句不继承该前缀；旧句失败后若另一实时唤醒刚好到达，旧句也不能借新授权进入 ASR。
- 健康报告只增加就绪、次数、命中、错误与本地耗时；可选 native 异常保持拒绝并记录错误类型，不冒充语音服务故障。

本路径在语句结束后才补查，不能宣称零等待唤醒或改进所有真人识别。原有实时路径命中仍直接走原流程。APK 0.9.47／code84、协议 2 和正常关麦 / 重连规则保持。
