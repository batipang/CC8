# 明确启用的定时工作汇报

目标：补齐P1-03／P1-10的可选完成提示和定时汇报。默认关闭，只检查用户当次明确选择的聊天或登记成员范围，每5／15／30分钟检查一次；没有新增或可行动变化时保持安静。后台0.16.24／助手0.9.97 code134已组合交付数量提示、明确选择的原答复摘要及最近检查结果；当前设备仍未启用该功能。八项CI、两项受影响的正式默认关闭界面与独立原后台复核通过，见[当前部署](CURRENT_DEPLOYMENT.md)。真实来源／系统通知正向送达仍在最终环境队列。

确认启用时说明：保存必要的来源元数据、启用起点、已提示结果标识／版本摘要和送达认领，不保存结果正文、原始聊天、录音、图片或模型上下文。最多256个已提示版本，不自动淘汰；达到容量、时间范围超过31天、来源删除或时钟异常时停止并提示明确重新设置。修改／清除需要当前修订与明确确认；无关登记修订不改变冻结的成员范围。

默认和旧配置只提示本次最多3个新增完成答复的数量和来源，明确原答复尚未独立核验。0.16.24允许在CC8渠道再明确选择“朗读原答复摘要”：逐项朗读服务器读取的原答复摘录、完成时间和回执情况，不调用模型重写，不把模型自述当成已验证事实；截短、覆盖不足和剩余已读结果都会说明。Mac桌面渠道仍只提示数量，不支持摘要模式。

摘要每项最多500字符的原摘录，整个内部播报最多4段、4000字符，段内沿用120字符的播放块及字幕／嘴型／打断链路。只有一项全部播放块收到设备确认，才将该项版本记为已播；整段job完成不能替代逐项回执。打断或落盘不确定时，已确认项保持，剩余项冻结为未确认并暂停，不自动重播；可按原范围明确请求手动汇报。数量提示的送达仍不代表摘要播完，两种模式都不代表原工作已验证。

最近定时检查的完整正文只保留一个RAM快照，期限10分钟，绑定本次来源／冻结成员、配置ID、实际连接和认证线路。入口“结果／管理 → 最近检查结果（只读）”支持完整分页；查看和翻页不重新查询聊天、不保存正文、不恢复旧语音编号、不变更手动补播进度，也不执行原任务。新一轮失败或取消不继续把旧成功显示为最新结果；Home、连接变化、维护租约、暂停／清除／重设和过期会使旧结果失效。覆盖不完整和已提示内容仍明确展示。

私有数量配置仍是schema1，只读或启动不迁移；只有明确选择摘要才原子升级为schema2并保存模式，依旧不保存结果正文。恢复旧reader前必须重查格式兼容，不能用旧文件覆盖索引。明确清除，或明确接受重新设置为数量模式并重建索引，才回到schema1；详见[升级准备](UPGRADE_PREPARATION.md)。

每次从启用起点重查至本次冻结截止，包含迟到收集的结果，按真实来源／回合／结果及版本去重。部分覆盖或失败不等于零成果，不提前推进读取起点；容量和原有读取上限需要明确展示，不能推断其他来源没有结果。

调度只在CC8前台已认证连接、整条管线空闲且不在既有提醒安静时段时读取／通知。配置确认可明确准入本次前台连接；重启或Home后仅持久配置不会自动准入新连接，正常用户开始语音后可恢复其已启用配置，暂停麦克风后同一前台连接可继续提示。维护无自动语音开关、测试独占锁、Home和线路变更不得触发新的扫描或通知；不自动打开麦克风、相机、窗口选择器或后台界面。

发送前原子认领；只有实际CC8播完或匹配的通知中心回执才记已提示。中断、异常、认领耐久性未知或重启遗留不自动重发，明确显示送达未确认。清除／重新配置后旧回执不能改变新配置。暂停通知不取消原工作；用户之后的明确手动汇报仍可读取原成果。

实现检查：私有存储／协议、实际调度器与真实控制器、编译后的原生窗口、Home／线路／旧回执、未确认认领、安静时段、范围和容量。默认不请求真实通知权限、不采集媒体、不读取实际聊天；真实来源与系统通知授权仍在最终环境队列，72小时最后。

软件入口：暂停语音 → 工作汇报来源 → 汇报选项 → 定时工作进展提示。设置时逐步选择5／15／30分钟和CC8／桌面渠道，CC8再选择数量／原答复摘要，核对服务器当前来源及保留规则后确认；旧后台不显示摘要选项。桌面渠道不自动请求系统权限。暂停保留索引；清除只删除此功能的配置和索引。重新设置从现在重新开始，不补发旧通知。当前只有一份明确范围配置，不自动扩大到全部聊天。

默认Bridge组件不会创建计时任务或读取订阅文件；真实生产启动工厂明确注入私有存储，测试仅注入临时存储。独立自动化租约按原路径只读检查，未创建、未夺取租约；租约期间撤销旧准入，测试结束本身不恢复查询。线程读操作共用实际聊天读取的忙碌准入，失败只保留类型诊断，不输出正文；通知仍优先让既有提醒先处理。
