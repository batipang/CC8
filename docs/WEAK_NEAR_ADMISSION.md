# 播放风险中的低证据识别结果

后台0.14.11源码候选在原识别门控之后增加`weak_near`分类。现场0.14.10曾在正常回答播报期间，把一个只有2帧credible输出的候选识别成了与脚本无关的流畅短句，文字/参考ASR比对没有拦住，进而中断原任务并交给Dot。新规则阻止这类低证据候选直接成为新请求。

仅当原流程判断有播放回声风险、原request ID有有效capture观察、没有本地唤醒命中且不是已有停止指令时，要求句内至少5个credible帧（每帧10ms）。这是已有近端检测器确认输出的累计50ms，不是声纹、真人判断或声学暂停延迟。取值在本批20组对照采集前已冻结，没有根据留出音色结果重调。缺少观察的旧式组件输入保持未知，不把缺测补零；实际Endpoint在句尾、入识别队列前绑定观察，离线集成回归验证这一顺序。

低于门槛时，不推进代次、不发transcript、不交给Dot或视觉入口，原暂停按既有拒绝后恢复规则处理；旧代次不能恢复或覆盖新请求。已有停止词、本地唤醒、无播放风险的输入及已确认近端问题沿用原流程。没有提高能量门槛、改音色/服务/权限、增加模型重试或延迟最初的暂时暂停；因此本补充**不等于误暂停频率已达标**，后续仍需单独解决和验证。

门控复用TraceBook上不可改写的capture副本，不复制音频。`weak_near_rejections`在显式开始语音时清零。新版采集器认识新增枚举，旧严格采集器需先更新，不能把它当普通accepted。

## 对照证据与缺口

0.14.10实机预定20组：4组仅参考播报，16组由Mac播放已安装Tingting/Meijia合成短句，文件播放增益1.0/0.25；不改变Mac主音量或CC8音量，不声称校准了SPL、物理距离或真人说话。前17组之后，原型因Wi-Fi通道瞬时未就绪的前置检查停止；USB保持连接。原报告保留，仅对未执行的C18～C20改用与本轮相关的USB门控补采，固定来源/条件/候选门槛不变，没有重跑已完成样本。

16个外部刺激中，14个已准入回合与已知短句完全匹配，可信帧数最低28；另两组分别在原文字回声门控被拒绝、没有形成候选，均保留为缺口，不记通过。4个仅参考案例没有观察到新语音候选，但这是较长的固定参考句，不能冒充覆盖先前短数字回答的错误形态或推断一般误唤醒率。匹配观察仅保留布尔值，不保存识别正文或回答。未完成的病例、不同批次与合成音色不被合并成真人验收。

另显式启用旧私有输入的离线重放：原AEC3+近端检测器对旧纯播放文件没有成句，对旧有人说话文件观察到累计53个credible帧的片段；该片段到文件末尾仍未收尾，不计一次完成对话。无新录音、云调用或处理后音频保存。它只支持本候选不会因低可信计数筛掉这段旧输入，不证明当前房间的完整表现。

私有证据为`voice-sequence-286e5208.json`、`barge-calibration-summary-01410.json`及其原始/续采/匹配报告、`near-evidence-ae94c40e.json`。源码回归使用合成数值重现短确认形态，不提交录音、正文、原始报告或设备标识。

## 软件回归

实际RecognitionWorker执行低证据流畅误识别→拒绝/恢复、已确认问题接续、低计数停止词/本地唤醒/空闲输入、不具备观察的旧组件、迟到识别与新代次隔离；视觉路由用内存hook，弱候选不开镜头，确认请求仍可路由，没有设备或模型访问。

测试还发现裸“看一看。”因句号不能命中原短指令fullmatch。候选仅允许明确短镜头指令末尾的句末标点，保留否定、引用、代码查询与额外文字的拒绝，不剥去引号或扩大后台取景范围。两项定向回归在旧e82c1cb上分别复现一处断言失败、零fixture error，修复后通过。

准入在原session guard内重新检查代次并原子完成唤醒/停止/路由，capture副本的锁在进入guard前已释放。新增两种强弱计数的线程交错回归，在开发中未加原子保护的快照上各出现一处断言失败；当前实现通过，不能把开发快照称为先前部署版本。另覆盖播报尾音被拒绝后恢复listening，避免停在thinking。

最终离线检查：installer23、host655（4项旧私人录音未显式启用而跳过）、tooling100、Java15全部通过；Ruff格式/规则、Java与七个严格类型文件检查通过。无新包/模型/设备采集；实机部署与新轮语音检查另行留证。
