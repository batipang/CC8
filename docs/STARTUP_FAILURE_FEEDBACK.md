# 请求尚未开始时的失败反馈

后台0.15.72／助手0.9.54（code91）源码候选关联P0-01、P0-02与P0-06；包含前一批[播报提交](ANNOUNCEMENT_ADMISSION.md)的配套恢复工作。当前现场仍为后台70／code90，新的主机与APK需集中部署验证；不改变原音色、MiniMax／Dot分工、麦克风策略、头像或字幕布局。

## 明确失败，保留新请求

此前启动失败虽会回滚归属，但开始通知前没有设备任务可承接普通错误状态，本地队列异常还可能冒泡至连接循环。现在文字和逐字播报在原锁内清理后发布分类指引，明确「本次文字指令未启动」或「本次播报未启动」。文字开始通知／亮屏故障沿用transport分类，诊断、队列、准备及初始取消故障沿用runtime分类；只依据异常类型，不传播异常正文。

反馈绑定原取消操作推进后的代次。更新请求、线路变化或清理回调已取得新归属时，不发布旧错误；诊断同样绑定原代次，不能把新任务标成失败。反馈再次失败只记录固定阶段／类名，调用者仍取得原始错误。没有自动重交、重播、开麦或补执行。

设备文字入口捕获已处理的队列、运行及I/O错误，不因此退出事件循环。尚未取消任何工作的输入／就绪拒绝保持原通知；已回滚的启动失败使用上述分类反馈，不追加一条可能覆盖新工作的通用拒绝提示。

## 设备端的接纳边界

沿用原status事件，仅错误反馈带严格布尔 `request_start_failed: true`。code91允许在当前取消代次尚未开始任务时接纳一次这种错误；字符串 `"true"`、没有当前取消归属的未来代次、已开始／已失败的重复反馈、旧代次和后台页面均不能借此重开状态。已有录音／播放错误的接纳方式保持。

状态仍展示可点击的完整固定指引，不制造任务、任务进度或成功回执。停止朗读不撤销已经完成的操作。原code90可忽略新增可选字段，但在开始通知前可能仍看不到错误，因此该功能的完整验收要求新APK与主机配套。
