# P0-06：分类失败与恢复（0.13.1 候选）

失败按语音识别、助理执行、语音合成、设备播放、设备连接、画面获取和本机运行分段；原因只使用稳定类别：超时、限流、额度不足、凭证/服务权限、审批拒绝、连接/读写和其他服务/运行错误。屏幕沿用现有 error 状态展示阶段、原因与可执行的人工恢复步骤，不新增一个不能执行的按钮。

## 行为

- ASR 失败：这句话不会交给大脑；检查服务后可再说一次。
- Dot / MiniMax 大脑失败：结果可能不完整，先在电脑端核对已执行步骤。错误不再被包装成普通成功回答，RAM-only 任务卡保留固定的失败指引。
- 本次工具审批已拒绝：需要审批的操作本次未执行，已执行步骤仍需核对；当前没有悬挂的待批准请求。到电脑端核对权限后重新发起，不自动批准或虚构恢复入口。
- TTS 失败：明确是语音合成失败，已收到的真实 Dot 完成回执保持完成。查看任务结果，避免重新交办同一任务。
- 设备播放错误或没有 play_done：取消旧音频、显示播放失败/未确认；发送完 PCM 不算播放完成。停止与字幕/音频代次保持一致。
- 旧代次迟到错误：不覆盖新请求的界面或重放旧内容。离线仍按既有规则停止采集，重连不自动开麦。

没有自动重试 ASR 上传、模型执行、工具写操作、摄像头或播报。健康/只读诊断仍由原有监督/采集周期有界查询；不将未知任务包装成“只读”后重试。任何可能有副作用的请求，恢复前先核对回执。提供方不会被静默切换。

## 边界与保密

OperationFailure 传递固定 stage/kind；Dot RPC 和 turn 的已知超时、断连、审批拒绝在发生处分类。MiniMax 三种真实 Transport 入口保留 requests Timeout / 连接错误类别，不再统一丢成未知网络错误。HTTP 429 / 402 / 401、403 分别归限流 / 额度 / 凭证权限；不猜 MiniMax 未核实的业务码，未知仍显示其他服务错误。

流式 TTS 的下一块 PCM 失败仍属于 TTS，不因前一块 PCM 已播放而误标播放失败。任务回执和播报结果独立；取消音频不撤销已完成工作。错误 UI、任务恢复说明和日志不拼接异常正文、服务响应、密钥、地址或识别内容。

Dot turn 截止时间和播放 ACK 截止时间保持。MiniMax 的累计网络预算补充见下文；恢复状态仍需实际请求证明。

在 44eaff7 基线源码上，两个定向回归分别确认 Dot 错误被当成普通回答、缺少播放完成回执时没有分类失败，两者失败；候选同样测试通过。所有输入为合成 PCM/假 API，不触达设备或云服务。

新增 11 项离线测试内含矩阵：大脑的超时/限流/额度/凭证/断网/审批拒绝各 3 次；ASR 与 TTS 的前五类各 3 次；真实 MiniMax Transport 三个入口的 requests 超时/断连各 3 次。每次断言最多一次请求、busy 清理、任务终态和固定 UI 指引、秘密 sentinel 不出现在事件/日志/报告。另覆盖真实 RPC waiter 超时/清理、后半段 TTS 失败、play_done 缺失、设备错误和旧代次迟到。真实服务/额度/网络、CC8 显示及恢复体验仍需部署后验证。

当前运行助手没有更新；候选不改变模型选择、音色、原签名或采集授权。

补充真实路径回归：MiniMax 搜索错误原先仍被转换成普通回答，可能关闭成完成任务；候选 0.13.4 改为失败向上透传，并仅记录白名单错误类别。实际 MiniMaxBrain→BrainRouter→ResponseWorker 的五类失败各 3 次及 failed 进度正文注入在修复前均复现、修复后通过；无模型请求。未修改查询规划失败时原有的直接关键词准备逻辑，也不将“成功检索但无结果”改成服务错误。

补充断连收尾：0.13.5 在发取消通知之前先作废本地状态并唤醒播放 waiter，普通连接错误不阻止 Stop 释放采集；即使提供方取消抛出未预期错误，Stop 的 finally 仍关闭 AEC/收音并保存状态，错误本身保留。play_begin、PCM、play_end 和字幕发送错误统一定位 transport，provider iterator 内的字幕失败不重标成 TTS。该软件回归不代表已完成物理拔插。

## 0.14.3：慢速响应的累计网络预算（软件候选，未部署）

Requests 的 read_timeout 只限制一次读取。服务每隔一小段时间返回几个字节，可让响应头、JSON 或 SSE 持续拖延，即使每次读取都没超时。现在每个 MiniMax ASR / JSON / SSE 请求独立累计连接与 socket 读写耗时，预算为现有 connect_timeout + read_timeout（默认8+20=28秒），每次实际 socket 操作的等待上限同时受剩余预算约束；不增加重试、不改服务或凭证。

预算经过 HTTP 缓冲解析器生效，涵盖响应头、正文、chunk framing 和普通 HTTP 代理 CONNECT。池类映射按请求复制，保持证书/主机名验证与已有代理配置；不修改 urllib3 全局池映射。当前 Requests/urllib3/Python 固定版本已做真实 TLS 回归；没有声称未测网络栈或所有代理实现都兼容。

正常播报、暂停和消费已返回事件的时间不算网络等待，避免长回答仅因播放较慢而失败。它是累计网络 I/O 预算，**不是整段对话的墙钟上限**；系统 DNS 解析不能在此处中断，返回后才计入连接耗时，这个界限仍保留。没有将该补充当作完整 P0-06 验收。

取消先只 shutdown 当前请求拥有的 socket，唤醒响应头或正文阻塞读取，再沿既有异步关闭路径收尾；重复取消不再持续创建关闭线程。TLS-in-TLS 包装本身没有 shutdown，取消沿它的已拥有底层 socket 执行；该分支有固定版本结构回归，不冒充完整 HTTPS 代理实测。旧请求不能关闭后来的独立请求。Requests 将流式读取超时包装成 ConnectionError 时，也归为 timeout，保留现有分阶段失败指引和已完成任务结果。

自动测试使用临时证书、证书验证开启的 loopback TLS 服务：修正为完整消费请求体的 fixture 在旧 bfb6388 实现上复现5处预期失败、零 fixture error；修复后响应头/JSON/SSE/CONNECT 滴流均按预算结束。另有正常三入口、成功 CONNECT 后的 TLS/JSON、取消阻塞头/正文读取、错误主机名拒绝、缓冲 makefile、嵌套不重复记账、消费者时间不计费、请求/代理池隔离和重复取消回归。不联系模型服务、不启停设备或开麦。

## 0.14.4 / APK0.9.1：错误不再被收尾覆盖（软件候选，未部署）

自动检查发现，麦克风关闭时的TextReply失败先执行finish_text，清掉唯一有效owner，再进入外层错误处理；valid已为false，因而只有正常text_done，没有错误提示。现在串行worker在owner仍有效时先发布分类错误，随后才清理文字会话。错误发布与新请求准入共用已有session锁；ASR与指定播报的同类失败发布也采用这一边界。清理通知发生连接错误时仅记固定异常类型，worker继续处理后续请求，不重试已执行任务。

设备端原先无条件用“任务已结束/播报未完成”替换错误。现在StatusFeedback只保存代次/终态标志，不保存内容；结束回执仍释放播放控件，但保留同请求的错误及恢复说明。状态必须属于前台当前请求，低于取消边界或已知最新代次的状态不能覆盖新请求；旧text/announcement结束回执也不能关闭较新的控件。切换连接或显式开始新麦克风时重置这份状态。

播放失败会先cancel输出，再报告原因。只有设备刚刚拥有该取消请求时，才接收对应代次的一条终态错误；无任务的被动取消不授权任意错误，重复取消不隐藏已经显示的错误。实际协议的cancel(N)→text_begin/announcement_begin(N)仍允许第一次合法begin；重复begin不能重开失败请求。正常多句播报和下一次成功请求仍正常收尾。

状态栏显示阶段/原因摘要及“查看详情”；点击错误状态打开可持续阅读的完整处理指引对话框，关闭只关闭对话框，不重新交办、批准工具或开麦。成功任务的真实回执不因朗读失败而改变，副作用结果仍须先核对。

13项新增回归执行真实Bridge/ResponseWorker/RecognitionWorker/AnnouncementController及有界线程屏障；文字模式六类错误各三次，校验一次请求、分类指引先于text_done、失败任务终态及无异常正文泄漏。JDK编译的是从实际VoiceSession提取的六个事件分支和真实StatusFeedback，覆盖错误保留/正常收尾/旧状态/背景/取消后错误/同代次cancel→begin/多句播报；最小接口不调用Android I/O。旧ada7aa3源码对同一测试复现30处失败，零fixture error；修复后通过。这不是实际屏幕渲染、TLS线路、设备线程或云服务故障演练；Android编译/lint与这些回归不能关闭整项P0-06。

## 0.14.5 / APK0.9.2：看图与桌面拍照的分类失败（未部署）

旧看图流程捕获Dot或TTS异常后发送普通idle状态和一条假作Dot结果的固定错误文本；设备释放相机控件时又覆盖错误。现在接受请求时即建立无内容的vision诊断记录，失败在当前owner仍有效时发布，随后清理。画面未取得时不会运行Dot；真正的Dot/任务完成回执不被后来的TTS失败或通用错误文本替换。桌面拍照失败同样保留安全错误代码、释放等待方，不返回照片、不调用Dot/TTS或自动重拍。

新增`vision`错误阶段，显示“画面获取”。相机权限/前台授权、明确超时、图像传输分别归现有稳定类别；取消与超时分开，未知相机字符串归`camera_failed`，不因符合小写代码正则就原样进入指标或IPC。内部JPEG/分块校验错误仍只保留固定枚举。错误阶段的诊断校验和采集器共用同一来源；采集器需随后台更新，旧记录仍兼容读取，不把旧工具当作已支持新阶段。
