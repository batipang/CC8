# P0：播放时钟的生命周期对照与后续实现

2026-11-05，生产仍为后台 0.14.85／原签名 APK 0.9.35（code72）。本次只安装和移除独立的输出测试包，没有替换生产 APK、重启后台或采集声音、图像。功能排期仍在 [统一 TODO](TODO.md) 的 P0-01／P0-04；本页保存实验依据与实现约束，不增加第二份待办。

## 实际设备对照

隔离包复用当前源码的 `PlaybackClock` 和 `RenderClockStats`，配置与生产一致的 16 kHz、单声道 PCM16、STREAM_MUSIC、缓冲下限和 0.35 轨道音量。APK 经实际清单检查不含任何权限，不使用麦克风、相机或网络。每轮写入 60 个 320 帧块，以低音量短音和尾部零样本检查时钟与播放头；播放头确实越过短音末尾才收录结果。

首次对照依次执行三组，各六轮：每轮新建并直接写入内容、每轮新建并先写入 9600 个零样本、同一 AudioTrack 跨六段保持零样本间隔。9600 个样本对应 600 毫秒音频，不等于测得的初始化墙钟耗时。随后按预先固定的冷／热／热／冷顺序重复三次，共十二轮，使用不同的短音。验证前约定：六轮热启动均无超过 40 毫秒的步长，最大步长不超过 2 毫秒，并与交错冷启动控制比较。

| 条件 | 轮数 | 出现超过 40 毫秒步长的轮数 | 各轮最大步长的范围 | 应用写缓冲欠载次数合计 |
| --- | --- | --- | --- | --- |
| 新建后直接写内容，含交错控制 | 12 | 12 | 64.038～107.747 毫秒 | 2 |
| 前置零样本，含交错验证 | 12 | 0 | 0.031～0.085 毫秒 | 0 |
| 持续播放时钟，首轮前置零样本 | 6 | 0 | 0.041～0.080 毫秒 | 0 |

两轮执行分别为 69.871 秒和 59.752 秒，测试包均核对摘要后移除，原助手不开麦恢复前台，同一生产后台继续工作。独立复核绑定了原始报告、实际编译 Java 来源、全部 18＋12 个数值结果及预定交错规则。报告摘要分别为 `c55b58e1c49304782aa15c9627c2385f539c01cc8e63a0650ac565b1f3df3ab9`、`1340bec602475d458be0a63bfaf2c7301da2b1dba6006f0eb30939c3b3a1a07d`；原始报告和研究脚本留在本机忽略目录 `speaker-clock-lifetime-20261105`，尚不是通用项目命令。

在当前设备与固定输入上，轨道初始化方式对应不同的呈现时间估算稳定性。冷启动共记录 17 个超过 40 毫秒的步长及 2 次应用缓冲欠载，尚未测量两者的逐项关系，不能把每次跳变都解释为欠载。这仍是数字时钟／播放头证据，没有测量扬声器首声、AEC 效果或一般语音准确率，也没有解释录音 API 的帧位置越界。

## 后续实现约束

拟由会话级输出组件拥有唯一 AudioTrack 和空闲零样本写线程，逐句 Player 只取得绑定 generation／playback ID 的租约。轨道初始化期间建立稳定时钟，语音会话内跨句保持连续；不在每句话前固定插入一段静音。字幕、嘴型和进度只看本句实际内容，不把空闲零样本算作已经播出的内容。

Android 的 [AudioTrack 时间戳说明](https://developer.android.com/reference/android/media/AudioTrack#getTimestamp(android.media.AudioTimestamp))区分初始稳定期与稳定运行后的低频查询，并建议在应用层构建高分辨率映射。后续组件需要分开物理累计帧、本句起点与内容帧，处理播放头的 32 位回绕；不能直接把轨道累计播放头送给现有逐句回执。协议 2、原音色、配置、权限和 MiniMax／Dot 分工保持。

| 边界 | 必须保留的行为 |
| --- | --- |
| 内容写入与空闲维持 | 同一时刻只有一个写者。租约交接等待在途零样本写入入账，旧线程不能写入或关闭新租约 |
| 正常句尾 | 确认内容末尾已播放后交还租约；后续零样本不推进旧字幕，也不改变已完成任务 |
| 临时插话暂停 | 暂停与恢复回执、参考时间线及冻结画面仍对应同一租约；暂停期间不启动空闲写者 |
| 确认取消 | 作废旧租约，暂停并清理旧排队声音；只在清理完成后重建物理计数与时钟锚点，迟到清理不影响新回答 |
| 手动停止、后台、两路全断 | 关闭空闲维持、取消在途写入并释放轨道；重连不能自行创建输出资源或开启采集 |
| 独立播报／看图回答 | 只在现有明确授权及前台生命周期内持有输出资源，结束后释放；桌面入口服务不持有音频资源 |

## 验收范围

先用真实线程验证租约交接、初始化中取消、阻塞或短写中的停止、迟到释放、暂停恢复和计数回绕，再执行原有 Java／主机回归与编译、lint。实机分别复核时钟来源、同回合多段播报、字幕嘴型、普通音量新问题插话、无人交办时无新回合及关麦收尾。同步修正不能只靠这三十个时钟结果关闭 P0-04。

还需测量逐句起播与总响应时延，确认没有每句额外静音，并记录前台空闲维持时的 CPU、内存及线程；后台和手动停止后不得继续写音频。正式 72 小时观察仍留到功能稳定后。这项输出改造尚未实现或部署，当前运行行为见 [当前部署](CURRENT_DEPLOYMENT.md)。
