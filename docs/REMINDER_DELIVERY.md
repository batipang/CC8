# 提醒送达、安静时段与迟到规则

后台0.16.9／原签名助手0.9.67（code104）已部署交互修复，0.16.10／code106为桌面通知候选；实际安装状态以[当前部署](CURRENT_DEPLOYMENT.md)为准。它复用原来的Mac提醒与CC8认证连接，不是独立系统闹钟；Mac关闭或CC8不在前台时不能保证准时出声。

## 使用

- 设备“查看提醒”→“送达设置”：明确应用或恢复默认。设置保存在Mac，改变设置不会开启麦克风或摄像头。
- 可明确说“晚上十点到早上七点不要播报提醒”“迟到超过三十分钟就跳过”。Dot须先读取`cc8_reminder`的`policy`，再以原修订提交完整`set_policy`，按真实返回确认；过期修订不能覆盖新设置。
- 默认关闭安静时段，默认对迟到事项补报。启用后可设当天或跨午夜区间，开始时刻包含、结束时刻不包含，均按北京时间解释；起止相同不表示全天。
- 选择跳过时，迟到从原定时间计算，时限1～10080分钟。超过时限才记为错过，恰好等于仍可送达。因此夜间提醒可能在安静时段结束前过期。新规则不倒推取消已经开始的播报。
- “查询提醒送达记录”对应`history`，最多返回12条保留记录。每个事项保留最近一次尝试，重复提醒不是完整事件档案。`list`包含待提醒、发送中及送达未确认事项。

## 送达状态与重复保护

到期、前台认证连接且语音／看图／校准／任务与识别队列空闲时，最多认领三条到期事项，在同一次播报中逐条播放。发送前先持久保存每项的事项ID、修订、尝试ID和原定时间。0.16.9候选还在识别更正草稿待核对时延后认领，不取消草稿；用户撤回或两分钟过期后重新检查原到期事项。发送未确认、中途停止、断线、播放失败或服务在发送后重启，均不自动再次播报这一发生次。

每条提醒的所有音频片段都收到对应的设备播放完成回执后，该条才记为已播完。播报中途停止时，保留前面已确认的条目，尚未播完或未取得回执的条目显示“送达未确认，需重新安排”。重复提醒只有当前发生次已确认后才推进到下一次。可明确修改到未来时间／“稍后10分钟”或取消；这建立新修订，迟到的旧回执不能推进或结束新事项。已经听到的内容无法撤回。

提交回执时存储失败，只重试提交同一回执，不重做TTS。文件已原子替换、目录同步却报错时，保留已发布状态，不回滚成可重播的旧状态。发送前出现这种不确定性时不发音，事项保持待核对。

发送中或送达未确认的事项，必须明确选择与原发生次不同的未来时间才能重新安排。只改标题、渠道或重复规则会被拒绝。取消或改期会保留已经记录的未确认回执时间与渠道。

新版 CC8 的修改、稍后提醒和取消会提交打开页面时读到的事项修订。Dot 的提醒工具也须先读列表，再提交对应修订。期间若已经完成、重新安排或进入送达流程，旧请求会被拒绝，请重新打开该事项核对。旧版 CC8 仍兼容原请求格式。

同一段合并播报或同一条合并桌面通知使用同一个送达尝试编号。每条事项仍以自己的 ID 和修订匹配回执，编辑或取消其中一条后，旧回执不能更新它的新状态。此前保存的送达记录继续按原编号读取。

如果进入安静时段、换线或改期发生在提交给播报或桌面通知服务之前，仍属该批的事项恢复为待发送，并保留上一次送达记录。下次到达可送达时段时重新按迟到规则检查。恢复待发送的写入失败时，后台先重试该次状态更新；进程崩溃后遗留的发送中记录仍显示送达未确认。

已认领的 CC8 提醒在排队结束和每段音频开始前复核尚未播完的事项。等待期间取消、改期、进入安静时段、超过迟到期限，或时钟退回到原定时间之前，都会停止旧批次。合成已经返回但未开始播放的音频会丢弃。已取消或改期的事项保留各自的新状态，其余未完成的发生次记为送达未确认。

迟到跳过有独立“错过”记录，保留原定时间与渠道。Mac 恢复后会跳过过期的积压周期。如果最近一次重复提醒还在它自己的送达期限内，保留该次待发送，并继续检查安静时段和渠道；否则推进到下一未来发生次。日、周和工作日提醒保留原钟点／星期节奏，不补发已过期的提醒。

## 存储与恢复范围

旧`version:1`提醒在读取时不改写。用户明确保存设置、管理提醒或到期送达时，写入`version:2`，含策略和有界尝试回执；任务聊天仍为RAM，不持久保存录音或相机画面。目录0700、文件0600，拒绝符号链接、硬链接、超限／重复字段和外部替换；同目录原子替换。

0.16.7及更早后台不能读取格式2。升级计划和三阶段APK预检现在读取既有文件的格式号与目标源码声明，分别检查候选和恢复版本，不导出提醒正文。格式不兼容必须停止；不能用旧文件覆盖新提醒，也不能仅凭APK签名与源码协议通过宣称数据可回退。发布维护还须确认文件在检查后未变化。格式2产生后若要退旧版本，需要另做明确的数据迁移或具备该格式读者的恢复版本，本批不自动执行这种降级。

## 验证边界

自动测试覆盖真实文件原子保存、发送前认领、实际隔离子进程退出后恢复、单次／重复／合并／跨日／安静区间、迟到跳过、取消和重排、旧回执、异常提交及原子提交后的同步故障。实际Java设置回调核对应用、取消、恢复默认、无效值和旧线路，后台复核策略修订。

这些检查不等于真实系统登录／睡眠、物理断网或人耳确认；候选的实体交付另行记录。桌面通知渠道与完整P1-03仍开放，最终72小时仍为最低优先级。

## 设置窗口与键盘

0.16.8实机发现自动焦点弹出的键盘会遮住底部按钮。0.16.9候选在窗口显示后聚焦表单本身，取消对话框的全屏限制，并明确使用隐藏初始键盘／编辑时调整可见窗口的方式；仍可手动点输入框完整编辑时间与分钟数，不禁用文字输入。参见[Android窗口参数](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#SOFT_INPUT_ADJUST_RESIZE)。

只读HUD补充设置窗口是否可见、输入是否聚焦、按钮是否完整落在可见窗口内和窗口底边，不导出提醒正文／编辑值。Home或换线关闭旧设置窗口，已排队旧路操作仍由原线路与策略修订拦截。实体开发快照检查已核对手动唤起键盘时窗口实际缩小且按钮仍可见；首次未通过的完整记录仍保留，干净发布与正式包另行核对。

## 桌面静默通知候选

0.16.10增加每条提醒明确渠道与最近送达记录；默认仍为CC8。桌面回执不冒充播完或用户已阅读。格式升级为schema3，旧数据读入不写回，reader2降级门控继续生效。准备命令、前台与安静边界、真实系统授权范围见[桌面通知](DESKTOP_NOTIFICATIONS.md)。
