# 结果来源、文件回执与显式定位

后台0.16.3／助手0.9.57（code94）候选扩展 P1-02／P1-10 的结果卡，不替代原聊天续办。仅当所选任务真实收到来源回执后，任务详情显示“来源与文件”；已有保存记录取得同样入口。普通任务与路径元数据仍只保留内存，只有明确点击“保存结果”才连同来源、结束时间和有界文件回执写入 Mac 的 owner-private 保存文件。

独立 Dot 执行记录保存当前本机客户端、实际临时 thread／turn ID；若使用了摘要接续，原聊天来源名称及 ID 单列，明确没有向原聊天追加。只读工作汇报记录原所选聊天，编号详情可记录对应原回合；整份报告不伪造一个“原执行回合”。本记录结束时间是后台完成当前请求的北京时间，报告正文中的来源完成时间继续取真实 `completedAt`，两者不混用。复制来源是明确的本机剪贴板动作，不自动发送任何聊天消息。

文件只接收同一已确认 thread／turn 的 `item/completed`、类型 `fileChange` 结构化回执，保存项目 ID、操作、状态、路径与可选移动目标。不从模型答复、引用历史或 Markdown 链接推测文件，也不保存 diff／命令输出。成功、失败、拒绝、删除和移动分别保留。同一回执 ID 的路径、操作或状态出现冲突时不保留为成功文件；未知、畸形、超出预算的数据明确标为覆盖不足。

接收监听在请求确认之前挂接，只缓存有界路径投影，确认 turn ID 后再精确归属；不等待语音生成器从 TTS 返回。来源更新在最终结果回执之前提交到当前任务，停止朗读、随后失去显示连接或最后一句合成失败均不能撤销工作已经完成的事实。结束后的晚到来源数据不改写终态任务。元数据显示失败不能挡住已排队的真正完成回执。

每项最多8条文件、每条路径最多512个UTF-8字节、序列化来源最多8 KiB；超出时减少条目并标记截短，不截断一个路径后把它变成另一个目标。内部最多保留32个文件工具项目和32条早到元数据，不缓存源 diff。命令或外部工具生成的文件不一定有 `fileChange` 回执，因此空列表不是“没有文件”，工具成功也不是文件内容已经独立验证。

点击“在 Mac 定位文件”后再次明确选择某一条，设备仅发送当前任务／保存记录 ID、文件序号和随机请求 ID。后台从自己持有的终态回执或严格校验的私有保存记录中找路径，不接受设备传入路径、URL或执行参数。只有成功写入的普通现存文件可通过固定 `/usr/bin/open -R` 参数数组交给 Finder 定位，不打开文件内容、不运行脚本；文件自身为符号链接、目录、不存在、已删除或原工具失败／拒绝时不定位。macOS正常的父目录别名可用；定位不是当前内容或原 inode 未变的证明。

定位前核对原已认证连接，断连或换线后不把旧页面操作重投到新连接；超时或回执丢失不自动重试。后台保留最近64个定位请求 ID 去重，进程重启后不回放。关闭等待不会撤销已提交的 Finder 请求。应用离开前台／线路变化会关闭等待，旧确认不能打开新页面。旧后台没有明确声明能力时不提供定位按钮。

保存格式提升为schema2，读取仍支持原schema1，读旧记录不自动改写。新字段只取后端回执，保留32条／512 KiB上限、原子写入、私有权限和显式查看／复制／删除规则；原记录未保存的结束时间、来源和文件不会补猜。恢复旧后台时schema2可能不可读，但旧服务必须保留原文件，不能清空或自动重建。普通任务不因增加来源而自动持久化，health／status／日志不得保存来源 ID、路径、答复或 diff。

2026-11-09再次只读核对当前CLI0.166.0：共享 `app-server proxy` 仍不能初始化，daemon version未找到可用管理实例，已确认只结束自有探测客户端；零历史读取、原聊天写入和模型回合。当前桌面聊天提供的任务管理工具不能据此视为独立语音服务已获得同一入口。官方 [App Server文档](https://learn.chatgpt.com/docs/app-server) 中的恢复／追加能力需要实际目标宿主支持；[CLI队列说明](https://learn.chatgpt.com/docs/cli/reference) 也明确排队和成功恢复不是同一件事。本批没有使用队列成功退出码冒充原聊天执行成功。
