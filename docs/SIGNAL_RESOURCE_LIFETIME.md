# 信号处理与启动资源归属

后台 0.15.53 候选补齐 P0-02 / P0-06 的一组关联边界。默认 MiniMax ASR/TTS + Dot、原签名 APK84、协议、角色和语音参数保持。

## 信号只登记意图

原来的停止与自检处理器直接操作 Provider / 传输。如果 Python 在持有 USBPipe 的不可重入写锁时执行处理器，再次取消 / 关闭就会等待同一把锁。会话和 Channel 的部分锁虽然可重入，底层写锁仍不能递归进入。

SIGTERM / SIGINT 现在只登记停止；SIGUSR1 只登记当时活跃录音的回答与录音代次，不获取资源锁、不调用 Event.set、不进行 I/O。主循环在通信栈返回后的边界消费意图。停止优先于挂起自检；取出事件后若发现停止，不继续派发该应用包。心跳也会检查停止意图。

自检真正执行前由 SessionController 在原会话锁内核对代次。停麦重开、换线或较新的请求已更换归属时，旧自检不取消新工作，也不启动诊断线程。它仍只允许已有的活跃录音，不能开麦。

这不强行抢占已经执行的系统调用；正常 USB / TLS 写入的既有截止时间继续生效。底层操作返回后再收尾，不宣称任意外部阻塞都能立即退出。

## 启动与主循环退出

传输启动、IPC 启动、主循环退出统一进入 finally。已构造的独立资源都尝试关闭，未构造的 IPC 不被假定存在；继续解绑会话和更新最终状态。清理也失败时，保留发起退出的主异常，次要错误只记录类型。正常停止的清理异常仍会传播，不冒充成功释放。

联查这一分支发现 IPC 的 close 原来无条件 unlink：启动因已有普通文件被拒绝后，清理会删掉该文件。现在只记录成功 bind 的设备 / inode，close 仅删除仍匹配的 socket；尚未绑定或已被替换的路径保留。该检查配合项目原运行锁和私有目录，并非对同一用户恶意并发替换路径的完整防御。

## RPC 管道由对应操作所有者关闭

- 守护进程确认退出后，stdin 的关闭与原有非阻塞 writer 锁串行；退出先标记断连，使背压中的 writer 结束，避免另一个线程在写入中释放描述符。
- 已启动的 stdout / stderr 读取线程负责在 EOF 后关闭自己的管道。stdout 必须先完成已经准入的回执；关闭请求不从外部线程强行关闭它，也不等待自己正在交付的回执。
- 尚未启动的 reader 没有管道所有者，由启动 / 关闭路径释放。三处线程启动或 initialize 失败会清理自有守护和管道，保留主错误，失败客户端不能再次启动。

close 的守护确认与回执线程的自然结束是两种证据。若一个已准入回调尚未返回，它的读管道可暂时保留；不将守护退出等同于任意回调已经完成，不取消或重放已执行的任务。

## 自动验证范围

25 项定向检查和 140 项关联调用检查通过，包含：

- 真实隔离进程在本地 USBPipe 写入持锁时向自身发送 SIGTERM、SIGINT、SIGUSR1；停止优先、退出后不派发取出的包，不启动挂起自检。
- 部分传输 / IPC 启动、异常主循环与次要清理错误；真实文件 / socket 的原路径保留和正常幂等关闭。
- 本地 stdio RPC 的三个 reader / 观察线程启动失败位置、背压写入中的关闭、不依赖 GC 的管道释放，以及阻塞一个已经准入的回执时保持读取管道，放行后交付回执并关闭。
- 未活跃录音、自检忙状态和过期代次不启动线程、不改变当前任务；有效的同代自检仍按原路径工作。
