# 运行版本与更新准备

候选 0.16.33／助手 0.9.123 code160 在“设置 → 版本与更新”提供只读运行信息。打开和复制不会开启麦克风、相机、模型请求或安装。沿用 32sp 标题、30sp 正文及 28sp 按钮；长内容由系统对话框滚动。

## 信息来源

| 信息 | 实际来源 | 限制 |
| --- | --- | --- |
| 助手版本、版本号与本机协议 | 当前运行 APK 的 BuildConfig | 不用后台期望版本补齐旧设备 |
| 本机签名证书 SHA-256 | PackageManager 本应用当前签名证书集合 | 是证书摘要，不是 APK 文件摘要；取得失败明确未知 |
| 后台版本与支持的设备协议范围 | 当前认证连接的 hello 发布声明 | 仅进程加载的公开清单，不读取磁盘私有配置或密钥 |
| 版本组合一致 | 实际助手版本和版本号与后台声明相等 | 不证明完整行为、签名连续性或安装验收 |

握手声明有 schema、类型、长度和数值范围检查，快照在排队前冻结，并绑定连接代次；断线、新连接尚未声明或旧版未支持时显示“未确认”。打开窗口期间每秒只在内容改变时更新；复制时重新读取当前状态，避免复制已经失效的后台声明。关闭、离开前台或进入黑屏后释放窗口和刷新任务。

## 语音查询

Dot 的 `cc8_control(action="status")` 使用当前设备返回的版本回执，后台只加入自身进程的公开版本声明；`device_release` 缺失或无效时为 null，组合／协议结论也为 null。客户端不能覆盖后台版本和校验标记。`installation_verified` 始终 false，避免把状态查询当作部署证明。失败的 status 以及音量、停播和亮屏请求沿用原语义。

## 更新与验证边界

本入口只说明当前状态。组合更新继续在 Mac 进行，复用既有原签名、配置快照、协议检查、系统安装完成回执、实际 APK 摘要及运行检查。不在设备里下载 APK，不执行 Root、刷机、数据清除或静默安装。

软件自动检查覆盖真实握手、状态控制器和原生回执、SDK27／28 签名分支、错误与旧版消息、声明快照、换线／代次／后台隔离、窗口刷新和复制。Android 编译／lint、受保护 CI、实际安装与独立维护审计分别记录；这些结果不能关闭整个 P1-09 或最终验收。
