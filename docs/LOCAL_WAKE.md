# P0-03：Mac 本地双唤醒词（0.13.0 候选）

大黄蜂 / Bumblebee 由 Mac 的专用流式 KWS 检测，位于云端 ASR 之前。MiniMax 仍做有界话语识别和播报，Dot 仍做大脑；没有更换用户选择的服务、音色或工具权限。当前运行安装没有因源码合入而更新。

## 等待、对话与停止

后台 0.14.84 已部署，把独立的“听一下”作为停止播报、继续聆听指令，支持开头带大黄蜂 / Bumblebee。它不交给 Dot；“听一下这首歌”等带实际内容的请求仍正常交办。播放参考中的同词引用仍需近端语音证据。此修正不改变本地关键词检测，也不代表已解决“停一下”识别成“听一下”的问题。

唤醒模式的状态为：开始语音并完成校准 → 等待唤醒 → 本地检测到名字 → 正在听 / 处理中 → 空闲窗口超时回到等待。窗口默认 60 秒，可用非敏感配置 `wake_window_seconds` 或 `CC8_WAKE_WINDOW_SECONDS` 设为整数 15～300 秒。收音中的话语、识别、任务、播报、暂停和显式取景都会延长窗口；不在工作中途超时。说“休息”仍可结束唤醒对话。

后台 0.14.99 将语音返回等待限制为独立的“休息”“休息一下”等中文指令，前面可加大黄蜂或 Bumblebee。“别休息”“休息？”和“提醒我十点休息”仍交给 Dot。自由对话模式继续把这些话当作普通请求。离线测试使用真实收音分包、断句和识别线程及受控识别结果，覆盖直接返回等待、疑问、否定、引用和提醒。实机复验验证了一次普通问答和一次明确休息指令。唤醒模型与 15 分钟黑屏计时沿用原配置。 [中文待机指令实测](CURRENT_DEPLOYMENT.md#01499-中文待机指令)

等待期间的声音只在现有本地有界 AEC / NS / VAD / KWS 路径处理。断句入口和识别 worker 都校验 awake；未经本地唤醒的话语不进 ASR 队列、不调用识别提供方。没有云端文本找名字的降级路径，缺少本地模型时启动明确失败。正常启动也不调用 ASR 做空白预热；旧识别器原本会丢弃该空白，这不是对历史上传行为的变更声明。显式 `--speech-smoke` 仍属于提供方测试。

保留原有句首缓冲，支持“名字＋问题”同一句；只在这次本地唤醒所属话语开头去掉识别出的名字。仅说名字不向 Dot 虚构“你好”请求；随后问“大黄蜂是什么车型”不会删除句中的主题。自播报和尾音参考含名字时拒绝对应回声风险触发，仍需真实房间负样本验证。

后台 0.14.42 候选按播放顺序保留两段参考文字之间的英文词边界。播报结束后的 3 秒内，即使收音侧没有对应的播放参考帧，参考文字仍含唤醒词时也会拦截候选。参考文字无唤醒词或已过期时，正常本地唤醒继续生效。隔离收音回归覆盖两段拼接、参考帧缺失和过期保护，现场声学与重叠人声另行验收。

无唤醒词模式启动后直接听取有效话语；应用内 15 分钟黑屏后，仍可用本地名字唤醒并亮屏。Home、手动停止及全部认证通道丢失仍停止采集；连接恢复不会自动重开麦。会话/通道代次使旧检测和排队帧失效。显式回声自检在等待唤醒时拒绝运行，需先唤醒或选无唤醒词模式；不伪造自检成功。

后台 0.14.48 让待机状态和屏幕事件与本地唤醒、触屏共用会话锁。待机采用与唤醒窗口相同的忙闲判断，语音正在成句、识别或回答已排队时延后黑屏。并发回归覆盖待机决定刚作出时接受英文唤醒，以及收音、识别队列和回答队列三种忙状态。15 分钟阈值与检测模型保持原值，实机待机仍须验证。

后台 0.14.49 在退出已唤醒状态或打开唤醒模式时，以 Mac 已收到的最后一帧设备时间标记新的等待窗口。缓冲旧帧仍经过回声处理。进入关键词流前及继续断句前复核帧的时间，覆盖等待切换发生在音频处理中途的情况。回归使用真实收音包和可控检测器，核对旧帧被拒、新帧可以唤醒。这一边界只识别已收到的音频，实机声学与模型召回率仍按原计划验收。

后台 0.14.51 将本地唤醒后 ASR 返回的单独名字和尾随标点判为只唤醒，例如 `Bumblebee.` 或「大黃蜂？」。此时保持聆听，不生成新对话任务。名字后的真实问题保留正负号和小数点。同一句仍由本地关键词先授权，普通对话不额外剥去名字。

后台 0.14.70 候选保留发送失败的亮屏事件。替代通道完成设备握手后补送，发送成功即清除；重复握手不重复亮屏。新一轮 15 分钟待机仍可覆盖较早的亮屏请求。仅恢复前台应用的显示状态，不打开麦克风或重新派发断线时的对话。

后台 0.14.71 候选在设备握手和原录音通道恢复后按实际状态提示。仍在等待本地唤醒时显示「等待唤醒」，已经唤醒的对话才显示「我在听」。自由对话模式进入 15 分钟黑屏后也沿用该规则。原录音、会话和播报中断提示保持原有归属。

后台 0.14.96 已部署。黑屏通知发送失败时保留屏幕更新，现有录音随替代通道恢复后，设备握手会补送一次。更晚的触屏或本地唤醒会以亮屏替换待发黑屏。停止录音或双路全断会清除待发黑屏，已等待发送的亮屏仍可恢复显示。回归覆盖连续两次写入失败、重复握手、触屏和停采。15 分钟阈值、线路协议和录音启动规则保持原值，换线瞬间的实体屏幕仍待验证。 [英文待机与亮屏对照](CURRENT_DEPLOYMENT.md#01496-英文待机单轮)

后台 0.14.73 候选在新播报段的开始通知写入成功并再次通过代次检查后保留上一段参考文字，并从该时点起算原有的 1 秒参考窗口。暂停等待不会提前消耗窗口，等待中取消或开始通知写入失败的段落不会覆盖原参考。三个隔离回归在旧版复现问题。用相同 PCM 对照的 12 个原生 AEC3 用例中，收音、校准和逻辑切换报告逐项一致。

## 模型、资源与锁

中文流使用 `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20` 的独立 stream，与既有停止检测共享模型和 native engine lock。关键词资源为 `d à h uáng f ēng @大黄蜂`。停止检测的 gain、threshold、trailing blanks 和线程数保持不变。

原双语模型对本轮英语合成音效果不足，英文改用独立的 `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01`，资源为 `▁BU M B LE B E E @Bumblebee`。两支均 CPU 单线程、score 1、threshold 0.25、trailing blanks 1、输入 gain 2 / clip ±0.98。英文使用 int8 encoder / joiner 与原 fp32 decoder；未新增运行 Python 包。SentencePiece 只在隔离开发环境核对一次 BPE，不是运行依赖。

后台 0.14.74 将英文解码的候选路径上限由 4 提到 8。中文唤醒和停止指令仍共用原检测器，得分、阈值和前处理保持原值。配对数字结果及实机验收范围见 [英文解码搜索范围配对](WAKE_RESEARCH.md#英文解码搜索范围配对2026-11-05)。

`./cc8 setup --profile voice` 仍通过原全局运行所有权检查，再按两个清单下载/核对精确长度与 SHA-256、拒绝路径穿越/链接后解包。`doctor` 对照两个固定归档逐文件核验已提取内容。权重、下载缓存、生成音频不进入 Git；已运行另一份后台时不要从第二个克隆准备或启动模型。

英文归档 17,626,723 字节，SHA-256 `f170013b4716e41b62b9bfd809687c207cef798ef9bc6534d524e17af9b6561a`。此 SHA 从官方 HTTPS 资产本机计算，上游旧资产 API 未提供 digest，清单明确记录来源；不是官方数字签名。中文固定清单沿用已核验的归档。

native 调用不进入 session 回调；reset 按 session guard → wake native lock → engine lock 顺序，feed 释放 native 锁后才重新核对代次。进入 native 前再检查 serial，防止已失效帧污染新 stream。两个受控并发回归覆盖重置发生在进入 native 前及解码中两个窗口。

## 软件验证与尚未完成的验收

本机全套：installer 16、host 402（4 项明确依赖私人音频跳过）、tooling 51、Java 15 checks；Ruff / Java formatting / strict mypy 六模块通过。新增 native 适配和动态控制模块尚未声称 strict 全覆盖。模型准备的离线回归覆盖固定缓存、两个归档、链接/穿越/错误根目录、下载大小与校验拒绝；测试不访问网络。

独立 eval venv 使用运行锁相同版本的 numpy 2.3.4 / sherpa-onnx 2.0.1。真实权重＋Mac 本地 say 合成音（无麦克风、无云请求、临时音频已删除）结果：5 条名字正样本命中、3 条普通问句负样本未命中，10 秒 seed 固定低电平噪声无命中。观察到加载 0.571 秒、进程峰值 RSS 108.0 MiB，10 秒噪声的两支 native 累计计算 0.2123 秒；这是一次开发机合成检查，不是持续 CPU、整条语音时延或 CC8 真人召回率承诺。

P0-03 保持未勾选。尚需真人两词、1/3 米、安静/电视背景和自播报负样本、4 小时误唤醒观察；P0-04 普通音量插话及 P0-05 真实黑屏/物理切换一起验收。未安装 APK、替换后台、启停服务或开启设备采集。

补充持续输入检查：隔离真实双模型处理 1800 秒 seed 固定合成噪声（挂钟约 40.6 秒），无触发，最后三个采样点 RSS 稳定约 88.5 MiB；见 [资源观察记录](RUNTIME_OBSERVATION.md)。这不替代真人/实际时长验收。

## 中文唤醒复核候选

后台 0.15.13 可在当前用户配置中显式设置 `chinese_wake_verifier` 为 `sensevoice`，默认 `off`。需要本机已校验的 SenseVoice 模型与无附加降噪的快速停止收音支路。后台就绪检查中的 `chinese_wake_verifier_ready` 表示复核是否实际可用。模型缺失或快速停止关闭时继续使用原本地唤醒。

主路命中后，仅在本地复核明确识别出近音词且没有识别出唤醒词时拒绝。无附加降噪的辅助路仅在复核明确识别出唤醒词且没有识别出近音词时补入。两路复核最多使用各自最近 1.8 秒的处理后收音，只在等待唤醒且有辅助输入时运行。确认唤醒、播放风险、收音断点、切换和停止时清空本地窗口。复核不发送云端请求，也不改变对话识别器设置。

开发机隔离模型进程的空闲常驻内存，关闭时约 104 MiB，启用时约 906 MiB。冻结对照的单次本地复核 p95 约 31 毫秒。两个数字分别来自隔离模型加载与离线识别，实机后台的运行开销、唤醒延迟和回声隔离仍待验证。

### 按收音会话加载复核模型

0.15.14 候选将可选模型移到独立子进程。开始收音时并行加载，校准流程不等待模型。关麦或换线时关闭通道并回收子进程。换线只在原收音通过回绑确认后为其加载新实例。就绪字段分别报告是否配置复核和子进程是否就绪。

通过匿名本机通道发送有界 PCM，只接收固定分类。单次往返最多 150 毫秒，模型加载失败、通信超时或回执无效时保留主路原判定，辅助路暂不放行。故障进程在当前收音中不会反复启动。该候选保持默认关闭，尚需实机验证收音期间的资源和换线行为。

用正式子进程入口和固定模型离线复跑 352 个条件，命中帧或未命中与 0.15.13 逐项一致。此轮从启动到模型就绪约 587 毫秒，停止后确认子进程已回收。另一轮在模型就绪后强制终止隔离父进程，子进程随通道关闭退出。两轮均未使用实机收音。
