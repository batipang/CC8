# 工作汇报的完整文本分页

候选后台0.16.22／助手0.9.93 code130。软件实现、CI、实体交付和完整P1验收分开记录；当前运行组合见[部署记录](CURRENT_DEPLOYMENT.md)。

## 问题与行为

合法的20条长答复，在控制消息同时携带结构化卡片和完整渲染文本时，实际编码会超过64KiB，导致看不到汇报。测试必须调用真正的 `Packet.encode()`，同时验证带线路nonce的编码；只创建Packet不能发现这个错误。

长文本按实际JSON转义后的约8000字节分为至多16页，页头明确标注当前页数，逐页正文连接必须与完整原文完全相同。当前范围汇报提供下一页、上一页及保存完整快照。历史快照可逐页查看、复制本页、复制完整快照和明确删除。旧界面的结构化预览保留所有结果标识及证据；消息过大时只缩短预览并明确提示从新页面查看完整文本。

服务器的完整汇报、语音固定编号、已播进度和保存正文都不因显示分页而截短。翻页只读取一个十分钟有效的内存副本，不重新查询聊天，不延长期限，不恢复被撤销的语音上下文。来源对象、登记成员、对话代次、连接、线路修订或语音上下文变化后旧引用失效；新一次读取即使失败也撤销旧显示快照。

## 完整复制与取消

完整复制是显式操作：固定历史记录ID、存储修订、当前线路和页数，按序取得所有页面，核对页号、页头和修订，最多16页、65536个UTF-16单元、两分钟。全部收齐后只写一次剪贴板，不包含分页提示。Home、换线路、新窗口、错误、修订变化或等待超时丢弃未完成文本，保留原剪贴板，不自动重试。普通单页复制保持原来的行为。

请求只能携带服务器快照ID及页号；历史翻页须同时携带当前存储修订。禁止客户端传入正文、任意聊天或文件路径，拒绝布尔页号、越界页号及混合缺字段。归档被删除或修订变化后拒绝旧翻页请求。
