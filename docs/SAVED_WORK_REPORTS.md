# 明确保存的工作汇报快照

后台0.16.19／助手0.9.87 code124的软件候选，尚未部署。它保存用户选中的汇报摘录和必要结果索引，不能代替实时查询、原聊天续办或完整P1-10验收。

## 保存和管理

1. 暂停语音，通过“设置 → 工作汇报来源 → 汇报选项 → 读取当前范围”查询一次汇报。在当前结果窗口点“保存快照”，阅读保留说明后明确确认。
2. Mac只保存这份实际已读快照的摘录、来源名称／项目／本机Codex聊天标识、时间范围、覆盖不足提示，以及原聊天／回合／结果ID和原完成时间。每份最多20个结果，最多16份，整个存储不超过256KiB。容量满时拒绝新保存，不自动淘汰旧记录。
3. 在“汇报选项 → 已保存汇报”按保存时间选择，可查看、明确复制到设备剪贴板、确认删除单份或确认清空。只读历史快照明确显示“非实时结果”；删除仅作用于本机保存的快照，不删除来源登记、原聊天或任务。已明确复制的剪贴板不随删除自动清除。
4. 保存至手动删除，目录0700、文件0600，私有`work-report-archive.json`采用原子保存及独立跨进程锁。不会保留完整聊天、录音、图片、原始工具输出或任意设备上传正文。正常汇报仍只在RAM中；关闭窗口、重连、服务启动不自动保存。

保存只接受当前服务器快照编号，不接受设备正文或路径。十分钟有效期、当前来源成员、连接／线路、代次及修订号均需匹配；停止／普通新对话等撤销编号上下文后不能从旧窗口保存。容量、损坏、并发冲突或耐久性未确认时刷新查看，不自动重试。同一快照不重复保存。损坏的存储保留，不覆盖，也不阻止读取一份新的实时汇报；此时不显示保存按钮。

## 历史与实时分开

重启后仅在明确打开时读取已保存记录，不恢复语音编号、已播账本、自动播报、登记范围或原任务。历史记录保留保存时的时间与覆盖提示，不能说明原任务当前状态或提供新的执行授权。来源登记与快照保留独立；删除登记不隐式删除用户另行确认保存的历史快照，管理快照时可单独删除或清空。

现有“上次汇报后”及真实设备播完账本仍是RAM状态。跨重启的已播进度恢复、原聊天执行、ChatGPT接入和可选通知继续开放，不由一份历史快照冒充这些功能。工具执行／文件变更计数与原答复摘录同样不等于独立验证结论。

## 自动验证范围

实际私有文件、真实跨实例文件锁／原子替换、保存后重建存储、删除、数量／字节容量、损坏／链接／权限和同步失败分别测试；实际控制器／协议验证明确确认、禁止设备正文、快照过期、来源删除、换线、修订与重复请求。编译后的原生对话框验证不可变确认、保存／删除／清空、复制、旧回调、能力协商、Home和换线。

这些检查不启用麦克风或相机，不调用模型。正式版本部署与真实来源覆盖分别留证；人工判断和最终72小时验收继续最后进行。
