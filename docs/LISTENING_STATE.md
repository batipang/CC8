# 明确区分等待唤醒和正在倾听

后台 **0.15.59／APK0.9.53（code90）已部署**。P0-03 要求明确展示等待唤醒、倾听和处理状态；原设备却把全部 listening 消息替换成同一固定标签，因此后台的“等待唤醒”文案没有实际显示。

后台只在 listening 状态包附加 `listening_state`：当前采集未唤醒为 `waiting`，已经唤醒为 `awake`，没有采集归属为 `unknown`。同时携带既有采集 ID／epoch；读取当前采集和发布状态共用会话锁，其余状态保留原有锁行为。新字段是可选附加字段，不更改协议版本、唤醒授权或音频准入。

设备先核对明确状态对应当前已确认的本地采集 ID／epoch，再通过现有前台、请求代次和状态准入转交 UI。旧线包不能绑定到后来新开的录音；错误类型、未确认启动和不匹配归属不消费当前状态。界面分别显示“等待唤醒 · 大黄蜂 / Bumblebee”和“正在倾听 · 可以直接说”，处理状态沿用原显示。文案不参与状态推断；旧后台缺字段或当前归属内的未知字符串使用原通用倾听标签，不假定已唤醒。

已准入的 UI 回执还绑定生命周期、线路、请求代次、原采集对象和 epoch，进入主线程后再次核对。停止、Home、新校准清空状态；即使后来已重新开麦，旧回调仍不能借用新的采集。相同请求内本地播报、暂停／恢复和可恢复错误暂时覆盖时保留已确认状态，新请求不继承上个请求的等待标签。非录音的播报错误仍正常显示。所有逻辑仅用于呈现，不能启动麦克风、重交请求或控制屏幕唤醒。

原生状态导出附加有限枚举 `listening_state` 和 `listening_state_visible`；后者只在前台、亮屏、listening、真实 TextView 可见且内容与该状态一致时成立，不用新计算值冒充已经渲染的文字。无新增正文、录音或持久化。

定向 31 项检查通过真实后台状态发布、会话锁线程交错和实际设备状态分支／Java 展示组件，覆盖等待、已唤醒、旧代次、缺字段、无效状态、播报覆盖、Stop／Home／新采集及迟到回调。完整 host 1633 项通过，4 项既有私人录音 opt-in 未启用；Android 编译／lint 和固定质量检查通过。
