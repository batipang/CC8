## 排序原则

- 工程质量：F-04 / F-05 / F-07 / F-19 的回归、规则、CI 与扫描基础已完成，F-20 边界测试随协议与并发改动前置。既有 P0 缺陷修复继续推进，功能变更必须通过同一套合入检查。
- 发布条件：F-01 / F-02 等按公开分发计划实施，不自动阻断当前个人使用的 P0 修复。
- P0：影响日常可用性，必须先形成稳定基线。优先本地唤醒、运行恢复、语音质量与连接可靠性。
- P1：让助手更能办事、更好管理。优先桌面 Dot 接续，再做结果留存、提醒、视觉、记忆等。
- P2：扩展场景。先有明确用途和输入条件，再实现工作流程、家居、会议或多人体验。

共保留 **20 项功能任务**（P0 6 / P1 9 / P2 5）和 **20 个工程条目**（F-01～F-20）。关联项共用实现与验收，编号数量不等于相互独立的开发工作量。未勾选表示仍有验收缺口；已完成条目附验证记录，“已有基础”不等于整项完成。下文数值是首轮建议验收门槛，须用基线测试校准，不能对外宣称为已达到的性能。

## 每次交付的代码质量要求

功能和工程质量在本清单一起排期。先完成受影响范围的质量基础，再合入新功能；纯文档修改只检查链接、内容完整性和差异，不为此运行设备、模型或音视频测试。

1. **明确问题再改代码**：记录复现条件、基线提交、受影响组件及预期行为。关联已有 P/F 编号；同一问题只维护一份实现与验收材料，不因两个编号重复开发。
2. **测试能复现问题**：缺陷先用针对性用例确认失败，再验证修复；功能覆盖取消、旧代、断线和错误路径。可选模型缺失可以有明确 skip，核心逻辑不得靠跳过或吞异常获得绿灯。报告通过、跳过、失败及跳过原因。
3. **检查真实启动环境**：涉及服务/工具调用时，同时验证交互 shell、精简 PATH 和实际登录服务；依赖可发现、本地初始化完成、远端模型请求成功分别记录。0.12.2 的 Node 路径故障作为固定回归案例，不能只凭“进程存活”判定 Dot 可用。
4. **保留已确认的行为**：已有模型/音色/头像、单次开场口号、配对和原签名保持；停止朗读不撤销已完成工作。后台、手动停止或两路全断后不能重连自开麦。维护检查不自动打开麦克风/相机，不自动重放有副作用的请求。
5. **按改动运行检查**：Python 静态检查及相关回归；Android 改动运行编译/lint；协议、状态机、权限和生命周期改动补边界测试。CI 建成后这些成为合入门槛；建立前保留本地结果，不能写成“CI 已通过”。
6. **让变更可审查和回退**：格式化、职责拆分与功能改动分开提交；关键注释解释时钟、锁、所有权、取消和信任边界。配置迁移失败不覆盖原文件，运行目录和仓库保持可核对的版本；私有备份、密钥和音视频不得入 Git。
7. **按证据关闭任务**：说明改动、测试、部署范围和限制。离线测试、模拟故障、真实设备验证分别记录；没有做过的物理切换、实际起声、登录/睡眠和长期观察不勾选完成。

## 固定评测矩阵与首轮门槛

以下为计划，不是已测成绩。统一记录软件版本、模型 / 音色、音量、距离、房间和网络；没有声级计时只标明场景，不能把 PCM dBFS 写成环境分贝。

CER 指中文字符错误率，WER 指英文词错误率；p50 为中位数，p95 表示 95% 的样本耗时不超过该值。一次指令里的地点、时间等关键字段需另外核对，不能只看文字整体相似度。

| 项目 | 样本与方法 | 建议首轮通过条件 |
| --- | --- | --- |
| 唤醒 | 两种词分别在 1 米 / 3 米、安静 / 电视背景各做至少 30 次；负样本含自播报、普通交谈、电视及近似词，共至少 4 小时 | 安静召回率每种词 1 米 ≥95%、3 米 ≥90%；误唤醒 ≤1 次 / 小时；电视背景先报告实测，不用安静成绩代替；这是小样本试用门槛，不能外推总体准确率 |
| ASR 与意图 | 至少 60 条固定真人指令，覆盖 5 类：普通问答、名字地点、时间数字、中英混说、停顿 / 轻声；在 1 米 / 3 米安静与电视背景分别执行。调参样本和验收样本分开 | 中文报告 CER、英文报告 WER、关键字段完全正确率；安静条件关键字段正确率 1 米 ≥95%、3 米 ≥90%；电视背景与较轻声不低于当前版本基线，未达时继续 P0-04，不凭合成样本宣布胜出 |
| 插话与误打断 | 至少 30 次普通音量新问题 / 停止指令；纯 TTS、电视、低噪声各观察至少 30 分钟；另测人声与 TTS 同时出现、两人同时交谈各 10 例 | 人声起点到实际暂停 p95 ≤500 ms；“停一下”说完到停播 p95 ≤1 s；误暂停 ≤1 次 / 30 分钟且能恢复；纯自播报测试 0 个自发新用户回合；多人冲突不拼接成虚假指令，听不清时澄清，不承诺自动分离两人语音 |
| 回答时延 | 每类至少 30 次：简单问答、联网查询、工具任务；记录句尾 → ASR、首个可播句、TTS 首包、实际出声 | 简单问答初始目标 p95 ≤5 s；联网 / 工具按阶段另报，不能混成一个平均数；超过目标给出瓶颈和实测，不先承诺外部服务上限 |
| 连接与待机 | 20 次物理 USB / Wi-Fi 往返；两路全断；3 轮真实 15 分钟应用内黑屏；72 小时运行；10 组服务重启 / 故障恢复 | 通道优先级正确，无重复副作用或旧代播报；全断后采集停止且重连不自启；待机唤醒恢复前台界面；无未处理崩溃 / 卡死，资源曲线无持续失控增长 |
| 任务真实性 | 成功、失败、审批拒绝、取消、结果已产生后停止朗读、断线恢复各至少 3 例 | 状态与真实执行结果一致；不误报成功，不将停止朗读写成撤销已完成操作 |

数据收集默认只保存非内容指标。真人录音或照片仅在用户明确同意该轮采集、用途与保存期限后留存于本机私有目录；没有原始样本时标明复现限制。所有评测结果记录样本数与失败案例，不只提供单个百分比。
