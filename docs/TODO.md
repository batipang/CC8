## 排序原则

- P0：影响日常可用性，必须先形成稳定基线。优先本地唤醒、运行恢复、语音质量与连接可靠性。
- P1：让助手更能办事、更好管理。优先桌面 Dot 接续，再做结果留存、提醒、视觉、记忆等。
- P2：扩展场景。先有明确用途和输入条件，再实现工作流程、家居、会议或多人体验。

共 20 项待办：P0 6 项、P1 9 项、P2 5 项。所有复选框均表示尚未完成；“已有基础”不等于整项完成。下文数值是首轮建议验收门槛，须用基线测试校准，不能对外宣称为已达到的性能。

## P0：稳定地听、说、运行

- [ ] **P0-01 — 建立语音与运行基线、诊断报告**
  - 进度：0.12.0 已提供有界、无内容的请求阶段追踪、Dot turn/generation 关联、分类统计与私有导出。固定真人样本和设备真实起声计时仍待完成。
  - 交付：复用现有计数和 last_asr / 大脑 / TTS 信息，串联本地 request / turn / generation，输出不含音视频正文的诊断报告；记录句首、句尾、暂停、识别、首个可播句、实际出声、任务结果与错误阶段。
  - 验收：区分“没收到声音 / 没识别 / Dot 等待 / TTS 失败 / 设备未播放”；按场景输出样本数、成功率和 p50 / p95；导出不含密钥、原始音视频或完整聊天。跨端时延按时钟偏移校正或单端回执计时，不直接相减不同设备时钟。
  - 依赖：无。范围：Mac 诊断与 CC8 必要时间戳。先完成下文语音 / 时延的基线轮次，再调整阈值；72 小时长期观察留到 P0-05，不要求在每次调参前重跑。

- [ ] **P0-02 — Mac 登录启动、崩溃恢复和健康状态**
  - 进度：0.12.0 已实现并启用当前用户 LaunchAgent、OS 单实例锁、退出退避、健康检查、轮转日志及明确停止。真实单次崩溃恢复与停止/启用通过；完整十组与睡眠/登录验收待继续。
  - 交付：当前用户级服务管理，登录启动、单实例锁、退出退避重试、日志轮转、版本 / 模型 / 连接就绪检查，以及明确停止入口；先启动后台，不自动拉起 CC8 或开麦。
  - 验收：10 组启动 / 重启 / 故障退出无重复服务；人为停止后不被守护立即拉起；睡眠恢复可重新连接并显示真实状态；整个恢复流程不重复交办任务、不自动重播有副作用的操作、不改变麦克风原有停止规则。
  - 依赖：P0-01。范围：Mac 服务与部署文档。系统睡眠不等于后台仍在工作，UI 需明确不可用时间。

- [ ] **P0-03 — 真正的本地“大黄蜂 / Bumblebee”唤醒**
  - 交付：先在 Mac 验证专用唤醒检测，放在云 ASR 之前；唤醒后进入有界对话窗口，结束 / 超时回到本地等待。保留无唤醒词模式、手动开始 / 停止及句首缓冲。明确展示“等待唤醒 / 正在听 / 处理中”。
  - 验收：唤醒前无云 ASR 请求；中文 / 英文两个词分别测召回率与误唤醒；自播报中的名字不自唤醒；离开前台、全部通道丢失或手动停止后停止采集；重连不自行开始。模型许可、两种词的支持和资源占用都有记录。
  - 依赖：P0-01；常驻体验依赖 P0-02。范围：Mac 首版，CC8 端部署只做可行性评估，不承诺硬件低功耗唤醒。MiniMax ASR / TTS 和 Dot 分工不变。

- [ ] **P0-04 — 降低听错、截句和误打断，保持普通音量插话**
  - 交付：依据固定样本调节 AEC / 近端语音 / 断句，不只提高音量门槛；明确区分暂时暂停、确认新请求和噪声后恢复；覆盖名字、地点、数字时间、中英混说、句中停顿。
  - 验收：按下文矩阵报告 ASR 与任务意图结果；正常音量说新问题可暂停并接续，噪声恢复原播报，纯播报不生成新的用户回合；声画暂停 / 恢复同步。延迟必须是实测端到端，不能用 VAD 窗口值代替。
  - 依赖：P0-01；唤醒相关部分接 P0-03。范围：Mac 音频 / 识别及 CC8 播放状态。保留当前可用版本做同样本 A/B 对照。

- [ ] **P0-05 — USB / Wi-Fi、15 分钟待机与长时间运行验收**
  - 交付：物理拔插与故障矩阵，覆盖听音、播报、Dot 执行、取景和黑屏待机；修复复现问题，保留 USB 优先与已配对 TLS Wi-Fi。
  - 验收：20 次物理往返切换，通道选择正确、无旧结果重播、无重复工具动作；全部通道丢失即停止采集，恢复后不自行开麦。完成 3 轮真实 15 分钟应用内黑屏及语音唤醒、72 小时运行观察；记录故障与内存 / 线程趋势。切换若中止播报，明确提示并允许继续，不冒充无缝播放。
  - 依赖：P0-01、P0-02；本地唤醒场景依赖 P0-03。范围：CC8 / Mac 联调。不改变“应用内黑屏仍在前台”的既有含义。

- [ ] **P0-06 — 超时、额度、权限和断网的明确反馈**
  - 交付：ASR、Dot、TTS、传输分别显示失败位置与可用操作；耗时任务持续显示真实状态；对可重试读请求有限重试，写入任务先核对结果。保留原模型选择，不静默更换服务。

  - 依赖：P0-01。范围：Mac 路由与 CC8 状态。基本错误文案已有，实现重点是分类、恢复入口和一致的任务回执。

## 固定评测矩阵与首轮门槛

以下为计划，不是已测成绩。统一记录软件版本、模型 / 音色、音量、距离、房间和网络；没有声级计时只标明场景，不能把 PCM dBFS 写成环境分贝。

CER 指中文字符错误率，WER 指英文词错误率；p50 为中位数，p95 表示 95% 的样本耗时不超过该值。一次指令里的地点、时间等关键字段需另外核对，不能只看文字整体相似度。

| 项目 | 样本与方法 | 建议首轮通过条件 |
| --- | --- | --- |
| 唤醒 | 两种词分别在 1 米 / 3 米、安静 / 电视背景各做至少 30 次；负样本含自播报、普通交谈、电视及近似词，共至少 4 小时 | 安静召回率每种词 1 米 ≥95%、3 米 ≥90%；误唤醒 ≤1 次 / 小时；电视背景先报告实测，不用安静成绩代替；这是小样本试用门槛，不能外推总体准确率 |
