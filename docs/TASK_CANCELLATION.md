# 停止等待与后台终端的归属

后台 0.15.55 候选补齐 P0-02 / P0-06 的执行中取消边界，保留原 APK84、MiniMax ASR / TTS、Dot 模型与既有权限。不能把取消模型回合当作撤销文件写入，也不能保证任意 MCP、远端服务或主动脱离管理的进程都已停止。

## 现场发现与范围

0.15.54 的固定执行中检查提交了两个独立的一次性测试任务，均只写本轮私有目录，最长 30 秒，未开麦或拍照。第一项因未压缩的 UI dump 仅返回包装提示而退出，尚未点击取消；改用已验证的压缩、有界管道后可以读取界面，不重交原任务。第二项在已知命令开始后执行一次固定 10 秒逻辑双线路断开：任务等待已取消，双线路恢复，但已知命令仍活过检查期限，最终到自身 30 秒上限才退出。两项均保留失败，未自动重试；后台故障与新任务两个后续场景未执行。

收尾只读复核确认两个已知命令均退出、没有额外请求或故障信号，原后台 0.15.54、APK、配置、LaunchAgent 与 owner Codex 配置保持，前台 USB 优先、Wi-Fi 就绪、双端关麦及摄像头关闭。逻辑双线路断开不计作物理拔插，整组没有通过。

## 候选行为

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#clean-background-terminals)区分 `turn/interrupt` 和后台终端列表 / 单项终止。本机导出的 experimental schema 也包含这些接口；现有客户端已声明 experimental API 能力，不升级 CLI、改变模型或放宽审批。

客户端在发起回合前监听 commandExecution 的 item ID，支持先到事件、后到 turn/start 确认；只保留有界的线程 / 回合 / item ID，不保存命令正文、工作路径或 OS PID。取消仍异步执行，先发原回合的 turn/interrupt，再有界分页读取该线程后台终端，仅向本回合已观察 item 对应的 processId 各发一次 terminate。不会调用全线程 clean，也不会触碰以前已完成任务故意启动的后台服务。未知、重复、超长或不完整的清单不触发终止；接口不支持、超时或失败时不重试工具动作。

中断线程固定使用原 RPC 与线程 ID，不能在延迟后误用后继连接。终端清理与新的 turn/start 准入串行；若旧回调已被新回合超越，只能中断其精确旧 turn，不再凭可能复用的句柄终止终端。正常已完成的回合保持结果，不因停止朗读而清理其后台服务。

任务页的取消阶段明确显示“已停止等待”，提示工具可能仍在运行、需在电脑核对结果，避免把“等待取消”当成所有工具都已停止。它不伪造撤销、成功或可安全重试的保证，也不自动重交任务。

## 软件证据与待补验证

原版 `95a233c` 在三种行为上有四处断言失败、零 loader / fixture error：未终止已观察的本回合终端、延迟中断改用后继 RPC，以及两种取消状态缺少“可能仍运行”的说明。候选增加 12 项检查，覆盖早到事件、旧回合隔离、完整分页、重复句柄、无效清单、超时零重试、预算耗尽、元数据上限、取消与新回合准入交错、迟到取消和已完成回合保护。

这些是离线接口与受控线程验证，不是候选的真实命令取消验收。旧版两次现场失败保持原结果；候选部署后需另定有界新用例验证，不重放旧任务。真实后台故障、任意工具树、系统登录 / 睡眠、物理线路和最终 72 小时验收分别保留。
