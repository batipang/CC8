# P0-04：固定语料与私有评分工具

本轮先提供可以复用的评测软件，不根据合成数据调整 AEC、VAD 或识别门槛。当前选择仍是 MiniMax 耳朵 / 嘴巴、Dot 大脑；没有更新运行助手或采集音频。

## 语料和轮次

[asr-corpus-v1.json](../cc8-assistant/host/resources/asr-corpus-v1.json) 包含 75 条通用公开指令：普通问答、名字地点、时间数字、中英混说、停顿/轻声五类各 15 条；每类前 3 条是 calibration，后 12 条是 acceptance，共 **15 条调参、60 条验收**。参考正文和预先声明的关键字段在该文件中；没有真实用户转录或录音。

每条分别在 quiet/tv × 1m/3m 执行，共 300 个记录位。真实音量、位置和电视背景由操作人员按 TODO 矩阵安排，工具不会测环境声级，也不会控制播放/收音。停顿/轻声类别在同一版本内固定读法，并在 A/B 两轮保持一致；当前语料不是已经完成的真人采样。

命令只读用户提供的转录和人工标注。默认不保存音频；若未来需要录音回放，须先明确该轮授权、用途与保留时间，使用已有私有音频流程，不能因为填模板而自动采集。

## 准备空模板

从要保存结果的代码目录执行。下例不覆盖已有文件；输入和输出文件都放 owner-private 目录，评分文件不入 Git。

```sh
mkdir -p device-access/private/asr-inputs
chmod 700 device-access/private/asr-inputs
./cc8 score-asr --template device-access/private/asr-inputs/baseline.json
```

模板元数据 `engine=unspecified / version=0.0.0 / source=unspecified` 尚未赋值，按实际填写，例如 minimax / 0.12.2 / human。source 仅是操作人员声明，不会被评分器认证为真人证据。每行默认 `outcome=unmeasured`、空 transcript/fields；未测项不进入成功率或 CER/WER 分母，报告保留 missing。

真人测试时照语料朗读，在 CC8 字幕核对后填写识别原文。不要把参考答案复制进 transcript；没听到/没识别要分别填 not_detected / failed 和空 transcript，属于已测失败，按全部参考单位删除计分。recognized 即使空串也不算未测。

一条已测记录示例（示例只说明格式，不是实际成绩）：

```json
{
  "id": "names_places-04",
  "condition": "quiet",
  "distance": "1m",
  "outcome": "recognized",
  "transcript": "杭州的西湖有哪些特点",
  "fields": {"place": "杭州", "landmark": "西湖"},
  "intent_correct": true
}
```

fields 是操作人员核对的**实际听到/解释成的字段值**，只能使用该条语料预先声明的字段名。不能靠“转录中包含苏州”就判苏州正确，例如“不是苏州，是徐州”应标徐州。允许的等价值在语料中事先固定，不在看到错字后临时扩充。缺标注不计作正确；intent_correct 是人工核对任务意图的布尔标注，不是模型推断，不会执行指令。

## 评分与配对比较

```sh
./cc8 score-asr --input device-access/private/asr-inputs/baseline.json
./cc8 score-asr --input device-access/private/asr-inputs/candidate.json \
  --baseline-input device-access/private/asr-inputs/baseline.json
```

默认在忽略的 device-access/private/asr-scores/ 新建 0600 报告；也可用 --output 指定已有私有目录内的新 JSON。不会覆盖输入、已有结果、符号链接或外部替换的报告。输入要求当前用户普通文件、无 group/other 权限；重复 JSON 键、NaN、未知键、重复样本/场景、非法标注或超界值失败且不打印输入内容。

报告不保留参考文本、识别原文、实际字段值或路径，只保留语料 ID、分组、计数和差值。calibration / acceptance 在场景和类别统计中均分开，quiet/tv、1m/3m 不互相冒充。A/B 必须有相同已测 ID/场景和同一 source 声明。两版均识别时仍要求相同人工标注覆盖；一版漏听或识别失败时，允许与另一版识别结果配对。同一语料规范化哈希写入结果以绑定版本。

- Chinese Han CER：对 NFKC 规范化后的汉字计算 S/D/I 和字符错误率；不把阿拉伯数字或英语字母混入中文分母。数字错误必须同时看关键字段和完整转录精确数。
- English WER：提取英文单词，统一大小写/NFKC，保留词内连字符和 ASCII 撇号，计算 S/D/I。英文词内的普通和不换行连字符按同一拼写评分，完整转录和关键字段也使用这一规则。数字符号及预设等价值仍分别核对。
- 关键字段：预设等价值比较，保留正负号、小数点、单位，空白/全半角/大小写可规范化；成功识别的样本需要标完全部预设字段才进入整条关键字段正确率。已测漏听或识别失败且有预设字段的样本进入分母，按整条错误计。报告分别列出人工标注和可计分样本数。
- 完整转录：规范化常规标点/空白，保留数值符号和数字间的小数点/冒号；单独报告精确相等条数。不能代替语义正确率。
- 意图正确率使用人工标注及已测漏听或识别失败；后两类按错误计。A/B 的关键字段与意图差值各自只使用两版都能计分的配对，并列出对应样本数；识别成功但缺人工标注时仍可比较文字指标。source、版本、距离和背景都是操作人员标签。零分母为 null；**没有“验收通过”自动结论**。指标可以超过 100% 错误率（插入很多内容），不截断美化。

输入最多 512 KiB、每条转录 1000 字符、75 条语料×4 场景且不可重复；动态规划累计最多 500 万单元，避免畸形输入耗时失控。CLI 使用标准库，不加载语音模型、不连接设备/网络。系统 Python 3.9 最小 PATH 已验证空模板→评分，300 项全为 missing，输出 0600；这只是工具验证。

## 无需朗读的 API 组件回归

用户要求自动测试后，新增 `verify-asr`，与上述只读评分器分开。它用 Mac 已安装且身份校验通过的 Tingting 音色生成公开语料，直接走当前 MiniMax ASR 的同一去直流、增益、补静音和上传路径，不播放声音、不读取麦克风、不操作 CC8，也不将指令交给 Dot 执行。

```sh
# 只看计划；系统 Python 可运行，不读凭据、不创建输出、不联网
./cc8 verify-asr --runtime-root /absolute/live/workspace
# 已有语音 Python 环境执行：默认15条调参；显式选择60条验收或全部75条
/absolute/voice/python cc8 verify-asr --runtime-root /absolute/live/workspace --execute
/absolute/voice/python cc8 verify-asr --runtime-root /absolute/live/workspace --execute --partition acceptance
# 对照已有的同分区 API 报告，全部 PCM 字节一致才开始识别
/absolute/voice/python cc8 verify-asr --runtime-root /absolute/live/workspace --execute --partition acceptance --reference-report /absolute/private/api-acceptance.json
```

执行需 macOS、已配置的 MiniMax ASR 和匹配的五个识别/配置/网络预算源码文件；不下载音色、不安装依赖或改变运行提供方。共享运行目录的自动化排他锁，避免与设备/故障测试重叠。上传的是公开合成单句，使用现有 API 配额；每条最多一次工具级调用，连续三条生成或请求失败即结束，支持 Ctrl+C 收尾。

执行源码目录的 `device-access/private/synthetic-asr/` 保存原子 0600 报告：固定样本 ID、分区、失败类别、CER/WER、完整转录规范化精确计数、音频/源码/语料摘要。临时 WAV 删除，不保存识别正文。合成耗时、识别耗时分别计时；`recognition_ms` 使用已评分请求的识别阶段 p50/p95（线性插值），不包含生成时间，也不是用户句尾到实际出声延迟。失败和缺测另列，不混入成功分母。

对照模式先读取已有的 0600 报告，校验语料摘要、分区、每个样本的身份与 PCM SHA-256，再把已经核对过的字节从内存直接送进识别。缺样本、缺摘要或音频变化均在构造识别提供方前退出 2，避免部分上传后才发现输入不同。新报告的 `reference_fixtures_verified` 记录这项校验是否执行。对照锁覆盖核对和 API 调用。PCM 摘要对应识别预处理前的数字输入，预处理源码或服务端配置变化仍可能影响结果。

completed/退出0仅代表选定样本全部完成测量；有错字仍可是 completed，不能解释为准确率达标。partial/退出2、cancelled/退出130均保留已测和剩余覆盖。默认计划退出0也不代表实际执行通过。即使类别名是 pause_soft，当前输入仍是正常合成读法，不冒充轻声/自然停顿；没有声学距离、电视、人声打断、关键字段或任务意图验收。

## 工具指令限定词与前导静音对照

2026-11-06（北京时间）用同一份固定工具题音频复测 0.14.94／APK code75。直送 MiniMax 保留“只读”，经 Mac 扬声器、CC8 麦克风和生产前端时再次遗漏。独立前台 QA 随后按 `VOICE_COMMUNICATION` → `VOICE_RECOGNITION` → `VOICE_RECOGNITION` → `VOICE_COMMUNICATION` 采样。现用录音源的两段样本绕过 Mac 前端后均完整识别。另一录音源的两段采样未通过本地波形核对，未送识别，无法比较准确率。

用现用录音源的实机采样做内存复放，复用运行版 AEC3 和断句源码。复放使用零播放参考，固定语音窗之外置零。两段采样的完整 AEC 输出都保留“只读”，其中一段在 AEC 后经断句再识别时遗漏，打开和关闭降噪均出现该现象。追加三段对照均覆盖合成语句首尾，其中两段的同一断句 PCM 重复请求得到不同结果。保留完整语句的较短窗口 6/6 次通过。仅对齐开头 3/3 次通过，仅对齐结尾 1/3 次通过。相同 PCM 经本机预处理产生相同的待上传 WAV。

冻结一个只删前导极低幅度样本的候选，保留至少 240 毫秒输入上下文和原 120 毫秒静音垫片，最多删除 320 毫秒。已有预处理增益、其余音频及句中停顿保持逐样本一致。60 条独立合成语料在加前后静音前先核对原始摘要，其中 12 条另加入弱起音和停顿。两组的逐条精确匹配结果相同（54/60，弱起音组 9/12）。候选的汉字错误从 3 增至 4，英文词错误从 13 降至 11。单独重复目标工具句时，原版 7/8、候选 8/8 保留“只读”。

实际收音复放的三段中，一段未通过本地波形核验。其余两段在断句后分别移除 110 毫秒与 120 毫秒开头静音。第一段原版 0/4、候选 4/4 保留“只读”，第二段原版 3/4、候选 0/4。候选未采用，生产录音源和处理参数未改。隔离 QA 未把指令交给 Dot，结束移除测试包并核对 USB 前台、麦克风及摄像头关闭。只保存无正文的数字与判定报告；仍需验证能稳定保留限定词的方案及真人样本。

## MiniMax 与本地 Whisper 同源对照

2026-11-06，0.15.8／code78 两条实机工具题分别使用第 1 题慢速和第 5 题原速。每条均将同一段生产前端送出的 PCM 交给 MiniMax 和本地 Whisper，两种识别器均与题库匹配。两轮在 Dot 派发前结束并确认双端停采。此前工具批次仍为 4/30，第 5 题因缺失“只读”被门控拦截。 [实机同段识别对照](CURRENT_DEPLOYMENT.md#0158-实机同段识别对照)

另以 60 条公开合成验收语料运行 0.15.8 的 MiniMax 路径及本地 Whisper。两次都完成 60 条测量，且识别预处理前的 PCM 摘要逐条与历史 MiniMax 基准一致。

| 路径 | 完整匹配 | 汉字错误率 | 英文词错误率 |
| --- | ---: | ---: | ---: |
| 历史 MiniMax 基准（0.14.3） | 54/60 | 8/496（1.61%） | 12/102（11.76%） |
| MiniMax（0.15.8） | 55/60 | 8/496（1.61%） | 10/102（9.80%） |
| 本地 Whisper | 37/60 | 57/496（11.49%） | 76/102（74.51%） |
| 本地 SenseVoice | 43/60 | 3/496（0.60%） | 39/102（38.24%） |

逐条比较本次 MiniMax 和本地 Whisper，两边都完全匹配 37 条，仅 MiniMax 完全匹配 18 条，两边均有差异 5 条。同一源 PCM 经各路径自己的识别预处理，云端识别结果可能随请求变化。合成对照没有经过扬声器或麦克风，真人准确率与限定词稳定性仍需单独验收。生产默认保留 MiniMax，本地路径供对照。两类报告均未保留转录或录音。

本地 SenseVoice 使用同一组逐条核对过摘要的 60 条源 PCM。与 0.15.8 MiniMax 比较，两边都完全匹配 42 条，仅 MiniMax 匹配 13 条，仅 SenseVoice 匹配 1 条，两边均有差异 4 条。另将 30 条固定工具题原速合成 PCM 直送 SenseVoice，30 条均完整匹配，其中第 5 题的合成源摘要与实机对照一致。数字输入未经过 CC8 收音，不能据此判断限定词在实机录音上的稳定性。
