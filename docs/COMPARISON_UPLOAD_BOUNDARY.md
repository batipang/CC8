# 固定 ASR 对照的识别前边界

后台0.15.69源码候选关联 P0-01／P0-04。仅改变显式 `tool_sample_compare_arm` 对照的识别准入，不改变普通对话、工具意图测量、模型、声音门槛、APK或通信协议。当前实际运行仍为后台0.15.67。

## 实机发现与范围

后台67上预先冻结的上下文英文计划有六项：原模式与临时增强模式各测一个近音负例、两个正确词短句。首项负例测量及清理完成；第二项原模式在一次公开合成短句后出现两次 ASR 尝试，超过原定上限，整批立即失败。增强模式与其余四项没有执行，不自动重跑，不修改旧报告。

第一段识别已被对照门拒绝，后段在收尾时取消，两段均无 Dot 派发。第二段没有播放参考重叠；没有保留原始收音，不能确定声源，也不能将其定性为纯噪声、自播报或识别截句。独立终审确认原两个APK、profile、LaunchAgent、owner配置保持，英文增强仍关闭，前台USB优先／Wi-Fi就绪，双端麦克风、相机、播放与校准关闭，模型子进程退出且暂停状态稳定。

代码检查发现一项独立边界问题：原对照门只在识别完成后拒绝已关闭的样本。即使原对照已结束，后来候选仍可能先进入 ASR。这个问题可以由实际收音、组合器与识别线程的离线回归复现，不依赖判断上述第二段的声源。

## 识别前核对与最终消费

- 只有显式对照有新的识别前检查；普通对话、用于真正执行工具题的测量和限定词诊断沿用原流程。
- 已绑定但未开始、已经关闭，以及收音、会话代次、USB重绑、local-wake或原20秒输入时间窗不匹配的对照，在调用提供方前记录 `tool_sample_guard` 及原有固定原因。仍保留本地候选与拒绝诊断。
- 识别前检查只读，不消费样本。有效首段仍经过原识别和最终转录门，最终门继续独占一次性消费；本地同段对照、取消、结果归属及工具零派发规则保持。
- 两个入口共用同一份收音上下文校验。所有状态仍由原 ToolSampleGate 持有，检查在原会话锁中进行，不创建新锁、线程、队列或采集。
- 自动比较仍将额外候选判为失败。减少后续 API 调用不代表收音更安静、唤醒更准或普通对话的误打断已经解决。

## 验证边界

新增实际 Bridge／组合器／RecognitionWorker 回归在旧源码四项测试中复现五处断言失败、零fixture错误；覆盖未开始、已关闭、错误收音归属、时间窗和线路。普通工具测量仍识别后核对，首段对照继续使用相同音频且不派发任务。自动设备检查另验证：第二个候选即使在 ASR 前被拒，也不能被统计成一次成功的单样本测量。

整批 host 1721项通过（4项既有私人录音 opt-in 未启用），工具158项通过，固定格式／静态检查、14个严格类型模块及既有Java格式通过。没有Android源码改动。受保护CI、部署及实体检查按各自实际结果记录；上述失败的英文批次不因软件修复改为通过。真人识别、自然噪声、远场／电视、实际换线及最终72小时仍分别验收，72小时继续最低优先级。
