# 连接不可用时间与观测范围

## Mac 端新鲜诊断与实际详情观测

后台 0.15.56／APK 0.9.51（code88）候选补齐显式导出：在**实际运行助手的工作区**使用该工作区的 Python 执行 `cc8-assistant/host/diagnose.py --connection`。命令只在 owner 私有目录保存 JSON，并返回路径。它通过既有认证 USB／Wi-Fi 请求一次只读状态，设备等待最多 3 秒，IPC 总读取期限仍为 5 秒；不打开界面、开麦、拍照、播放声音或重试模型任务。普通诊断与健康查询保持原行为。

`observation=device_reply` 表示收到且通过校验的设备回复；`missing_or_unsupported` 表示旧端缺少字段或字段不合法；`unavailable` 表示当前无法完成读取。后二者的 `connection_availability` 均为 null，不能当作当前连接正常，也不复用此前成功结果。记录只含固定状态和设备本地毫秒／计数，不转发设备说明文本、未知扩展、网络地址或凭据，不用 Mac 时钟减 CC8 时钟。它是一次取样，不宣称取样后的线路一直可用。

既有 `CC8_ASSISTANT_UI` 增加 `connection_dialog`：只在前台详情真正可见时，读取实际 TextView，核对它与最近一次已设置的消息一致，再给出那一帧对应的固定可用状态；不是重新算出一个未显示的时间。关闭详情、旧详情迟到回调或退到后台不会产生虚假的可见回执。此字段供设备旁的自动读取使用；`--connection` 的状态取样不冒充屏幕渲染证明。

code87 已保留给 APK86 的恢复准备，本批使用 code88，避免覆盖已准备的版本。实机与受保护 CI 结果分别留证；候选实现不代替验收。

本批新增 11 项检查，26 项定向检查通过；完整 installer24、host1567（4 项既有私人录音 opt-in skip）、tooling144、Java76，以及 375 文件固定格式／14 模块 strict、Android 编译／Lint 通过。回归包含未知旧端、无效计数、说明文本过滤、真实 owner IPC、额外动作拒绝、三秒超时无重发、实际 Java 状态回复与详情 TextView 归属；这些离线结果不代替实体显示或 Mac 登录／睡眠验证。

## APK86 的部署与实机边界

APK 0.9.49／code86 已按原签名部署到源码 `8f99bf7`，后台为 0.15.55，维护九步和独立复核通过。就绪 Wi-Fi 下的 USB 逻辑切换未创建中断；一次全线路固定短断后，恢复回执和详情显示约 10 秒。该轮动态详情的自动读取断言失败，原先两次读取的文本及时间未保存，**实时刷新实机证明仍缺失**，不将后续恢复显示改记为原测试通过。

Android AOSP 的 [DumpCommand 源码](https://android.googlesource.com/platform/frameworks/testing/+/master/uiautomator/cmds/uiautomator/src/com/android/commands/uiautomator/DumpCommand.java) 会等待 1 秒无障碍事件空闲，最多等待 10 秒。动态更新可能让读取跨出固定断线窗口，这是待验证的读取假设；未核对厂商实现，不能认定为实机根因。关闭已知详情后，单独执行原批次尚未执行的后台场景：Home 停止观测、重开先等待、恢复后不虚增已恢复区间，15.780 秒通过。三种故障各执行一次，无物理拔线、模型调用或音视频采集，独立终审确认原配置、安装包和关麦状态保持。完整摘要见 [当前部署](CURRENT_DEPLOYMENT.md#0949code86-连接观测与部分实机检查)。

## APK86 的基础实现

APK 0.9.49／code86 候选补齐 P0-02 的连接可用时间显示，后台仍为 0.15.55，协议仍为 2。点击顶部 USB／Wi-Fi／未连接标签打开原有“连接状态”：显示首次等待、当前中断时长和最近一次已恢复的中断，每秒更新；关闭详情或离开前台后停止更新。不调整头像、光环、字幕、声音、唤醒和录音启停规则。

## 计时含义

- 首次进入前台尚未建立连接，显示“尚未连上 Mac”，不计作一次故障。
- 已确认连接后失去全部可用线路，才开始记录观测到的不可用区间；重复丢失回调不重置起点。
- USB 与已就绪的 Wi-Fi 之间成功切换不创建断线区间；过期连接回调不改变新线路状态。激活发送失败也不能宣称连接已恢复。
- 重新确认线路后保存本次中断时长及恢复计数，不再继续累计该区间。关闭前台时仍未恢复的区间单列为观测中断，不能用下一次打开应用的时间补成已确认恢复。
- 使用 CC8 的 elapsedRealtime，同一设备时基包含设备睡眠时间；系统日期调整不改变区间。时长从设备确认丢失连接时算起，不代表故障真正发生的时刻，也不是 Mac 精确休眠时长。

仅凭线路断开不能区分 Mac 睡眠、服务退出、网络或线缆问题。详情明确说明助手在这些情况下可能不可用；连接就绪也不等于模型调用成功。记录仅存本次 Activity 的内存，退回桌面期间不观测，重建界面后重新开始，不持久保存在线历史。

## 无内容状态

助手原有只读 `CC8_ASSISTANT_STATUS` 导出增加 `connection_availability`，包含版本、固定状态／说明、首次等待毫秒、当前中断毫秒、最近一次已恢复时长、恢复次数与累计已恢复时长、观测中断次数。尚无已恢复区间时 `last_recovered_ms` 为 -1。累计值只包含已确认恢复的区间，不混入首次等待、后台时间或未确认区间。

不记录绝对日期、设备 ID、网络地址、SSID、聊天、命令、音视频、配对或凭据。它是设备侧状态，不冒充 Mac `diagnose.py` 已有导出中的新增字段。查询与显示只读取状态，不启动网络、麦克风、摄像头或模型任务。
