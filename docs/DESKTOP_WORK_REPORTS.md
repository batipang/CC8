# 所选桌面聊天的只读工作汇报

已部署后台 0.16.2／助手 0.9.55（code92），更新与既有6项隔离实机界面检查见[当前部署](CURRENT_DEPLOYMENT.md)。明确起止时间／未播账本已部署，APK不变。本批推进 P1-01／P1-02／P1-10 的只读结果入口，不关闭这些任务的完整验收，也不接管原聊天的执行。

在「设置 → Dot 聊天接续」明确选择来源后，可打开「工作汇报」，选择过去半小时、过去两小时或今天。今天按北京时间零点开始，时间窗口含起点、不含终点。只有新后台明确返回能力时才显示入口，修改来源沿用原空闲和取消规则，不开启麦克风。

后台先调用 `thread/turns/list` 的 `itemsView=notLoaded`，最多四页、每页25轮，只读取所选聊天的状态和时间。按真实 `completedAt` 过滤完成回合，再通过带 `turnId` 的 `thread/items/list` 读取最多20个结果，每轮最多两页、每页50个 item。请求总期限30秒，逐请求检查取消和原连接／代次；任何分支关闭自己的只读 RPC。它不调用 `thread/resume`、`turn/start` 或原聊天写接口，不根据独立客户端的 notLoaded 状态判断桌面空闲。

时间字段依据本机 Codex CLI 0.166.0 实际生成的协议 schema：Turn.completedAt 为 Unix 秒，item 完成时间另以毫秒记录，不混减单位。公开接口说明见 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server#list-thread-turns)。文档中的 thread.updatedAt 更新并不等于工作完成；时间缺失时只标记缺口，不用更新时间、开始时间、文件时间或 UUID 推测。

结果为当前只读快照：只展示明确 final_answer 的原答复摘录，每条最多500字符，并标记截短。推理、commentary、partial_answer、用户正文、终端输出和文件 diff 不作为汇报正文。终端成功仅计状态 completed 且整数退出码为零的实际回执；非零退出、失败或拒绝分别计入失败，缺退出结果的 item 标为待确认。文件变更回执单独计数，不把事件数写成文件数。

单来源汇报的屏幕页首显示本机 Codex 聊天标识，每项显示回合与结果标识；单独查看编号详情或执行回执时同屏显示三个标识。多来源汇报按每项的实际来源标注。新增标识不进入语音播报。原答复仍是引用内容，回合完成和工具成功都不等于整项任务已验证。失败、中断、读到仍进行中的回合单列；进行中计数是读取时见到的状态，不冒充窗口内已完成成果。

多来源汇报的覆盖区按来源显示读到仍进行中的回合，以及所选时间窗口内失败和中断的数量。部分读取只统计实际取得的页面，同时标出覆盖不完整。未读取的来源显示原因和状态，数量留空。可以追问“这次汇报里还有哪些项目在进行中”，直接读取当前快照中的来源和数量，不再查聊天，也不把该播报计为成果已播。工作汇报原有编号仍对应已完成答复。

在 CC8 的任务页明确保存“待桌面接续”回执后，可在 Mac 终端用 `./cc8 saved-handoff list --runtime-root /absolute/runtime-workspace` 找到保存编号，再用 `./cc8 saved-handoff show <保存编号> --runtime-root /absolute/runtime-workspace` 查看原聊天、回合和当次草稿。需要 Python 3.11 或更新版本。列表只显示保存编号、来源标题和保存时间，草稿只在明确查看该条记录时输出。核对草稿后可手动粘贴到原桌面聊天。若当时没有指定下一步，草稿字段为空。命令读取现有保存记录，不启动助手、写入原聊天或建立新的持久记录。

对已登记来源的当前汇报，可说“查看这次汇报的第二项待办队列”。后台按编号绑定原聊天，只查这一条来源的当前队列。只显示和播报条数及读取覆盖状态，正文和附件不会进入回答。屏幕标明读取时间和原聊天，部分读取报告至少读到的条数，读取失败则标为未确认。查看队列不启动原任务，也不改变汇报的已播进度。

页面未读完、结果超过20项、缺完成时间、缺最终答复或回执不完整时，显示覆盖不足，不能宣布没有其他成果。分页不能因为开始时间早于窗口而提前停止，跨窗口开始、窗口内完成的工作仍须参与过滤。报告默认保留内存，不保存到status、配置或日志，不自动后台播报，不启动大脑模型回合或自动重交任务。显式语音汇报沿用现有MiniMax TTS，播报部分文字会交给该已配置的语音服务；结果卡不会自动成为后续模型对话的历史。已读结果进入原有内存任务回执，显式保存结果仍沿用P1-02入口和权限。

读取后续页或结果时，Codex 连接超时或断开会保留此前已确认的结果，标记覆盖不足。如果同一回合已经取得最终答复但后续回执页未读到，该条也会注明回执不完整。CC8 换线、取消或归属变化仍会撤销本次结果。数据归属错误和分页数据冲突会拒绝本次读取。

开麦且通过原唤醒／识别门控后，可说“汇报过去半小时的工作”“汇报过去两小时的工作”“汇报今天的工作”；文字入口也支持。兼容识别成“过去2小时”“过去30分钟”的写法。默认口播最多前三项，每项最多80字并标注截短；全部已读结果卡在“设置 → 最近 Dot 完整结果”。完成、失败、中断、覆盖不足和未独立核验分别说明，不把读取完成写成源任务已经验证。

可说“详细说说第二项”或“查看汇报的第2项详情”。编号绑定该次报告的深拷贝，不重新扫描、插入或重排；UI报告和语音报告共用本地快照。快照在服务内存中最多保留一份，十分钟后再次查询时失效；换来源、线路修订、普通对话或服务关闭也会清除或使其不可用。汇报读取完成后的停止朗读保留已读结果；读取未完成就取消／断线时丢弃晚到结果。缺来源／编号越界／不支持时间会澄清，不调用大脑猜测。汇报后的“继续第二项”在任务列表和结果卡显示「待桌面接续」、原聊天和回合，便于在桌面定位并手动提交下一步。目标不明或涉及多项时要求明确一个编号。编号失效后需重新汇报。显式保存接续指引后，重启仍可从已保存结果查看「待桌面接续」和原回合。此入口不写入原聊天，也不创建独立聊天执行。

可以单独问“第二项是否通过了测试”或“查看汇报的第2项执行回执”。只读本次快照中的终端、文件和待确认回执，并标明覆盖不足。能明确识别的直接 `pytest` 或 `python -m unittest` 命令会报告退出码为零、非零或未确认的次数。复合 Shell 命令、测试收集或帮助参数不纳入。退出结果不证明测试范围或整体验收。此字段只在本次或内存补播快照可用，旧检查点恢复后重新读取才能补齐。命令和终端输出不进入汇报。只听回执不会把摘要标为已播。

CC8 自己的 `python tools/test_all.py` 和 `python -m tools.test_all` 也可提供进程退出回执，支持直接运行全部套件或用 `--suite` 选择套件。每次调用计一个进程，即使同时运行多组测试。

语音和文字请求也可说“汇报昨天的工作”或“上周完成了哪些工作”。昨天按北京时间前一个自然日计算，上周按上个周一零点至本周一零点计算。两者均含起点、不含终点，查询期间固定。所选聊天与登记来源的设备菜单在后台确认支持后也会提供这两个选项。

可说“继续第二项，下一步：检查 Android CI 的退出码”。结果卡保留识别到的下一步原文，并附原聊天和回合，供核对后在桌面提交。大黄蜂只播报接续提示，草稿正文仅在屏幕显示，随接续结果显式保存时才持久化。若同一句涉及多个汇报编号，请重说单一目标。

在「Dot 聊天接续」打开的汇报只读取当前摘要聊天。已登记多来源范围仍用于其自己的菜单和语音汇报。查看范围之外的单聊预览不会替换已有的语音编号、分页或补播进度。

仅从上次汇报保留、当次未重新读取的补播条目仍可查看详情和回执。续办前须重新读取其原来源，再使用新汇报的编号。当前已读结果的接续卡显示原聊天、回合和结果标识。

0.16.18／code122 软件候选补充[明确登记的多来源汇报](REGISTERED_WORK_REPORTS.md)：单来源入口保留，也可明确登记元数据并切换汇报范围。原聊天续办、持久化成果索引、ChatGPT 接入和通知仍按 [统一 TODO](TODO.md#执行阶段与下一批工作) 推进；当前只读入口与本批自动验证不等待最终人工 P0 验收。


0.16.2支持“汇报今天上午八点到上午十点的工作”“汇报昨天23:00到今天01:00的工作”，也支持完整年月日与24小时制时刻。相对日期由一次冻结的北京时间解析；起点包含、终点不含，最多31天，终点不能在未来。缺起始日期／年份、没有说明上午下午的中文钟点、倒序或不合法日期会要求补全，不隐式跨日，不调用模型推测。设备原页面仍提供三个固定时间按钮，自定义范围走已授权语音／文字入口，没有扩展网络指令字段。

先成功查询一个明确范围后，可说“汇报上次汇报后的工作”。后台从上次范围的起点重新读取到现在，按结果标识和内容版本去重，避免只从上次截止开始而漏掉迟到收集的旧完成结果。默认摘要确认播完的条目跳过；上次没有播、没有确认播完或内容更新的条目保留。结果卡明确区分迟到、新增、待补播、更新及仅引用旧快照；旧待播结果本次未重新读到时仍保留，覆盖标为不完整。“没有新增或待补播”不等于来源没有完成工作。原来源读取预算和覆盖限制保持。

播报账本与来源工作完成分开：只按同一代次、当前播放计划的真实设备播完回执确认，每次口播返回成功、音频发完或界面显示结果都不算。概览最多前三条80字摘要，只有各自摘要及补播说明播完才确认；编号详情则须整组详情和核验说明播完。停止保留尚未确认条目，已经完成的读取任务不被改成取消。旧计划／旧版本／换来源的回执不能确认新结果。

账本只保留当前明确来源、当前基线，最多256条在内存中；不写status、配置或日志。普通话题清除编号快照，保留同来源的播报账本；同来源重新认证连接可继续查询，但旧编号沿用十分钟和线路变化失效规则。更换／清除来源、服务关闭／重启会清除账本；再次成功明确查询固定或自定义范围会重建基线。无基线、系统时钟倒退、原范围超过31天或容量达到上限时明确提示，不静默丢弃或自动推进截止时间。失败／取消的读取不改变原账本。以上是只读阶段的内存补播能力，不代表定时通知、持久化成果索引、原任务续办或完整P1-10已验收。
