# 明确登记的多个聊天工作汇报

后台 0.16.18／助手 0.9.85 code122 的软件候选。原“摘要接续”与新“汇报范围”彼此独立：登记或选择多个汇报来源不会把这些聊天的历史交给独立 Dot 大脑，也不会向原聊天发请求。完整 P1-10 保持开放。

## 使用

1. 暂停语音，在“设置 → 工作汇报来源”选择“添加来源”。这里只读本机 Codex 聊天的名称和项目简称，不读取历史正文。来源须来自刚刚列出的候选，五分钟后需要重新列出。
2. 核对来源并点“确认登记”。最多八个；只将提供方、本机范围、名称、项目简称、聊天标识与登记时间保存在 Mac 的私有 `work-report-sources.json`，目录0700、文件0600。没有原始聊天、录音、图片或结果正文。保留至手动删除，可点来源删除或在选项中清空；不删除原聊天。
3. 在“汇报选项”明确选择“使用全部登记来源”，再读取当前范围的过去半小时、两小时或今天。也可切回当前摘要聊天。服务重启不自动启用登记范围、不扫描来源、不自动汇报。
4. 已选定登记范围时，原“汇报今天的工作”、明确起止范围、“汇报上次汇报后的工作”和编号详情语音也使用这个固定范围。每个结果显示实际来源名称、项目、聊天／回合／结果标识，默认只口播前三项。所选范围不是一个虚构的原聊天；编号详情按实际原聊天生成来源信息。

登记本身不改变正在使用的范围。新增来源或删除范围外来源保留原范围和未播账本；需要明确再次“使用全部登记来源”才把新登记纳入。删除当前范围内的来源或明确切换范围会撤销该范围的内存编号／待播账本，确认页会说明；原工作不会撤销。选择同一未变化范围不会清空已读或待播状态。

## 读取与覆盖

所有来源使用同一个冻结的北京时间区间，含起点、不含终点；仍按真实回合完成时间筛选，保留既有分页、证据和正文过滤规则。一次总期限45秒，每个来源最多分配12秒（已开始的初始化有自身超时）；耗尽后不再启动新的来源客户端。总结果卡最多20项，按完成时间与稳定来源／结果标识排序；达到读取或卡片上限时标明覆盖不足。

不可读取、未在总期限内读取和已读但分页不全分别显示。无法读取不等于零成果，所有来源均无法读取时也不能宣称没有成果。读取之间检查原请求、连接、代次和登记成员的有效性；删除成员后不再读下一页／下一个来源。只关闭本次拥有的短命只读客户端。

跨聊天的相同回合／结果编号不会合并。上次未确认播完的结果继续留在原有内存账本；来源本次读取失败时，明确标成“引用上次快照，当前未重新核验”，不会当作新的已核实成果。只有当前播放计划的真实设备播完确认才记为已播；停止播报不取消原工作。结果正文、编号快照和播报账本仍不落盘。

原生列表、确认、范围与结果窗口绑定请求号、线路、窗口代次和不可变来源副本。旧回包、旧确认、Home、换线及旧超时不能更改新窗口或提交新请求。修改回执未确认时重新查看，不自动重试；保存后的目录同步失败保留“耐久性未确认”，不重复登记。

## 接入边界与验收

目前接入本机 Codex 的只读 `thread/list`、`thread/turns/list` 和 `thread/items/list`。官方[App Server 文档](https://learn.chatgpt.com/docs/app-server)区分只读历史和恢复后执行；接口存在不证明独立客户端能安全接管当前桌面。2026-11-10 以本机 CLI 0.166.0 再次只尝试共享代理初始化，仍不可用，未读取聊天或启动模型回合。因此原聊天续办、桌面专有工具范围、ChatGPT、持久化成果索引和可选通知继续开放。

自动验证使用临时私有目录、真实文件锁／原子保存、实际控制器／只读读取器／播报账本及编译后的实际原生对话框。保持取消、来源归属、部分覆盖、命名空间和旧回调负向检查；不为界面检查启动摄像头或麦克风。部署、真实来源覆盖与最终人体验收分别记账，72小时冻结版本验收最后进行。
