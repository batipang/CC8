# 播放头驱动的轻量口型

候选后台0.16.28／助手0.9.101 code138。当前实际部署仍是0.16.27／code136，见[部署记录](CURRENT_DEPLOYMENT.md)。本批是P2-05的软件改进，未关闭其完整验收。

嘴部继续叠加在原有透明头像的口部区域，原图、眼睑表情、光环时钟、独立声波、三行字幕和能量舱位置不变。闭口时直接显示原图。没有新增位图帧、定时器、工作线程或音频／网络权限。

播放器只分析AudioTrack实际接受的PCM。原有每个包络增加一个0～1的轻量信号变化值，与RMS来自同一段采样；不保留额外PCM或更改发送给Mac的回声参考。界面只取实际播放头当前所在的包络，排队但尚未发声的数据和预热静音不能提前张口。

`SpeechMotion`在UI线程中复用一个小状态对象，按实际已播毫秒平滑张口和内口宽度，幅度和形变有界；播放头不动时，界面刷新不能继续推进。每次本地播放分配一个不含内容的身份标记，重连后服务器编号重复也不沿用旧姿态；标记不引用播放器、PCM或Activity。播放头回退时先闭口，恢复到原水位后才继续。暂停、取消、断线后空帧、Home和真实静音不保留渐隐尾巴，当前界面帧即收口。字幕继续使用原有时间轴，播放完成和停止回执不变。

它是基于能量包络和信号变化的近似动画，信号变化值不是音素、元音或说话人分类。MiniMax现有调用没有提供足以验证音素对齐的可靠数据，本批不编造逐音素嘴型，也不改换当前音色。

离线验证使用真实Java姿态类、真实Player／SpeakerOwner／NativeSpeaker代码与受控输出适配：覆盖短写采样、预热区、同一播放头的包络／形变、暂停冻结、恢复、取消、换句、非法值、时钟回退、UI重复刷新及固定种子的长序列边界。测试不会打开生产设备麦克风、摄像头或云端模型。常规Android构建／lint和受保护CI随批次进行。

低CPU的设计依据是一遍有界的采样遍历、每帧几个标量运算、复用位图和Path；这些源码约束不等于已测得CC8的帧耗时、发热或主观自然度。暂停／恢复／换句／取消的一致性优先自动核对，真实设备视觉与语音体验留最终集中验收，不自动启动录音或72小时观察。
