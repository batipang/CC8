# 大黄蜂：第二轮竞品复盘

研究日期：2026-11-01（北京时间）。项目基线：Android 0.8.6 / Mac 后台 0.11.0，源码提交 d75da8f。

本轮面向当前这台 CC8、当前 Mac 和单人家庭 / 桌面使用场景，回答“接下来先做什么”。依据上一版 P0 / P1 / P2 列表、仓库代码、已有实机记录及官方资料；没有重新做设备测试。可执行清单与验收条件见 [TODO](TODO.md)，总体状态见 [ROADMAP](ROADMAP.md)。

## 结论

继续保持 **CC8 作为语音与视觉终端、Mac 处理音频和运行服务、Dot 执行任务、MiniMax 识别与播报**。当前最有价值的下一步是把已经跑通的能力做成稳定的日常工具，再打通桌面任务接续。

本轮优先级调整：

1. P0 从“补基本功能”转为“本地唤醒、可恢复运行、可量化的语音与连接质量”。先建立基线，再调参数，避免在误打断和听不清之间反复摇摆。
2. P1 首项是桌面 Dot 聊天接续；随后补任务结果留存、提醒送达、高清看图和可管理记忆。
3. P2 保留工作流程、家居、会议、多用户和角色增强；现阶段不扩大成连续摄像监控或通用家庭生态。
4. 头像、抽象时钟、三行卡拉 OK 字幕、方案二能量舱已完成，进入维护，不再占据新一轮 P0。

以上是针对本项目的判断，不是竞品市场份额或准确率排名。

## 从竞品得到的产品判断

### 1. 先解决可用性，再扩充能力

本项目已经遇到过自说自话、普通音量难打断、识别错误、应用不在前台、断线后状态不清等问题；后续用户反馈确认部分问题已改善。它们仍需要持续、可复现的验收，不能以一次成功体验替代质量结论。Google 的更新记录也表明这些基础体验值得长期投入，但不能据此估算我们的故障率。

应记录“何时听到人声 → 何时暂停 → 识别结果 → Dot 首个可播句 → 真实开始出声”的完整时间线。已有状态计数和分阶段信息可复用，新增的是汇总、诊断与稳定的评测方法，不是重建一套日志。

### 2. 本地唤醒与本地识别分开决策

本地唤醒只决定何时开始接受一轮请求，不要求把已选定的 MiniMax ASR 换掉。第一阶段在 Mac 上验证“大黄蜂 / Bumblebee”，利用现有音频前处理，唤醒前不调用云端 ASR；随后才评估是否值得下放到 CC8。

HA 的 Android 实现提供设计参考，不证明其现成模型支持中文自定义词或兼容 CC8 的 Android 8.1。需要单独验证模型授权、两种唤醒词、误触发率和资源开销。Mac 上运行的唤醒也仍依赖 Mac 与本地连接，不能标成 CC8 离线独立助手。

### 3. 桌面接续应成为主要增量

用户已经明确要求 Dot 与当前 GuGua 能力一致。更有用的体验是“继续刚才电脑上的任务”“这个结果发回对应聊天”“现在做到了哪一步”，而不是再增加一个独立问答入口。

App Server 官方协议提供线程创建 / 恢复、任务事件和审批交互，但协议能力本身不能证明当前桌面宿主的所有聊天与工具都对自建客户端可达。[App Server 文档](https://learn.chatgpt.com/docs/app-server)

实施前做小范围兼容性验证：当前版本能否列出和接续用户选定聊天、怎样关联任务 ID、怎样处理正在运行的任务与审批。若不能可靠接续，交付有明确标识的“上下文摘要交接”，不声称是共享原聊天。

### 4. 视觉优先解决“看清、重拍、依据哪张图回答”

目前 640×480 单帧足以验证看物链路，但小字、标签、表格和屏幕内容需要更高质量输入。优先做高分辨率实拍验证、5 秒取景、重拍、裁剪和 OCR，再考虑视频。摄像头支持列表不是实拍画质证明。

保留每次主动触发、前台预览和拍后释放；对“再看一下”拍摄新图，对追问明确沿用哪次图像。低光、模糊、字太小需要请求重拍，不能补出看不清的内容。

### 5. 记忆与通知必须能解释和管理

临时聊天上下文、持久偏好、任务历史和定时提醒是四类数据。分别给出查看、修改 / 删除及保留规则，避免把后台重启后的遗忘解释成模型能力不足。

现有提醒已具备一次 / 重复、修改、取消、稍后提醒和私有保存；新的工作是送达状态、安静时段、迟到处理及用户选定的通知入口。Mac 关闭或 CC8 不在前台时，不应继续承诺它能像独立闹钟一样准时响铃。

- 竞品材料均来自官方产品、帮助、开发文档或政策页面，查阅日为 2026-11-01。Google Home 使用明确的 2026-10-29 发布条目；超级小爱政策版本为 v20260814；其余动态文档以查阅日为准，不虚构发布日期。

- 项目“已实现”以代码和验证记录为依据；“用户确认”仅代表当时场景；TODO 中的数字是建议验收门槛，不是现有成绩。
- 本轮没有足以推断市场用户问题频率的样本。优先级主要依据本项目用户反复反馈、功能依赖和日常价值；行业材料用于校准方向。
- 待解决的不确定性：中文 / 英文自定义唤醒效果、现有桌面聊天可接续范围、CC8 高清拍摄实际画质、服务长期运行与局域网切换质量。每一项都有对应的验证任务，不先承诺结果。
