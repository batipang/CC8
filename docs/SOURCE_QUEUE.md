# 明确查看原聊天待办队列

只读队列入口始于后台 0.16.20／助手 0.9.89 code126。实际安装范围见[当前部署](CURRENT_DEPLOYMENT.md)。队列条数和运行状态来自不同接口。

在“设置 → 工作汇报来源”明确点选一条已登记来源，再点“查看待办队列”。界面显示来源／项目、原聊天、读取时间及最多32条短预览，可明确复制或关闭。不改变摘要接续对象、汇报范围、编号语音上下文、已播账本或模型历史。来源仍须来自原有明确登记；设备只提交登记编号和列表修订，不接受任意聊天路径、正文或执行指令。

后台通过 `thread/queue/list` 读取最多4页，每页8条。队列结束或未能完整读取后，如果本次预算还有剩余，会对同一个已登记来源调用 `thread/read`，设置 `includeTurns=false`。状态读取最多3秒，与初始化、队列分页共用25秒预算。短命客户端由本次查询关闭。取消、Home、换线、来源删除或变更会停止后续查询并拒绝旧结果。达到页数／期限、游标循环、重复条目、错误或坏数据均保持未读／覆盖不足提示。

队列页和编号语音追问都显示本次 Codex 连接返回的运行状态，包括运行中、待审批、待用户输入和运行错误。独立进程返回 `notLoaded` 时，显示桌面执行状态未知；返回 `idle` 时仍提示核对桌面。状态读取失败或超时保留原队列覆盖结果。两次读取不构成原子快照，也不会恢复聊天、启动队列或授权重做原任务。使用本机 0.166.0 对当前开发聊天作只读检查，队列分页完整，运行状态为 `notLoaded`。接口语义见 [Codex App Server](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming)。

每条最多160字短预览，只取文字输入；不读取或访问图片、文件路径、URL等附件内容，额外字段不进入回包。正文只留RAM、不进日志／存储／模型／语音播报；复制仅由当次明确点击触发。服务启动、连接恢复或登记来源不自动扫描队列。

## 官方接口与实际边界

OpenAI的[开发者命令文档](https://learn.chatgpt.com/docs/developer-commands)提供`codex queue --thread --message`；其`--resume`失败仍可能成功退出，因此退出码不等于执行成功。本机0.166.0的帮助和实际生成schema确认`thread/queue/add`、`list`、`start`、`delete`及`clientUserMessageId`／队列ID字段存在。只读实测先向不存在目标得到错误，再向当前开发聊天成功读取空队列，均未发送消息、恢复聊天或启动模型。

字段存在不证明服务端幂等、桌面可见性、原宿主归属或完整模型／工具／审批继承。当前原聊天追加、恢复、开始、取消和重排均未接入；共享proxy的既有失败事实保留。后续发送必须绑定用户当次明确要求、固定来源及真实队列回执，未知提交结果先查、不自动重发；真正执行与完成仍需原会话证据。P1-01和P1-10保持开放，真实5个Codex／3个ChatGPT聊天接续仍在最终接入验收队列。

自动测试覆盖实际分页读取器、原控制器和编译后的原生入口：来源／修订／旧回调、关闭／换线、坏字段／附件排除、初始化／中途失败、页数／期限／游标、Unicode和复制。测试不取摄像头／麦克风，也不向真实聊天写入。最终72小时验收继续后置。
