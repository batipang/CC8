# 自动设备检查

2026-11-02 用户要求减少重复人工操作，改用自动测试。`cc8 verify-device` 从 Mac 检查已有安装，不安装 APK、不重启后台、不增加设备端调试接口；默认只输出计划，离线 CI 不接触设备。

```sh
# 只看计划：不查设备/模型，不创建目录，不开麦
./cc8 verify-device --runtime-root /absolute/live/workspace
# 实机：固定播报、播放回执、字幕布局和逻辑切换
./cc8 verify-device --runtime-root /absolute/live/workspace --execute
# 明确启用前台开麦、Home 停采、维护重开保持关闭
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture
# 追加真实 15 分钟待机，黑屏后由 Mac 播放合成问句
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --standby --acoustic
```

runtime-root 指**实际运行目录**。现场为 `/Volumes/AI/Codex/CC8-P0`，冻结运行源码1ab67a0：后台0.14.17 / 保留原签名APK0.9.13 code48；实际部署与验收范围见 [CURRENT_DEPLOYMENT](CURRENT_DEPLOYMENT.md)。自动检查脚本可来自另一份已验证源码；报告中的脚本摘要与受测后台版本分别记录。深层候选目录曾超出 macOS Unix socket 路径限制，已改为短路径并重新创建独立 venv。

## 门控与动作

- 唯一正常 Android USB AILABS_S6 / SDK 27 / shell UID 2000，原装电源连接。每次 Android 操作重核原 USB transport，不跟随被更换的目标。
- 已有 owner-private IPC，实际后台版本与指定源码声明一致；USB、已认证 Wi-Fi 都就绪。助手须在前台，麦克风、播放、校准、相机均空闲；拒绝接管正在使用的设备。
- execute 会通过现有 MiniMax TTS 播放固定公开文字。capture 明确启用**相关语音测试**，仅通过既有可见 MainActivity 和 auto_start_voice=true 开始；维护打开仍为 false，不增加远程开麦 IPC。
- 0.9.13/code48加入设备端测试时限，已于2026-11-04部署：普通采集检查180秒、包含真实待机时1200秒，均从本次启动计时；设备允许显式测试值1000～1500000ms。旧APK不会识别此约束，因此新版检查器在任何UI/播报动作前拒绝不支持它的采集测试；直接capture打开也核对能力和原采集关闭。
- standby 要求已选唤醒模式，真实等待约 900 秒，临时防止 Mac 空闲睡眠；过早黑屏、连接/采集丢失、超时均不算通过，没有修改待机阈值。
- acoustic 在 preflight 先核对 Mac 已安装且唯一的 Tingting 音色；缺失/歧义时在打开 UI 或采集前拒绝。仅在黑屏且采集仍开启时，用解析后的完整音色名说一次“大黄蜂，一加一等于几？”。不调整音量；静音、距离、方向或噪声可能导致未确认。不要求用户代读，不自动重试。
- acoustic 检查区分任务完成与声音播完：同一新准入voice回合须有唤醒、ASR、大脑与播放完成阶段。播完再观察20秒，出现额外准入回合、原回合取消、断连或采集关闭即失败；不再次播放问句。VAD先于准入创建的记录单列为候选，不直接当作对话；窗口结束仍未判定、错误终态或已确认暂停却未恢复也失败。计数本身不证明声源。

## 报告与恢复

执行源码目录的 device-access/private/device-checks/ 保存逐项原子检查点，目录 0700 / 文件 0600。仅保存测试名、状态、固定错误代码、版本、自动脚本及 Mac 音色解析模块开始时的 SHA-256 与单端耗时，不保存 dumpsys 全文、设备身份、识别/回答正文、录音、图像或凭据。开发中较早启动的报告不自动获得后续脚本摘要。

`acoustic_evidence`仅包含固定数字：本次voice记录总数（保留旧字段名new_voice_requests）、准入/已拒绝/未决/未知终态候选数、拒绝候选的暂停/未恢复数、完成/取消/任务完成数、固定阶段计数与已观察的播后时长。超时或取消也保留部分证据；请求ID、文字与提供方错误原文均不写入该字段。未启用或未进入该检查时为null。

准入依据是gate=accepted、绑定generation、brain_start或任务回执，任何一个成立就不能用“拒绝候选”标签隐藏额外对话。只有无准入证据、明确rejected且门控为empty/echo_text/echo_render/weak_near/wake_closed的候选可单列；未知、错误、stale/cancelled不会被忽略。候选可在20秒窗口内完成分类，已确认的暂停还须有resume_ack。计数保留真实暂停，自动问答完成不等于纯播报没有误暂停，P0-04仍独立验收。

2026-11-04的0.14.17首轮实机在第九项按两条原始voice记录提前失败。独立数字诊断证明一个准入问题已播完，另一条generation=null、echo_text/rejected，无大脑或任务，暂停后恢复。原失败和缺失的播后20秒观察保留，未重放刺激或把原轮次改成通过。候选统计的离线修复不改变音频门槛、APK、模型或运行后台；新检查器实机仍须另行验证。

同一实际运行目录共享排他测试锁。后台实例改变即中止；已触及 UI 的路径在失败、超时或 Ctrl+C 后均尝试 Home 停采，再维护打开恢复前台，核对两端麦克风及相机关闭。无法确认则 cleanup_unconfirmed，不能给出通过结论。启动前拒绝不改变原状态。

仅靠Mac的finally不能处理测试进程被强制结束。本次参考句观察在前两组无暂停、无新任务且收尾完成后被中断，第三组报告停在running；现场核查仍在收音。独立恢复核对原实例、测试锁、无在途工作和镜头关闭后停采，保留原报告及`interrupted-run-cleanup.json`，不追认为第三组通过。0.9.13/code48候选因此把时限落实到AudioRecord线程：截止前后均检查、过期帧不发送；设备看门狗也仅停止本次AudioRecord，可解除阻塞读取，旧epoch不能停止新硬件。前台按钮正常开启语音仍无测试时限/看门狗；测试限额不持久化，重连不续期，人工停止后再手动开启不会继承旧限额。设备挂起/硬件驱动本身失效仍不能凭软件测试保证即时资源释放，实机执行证据另记。

软件回归编译真实录音worker、finally、停止方法与实际intent回调，覆盖无Mac/UI回调的到期、阻塞read、跨截止帧丢弃、资源等待到期、正常长会话及旧新录音隔离。八项通过。两组旧源码对照分别暴露“持续收音”和“忽略无效test limit”：worker对照仅增加签名适配以调用未改动的旧实现，没有插入计时逻辑；编译均成功，两个断言失败、无fixture错误。它们不替代真实设备上的限额与宿主中断测试。

除能力位之外，开始采集后还须收到实际设备的同值整数限额与正的剩余时间；缺失、类型不符、错值或已过期都中止并收尾，不能把“声明支持”当作时限已经生效。

## 无录音的英文唤醒回归

## 播放的声学证据

0.14.18新增显式检查，APK仍为0.9.13／code48，协议仍为2。只读计划不查询设备、不载入模型、不创建文件：

```sh
./cc8 verify-device --runtime-root /absolute/runtime --capture --playback-evidence
```

部署支持该能力的后台后，使用其voice环境执行相同命令并加`--execute`。执行沿用单实例设备测试锁、唯一USB/型号/版本预检、有界前台麦克风租约和结束停采恢复；不需要再次手动点开始或听音判定。旧后台缺少`playback_evidence_supported`时，在首次打开界面或麦克风之前失败。默认检查不运行此项，必须同时指定`--capture`。

测试在校准完成后的既有收音中播放固定短句“这是扬声器和麦克风的声学检查。请保持安静，检查结束后恢复正常。”，不更换当前MiniMax音色。观察只在RAM中保留最多3秒MIC、1.5秒RENDER，选择200ms非静音参考，在同一CC8时钟的−80至800ms偏移范围查找；相关度至少0.55、与30ms邻域之外竞争峰的差至少0.12才报告`observed`。周期声或竞争峰报告`ambiguous`，不足覆盖/静音参考/序列或时钟缺口/超时分别记录。门槛是固定保守的测量规则，未按现场结果回调，不代表一般声学识别准确率。

显式测量期间继续运行AEC，不向ASR、唤醒、打断或Dot工具链递交这段音频；这不是全双工插话验收。正常界面的暂停仍可取消。观察期限20秒，IPC至多22秒等待并取消本次播报；客户端断开、停止、会话或传输代次改变会清理自有缓存。结束用设备时间水位丢弃尚在lookahead的测量音频，不从IPC线程修改接收队列，也不会误清理后继测试。测试不会自行开启麦克风或摄像头。
