# 自动设备检查

2026-11-02 用户要求减少重复人工操作，改用自动测试。`cc8 verify-device` 从 Mac 检查已有安装，不安装 APK、不重启后台、不增加设备端调试接口；默认只输出计划，离线 CI 不接触设备。

```sh
# 只看计划：不查设备/模型，不创建目录，不开麦
./cc8 verify-device --runtime-root /absolute/live/workspace
# 实机：固定播报、播放回执、字幕布局和逻辑切换
./cc8 verify-device --runtime-root /absolute/live/workspace --execute
# 明确启用前台开麦、Home 停采、维护重开保持关闭
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture
# 追加真实 15 分钟待机，黑屏后由 Mac 播放合成问句
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --standby --acoustic
```

runtime-root 指**实际运行目录**。现场为 `/Volumes/AI/Codex/CC8-P0`，冻结运行源码867ff19：后台0.14.16 / 保留原签名APK0.9.11 code46；实际部署与验收范围见 [CURRENT_DEPLOYMENT](CURRENT_DEPLOYMENT.md)。自动检查脚本可来自另一份已验证源码；报告中的脚本摘要与受测后台版本分别记录。深层候选目录曾超出 macOS Unix socket 路径限制，已改为短路径并重新创建独立 venv。

## 门控与动作

- 唯一正常 Android USB AILABS_S6 / SDK 27 / shell UID 2000，原装电源连接。每次 Android 操作重核原 USB transport，不跟随被更换的目标。
- 已有 owner-private IPC，实际后台版本与指定源码声明一致；USB、已认证 Wi-Fi 都就绪。助手须在前台，麦克风、播放、校准、相机均空闲；拒绝接管正在使用的设备。
- execute 会通过现有 MiniMax TTS 播放固定公开文字。capture 明确启用**相关语音测试**，仅通过既有可见 MainActivity 和 auto_start_voice=true 开始；维护打开仍为 false，不增加远程开麦 IPC。
- standby 要求已选唤醒模式，真实等待约 900 秒，临时防止 Mac 空闲睡眠；过早黑屏、连接/采集丢失、超时均不算通过，没有修改待机阈值。
- acoustic 在 preflight 先核对 Mac 已安装且唯一的 Tingting 音色；缺失/歧义时在打开 UI 或采集前拒绝。仅在黑屏且采集仍开启时，用解析后的完整音色名说一次“大黄蜂，一加一等于几？”。不调整音量；静音、距离、方向或噪声可能导致未确认。不要求用户代读，不自动重试。
- 新版 acoustic 检查区分任务完成与声音播完：同一新 voice 回合须有唤醒、ASR、大脑与播放完成阶段。播完再观察20秒，出现额外 voice 请求、原回合取消、断连或采集关闭即失败；不再次播放问句。额外请求的来源可能是回声或现场人声，计数本身不证明原因。

## 证据与界限

| 检查 | 实测依据 | 不据此宣称 |
| --- | --- | --- |
| 维护打开不开麦 | Mac health 与设备 snapshot 双端关闭 | 全部竞态均已验收 |
| 播报与字幕 | 新的 completed announcement、playout_ack、playback_done；播放期间当前行可见、字幕/进度及光环/状态无重叠 | 精确声学起声/延迟、字体审美 |
| 逻辑切换 | 抑制 USB 12 秒，Wi-Fi 接管、USB 优先返回，未自行开麦 | 真实拔线；不计入 20 次物理往返 |
| 采集生命周期 | 明确打开启动并完成校准；Home 后 inactive 且帧计数不增长；维护重开仍关闭 | 全部断网、登录/睡眠和故障矩阵 |
| 待机 | 新采集后的真实等待、黑屏，前台及采集仍有效 | 三轮全部完成或 72 小时稳定性 |
| 合成声学唤醒 | Mac 扬声器→CC8 麦克风→本地唤醒→新 voice 回合有 ASR/大脑/播完回执；设备亮屏且前台 | 回答语义、真人中英召回率、1/3 米准确率、真人打断延迟 |

旧版 0.12.2 / APK 0.8.6 的人工观察独立保留：基础对话、普通音量插话、单次物理往返、Home 重开和一次黑屏唤醒。半秒内是用户体感；拔 USB 约 9 秒连接空窗为采样观察，之后用户手动开麦。新版自动结果不能改写旧版证据的版本、样本量或性质。

## 报告与恢复

执行源码目录的 device-access/private/device-checks/ 保存逐项原子检查点，目录 0700 / 文件 0600。仅保存测试名、状态、固定错误代码、版本、自动脚本及 Mac 音色解析模块开始时的 SHA-256 与单端耗时，不保存 dumpsys 全文、设备身份、识别/回答正文、录音、图像或凭据。开发中较早启动的报告不自动获得后续脚本摘要。

新版 `acoustic_evidence` 仅包含本次新voice请求数、完成/取消/任务完成数、固定六个阶段的计数与已观察的播后时长。超时或取消也保留部分阶段证据；请求ID、文字与提供方错误原文均不写入该字段。未启用或未进入该检查时为null。

同一实际运行目录共享排他测试锁。后台实例改变即中止；已触及 UI 的路径在失败、超时或 Ctrl+C 后均尝试 Home 停采，再维护打开恢复前台，核对两端麦克风及相机关闭。无法确认则 cleanup_unconfirmed，不能给出通过结论。启动前拒绝不改变原状态；SIGKILL 或断电等无法运行 finally 的情况不保证进程外清理。

报告固定 physical_usb_unplug_tested=false、human_accuracy_asserted=false、acoustic_latency_asserted=false、full_p0_acceptance=false。离线 fixture 验证门控、计时、旧回执排除、失败清理和脱敏；实机结果另记 VALIDATION。一轮自动通过不关闭整个 P0。

## 无录音的英文唤醒回归

```sh
# 默认只打印计划，普通 Python 可运行，不载入模型或创建文件
./cc8 verify-wake --model-root /absolute/live/workspace
# 用已准备的模型环境执行；模型缓存必须先通过既有哈希校验
/path/to/evaluation/python cc8 verify-wake --model-root /absolute/live/workspace --execute
```

这项检查只生成 Mac 公开合成语音，不播放声音、不读取麦克风、不联系云端、不操作 CC8，也不修改运行环境。执行源码目录的 `local_wake.py` 是被测实现；model-root 仅指定校验过的模型缓存，不代表自动改测该目录的源码。

V2 固定25条语料：12个已核对安装的命名音色正样本（Samantha、Karen、Daniel、Tingting，各三档语速）、3个显式系统默认音色的旧输入，以及10个普通/近音负样本（含 Bumble、Bubble bee）。逐个以 20ms 帧馈送，覆盖即时、60/140/160/480ms 前导和 1s 连续上下文；另保留无初始化的两组参照。六组 production 条件全部正样本命中且全部负样本不触发才通过；少样本、生成失败、取消或条件缺失均不能通过。参照条件只作观察，不参与放宽标准。

仅在私有 wake-checks 目录保留固定样本 ID、标签、布尔结果、源码/语料/合成 PCM 摘要、原生库版本和二进制摘要；临时合成音自动删除。失败退出 2，Ctrl+C 退出 130 并在已开始评测时写 cancelled；普通计划退出 0 不代表通过。合成语音覆盖只能定位回归，不能替代真人、声学距离、电视背景噪声或中英文实际召回率。

2026-11-03 隔离研究发现原生 KWS 在连续静音后的重置边界也存在漏检；上游已有 [issue 3990](https://github.com/k2-fsa/sherpa-onnx/issues/3990) 和 [待合入修复 3994](https://github.com/k2-fsa/sherpa-onnx/pull/3994)。以固定 v2.0.1 源码隔离回编，官方复现从 59/65 改为 65/65，但自定义 Bumblebee 语料仍有漏检；扩大解码路径还出现近音误触发。320ms 初始化也未覆盖全部时点。因此未合入这些运行行为改动、未把实验原生库安装到正在运行的助手中，P0-03 保持开放。


### 音色身份校验修正

本机 `say -v Alex` 与一个不存在的测试名字均返回0且无错误，实际回退系统默认音色；因此不能用成功退出和已生成WAV证明目标音色存在。现在从 `say -v ?` 解析已安装列表，兼容本地化名称和重复行；缺失/歧义拒绝，使用唯一完整名称合成，不自动下载音色。计划模式不查询列表。

旧22条输入全部按PCM摘要保留：原3条Alex重标为明确省略 `-v` 的系统默认音色，其他19条摘要一致；额外加入3条可确认的Karen。原Alex不能算独立命名说话人，既有PCM漏检/误检记录仍有效。V2报告含语料版本、请求/解析后的音色、默认选择标志、脚本及音色模块摘要；默认音色变化仍须通过PCM摘要识别，不能声称复现了固定说话人。

新版0.14.5 / APK0.9.3也已完成三轮九项实机检查，报告与执行脚本/音色模块摘要一致；每轮均恢复前台、双端停采。旧版三轮真实待机已在0.13.7 / APK0.8.8候选完成，见 [VALIDATION](VALIDATION.md)。其中后两轮使用本次音色校验之前的 main `cf4f9e5` 自动脚本，摘要核对通过；不把它们改写成后续新增门控版本的执行记录。

最新隔离Python绑定补丁版正式重跑V2：与原版全部25条 `fixture_pcm_sha256` 一致，六组production正样本仍为2/15、7/15、9/15、11/15、13/15、13/15；各组10个负样本零触发，每个条件的预测逐条相同。连续上下文仍漏Samantha和Daniel的200档样本。上游65/65修复不能视作该名字的准确率修复，因此未部署补丁。单独的公开输入电平检查显示这两种音色的三档RMS相近；未证明削波或音量是漏检原因，不据此调阈值。

## 中文唤醒与停止指令的数字回归

```sh
# 只计划；普通 Python 即可，不载入 numpy/模型，不查询设备或创建文件
./cc8 verify-local-speech --model-root /absolute/model/workspace
# 明确执行；使用已准备的隔离模型 Python，不修改正在运行的助手
/path/to/evaluation/python cc8 verify-local-speech --model-root /absolute/model/workspace --execute
```

固定44条公开合成输入：Tingting、Meijia两种已核对安装的音色，每种140/170/200三档语速，各含“大黄蜂”、名字加问句、三种停止词和名字加停止词；另有八条近音或普通负样本。共18条含唤醒词、24条含停止词，六条同时包含两者；这些数量相交，不能相加当作样本总数。没有把与“大黄蜂”同音的“大黄风”当作可区分的负样本。

每条直接馈入当前源码的 ChineseWake 和 FastStopDetector 独立流，使用同一模型/锁、原有增益与门槛；每次新建流，按20ms帧输入，检查0/60/140/160/480/1000ms前导及两秒尾静音。六种时点都必须与预定的唤醒/停止结果集合完全一致。没有初始化、降阈值或额外关键词补偿。44条数字音频的264个条件观察不是264个独立说话样本。

model-root仅提供缓存；两份模型清单须先与执行源码中的受审清单一致，再用既有归档/逐文件摘要校验。报告绑定模型清单、实际源码、固定语料、合成PCM及原生扩展/动态库SHA；包版本相同的本地补丁也能区分。临时合成文件在每条结束后删除，结果仅保留owner-private JSON，不读旧录音、不播放、不联网、不操作CC8、不调用Dot。生产安装与配置保持原样。

漏检、错词、意外另一流命中、少样本、缺时点或合成失败均不能通过。正常失败退出2，已开始测量时取消保存cancelled并退出130；前置失败输出固定指引，异常正文不写报告。默认计划退出0不算验收。数字输入不覆盖声学回声、VAD、远场、电视噪声、真人口音、停止指令的端到端延迟或自播报抑制。
