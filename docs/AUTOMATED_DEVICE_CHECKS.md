# 自动设备检查

后台64候选增加[声学检查前的候选观察](PROBE_IDLE.md)：只在原采集、未准入且最终明确拒绝的本地候选上限时等待，正式请求、缺测和归属变化仍拒绝；保留失败现场的固定状态／计数，不放宽普通语音门槛。

0.15.63 起，时延采样和本地工具对照沿用普通检查的选项组合规则：只省略重复播报／逻辑换线，保留实际请求的采集生命周期、待机、声学和可选证据。特别是 `capture + standby + acoustic + latency_sample` 的七项计划，与真实执行顺序一致；未选择 `awake_dialogue` 时不会虚构清醒问答。离线对照直接执行原 `SmokeRun.run` 的分支，但不调用设备操作；它不能证明真实设备已通过这些检查。

2026-11-02 用户要求减少重复人工操作，改用自动测试。`cc8 verify-device` 从 Mac 检查已有安装，不安装 APK、不重启后台、不增加设备端调试接口；默认只输出计划，离线 CI 不接触设备。

```sh
# 只看计划：不查设备/模型，不创建目录，不开麦
./cc8 verify-device --runtime-root /absolute/live/workspace
# 实机：固定播报、播放回执、字幕布局和逻辑切换
./cc8 verify-device --runtime-root /absolute/live/workspace --execute
# 改用固定两段播报，逐段核对起播和完成回执
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --multi-clause
# 明确启用前台开麦、Home 停采、维护重开保持关闭
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture
# 在相同限时开麦窗口内，追加录音时钟检查
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --capture-clock-evidence
# 在屏幕已亮时测试本地唤醒、问答和播完后的回声；单独一轮，无需等待黑屏
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --awake-dialogue
# 追加同回合的设备时钟与室内声音对照，使用支持此能力的候选后台
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --awake-dialogue --response-acoustic-evidence
# 追加真实 15 分钟待机，黑屏后由 Mac 播放合成问句
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --standby --acoustic
```

runtime-root 指**实际运行目录**。现场目录为 `/Volumes/AI/Codex/CC8-P0`；实际运行版本与验收范围见 [CURRENT_DEPLOYMENT](CURRENT_DEPLOYMENT.md)。自动检查脚本可来自另一份已验证源码；报告中的脚本摘要与受测后台版本分别记录。深层候选目录曾超出 macOS Unix socket 路径限制，已改为短路径并重新创建独立 venv。

待机检查在开麦前记录唤醒和语音识别计数，校准结束后再记录播放帧基线。等待黑屏期间若任一计数变化，立即结束该轮，保留数字差值并走原停采流程。黑屏确认后还会再核对一次计数。验收新待机批次时，用 `./cc8 audit-device-suite /absolute/private/report.json --require-standby-quiet` 要求每轮的三个 `quiet_counter_deltas` 差值均为零。时长未确认和静默计数未确认各有固定原因。省略该参数时，旧报告仍可按原时长证据复核。

单独复验三轮待机可用 `./cc8 verify-device --runtime-root /absolute/runtime --capture --standby-suite` 查看计划。追加 `--execute` 后，在同一运行实例和验收锁下执行三轮真实等待、合成唤醒和完整问答，每轮都确认停采，失败后停止且不自动重试。报告可用 `./cc8 audit-device-suite /absolute/private/report.json` 复核，该批次类型始终要求静默计数。它仅覆盖待机和唤醒，物理拔插、真人识别与 72 小时运行分别验收。


## 设备检查中的后台资源证据

0.15.65 的检查器从原有 `health` 读取中复制 `runtime_resource_evidence`，不新增轮询、进程、相机或麦克风操作。只记录后台 Bridge 进程的 RSS／峰值 RSS、累计 CPU 秒数、Python 线程数及打开描述符数，不包含模型／Dot／工具子进程或整台 Mac 的资源。运行实例变化仍由原检查立即拒绝，不能混成同一条资源曲线。

每60秒至多保存一个周期样本，额外保留最后一次实际读取；总量最多256条。报告生成或收尾失败不会补造一次“结束测量”。旧端缺指标保持 null，非法值也保持 null 并单列固定字段名；不保存进程参数、实例 ID、正文、错误消息或音频。容量满后保留首段和最新读数，并记录丢弃周期数量。

`audit-device-suite` 对含新字段的阶段重新核对固定 schema、字段、数值范围、单调时间和容量；从原样本计算首尾、极值、变化量、每小时斜率及最大采样缺口，不采用文件自带汇总。累计 CPU／峰值回退会单列，禁止计算跨回退的变化量和斜率。已通过、失败和未执行阶段分别保留；没有字段的旧文件仍可核对原功能范围，但资源未测。资源状态 observed 只表示已有读数有效，不证明连续覆盖、无泄漏或72小时稳定；模型子进程和 CC8 资源也不在本字段范围。

软件回归覆盖真实检查器健康入口的零额外请求、实例改变前拒绝、失败收尾、采样上限、缺测／非法值、累计回退、保存快照隔离、旧报告、失败阶段以及篡改字段拒绝。实体测量另行记录，不因软件通过关闭 P0。


## 成对输入的自动验收

`verify-device --capture --expect-capture-frontend paired` 在原有有界前台收音中，要求 CC8 的实际格式与 Mac 接收模式一致，并核对 48 kHz／四路／版本 1 的格式声明。`mono` 对应 16 kHz／单声道。选择参数不改变 `capture_frontend` 配置；未部署、能力缺失、无法确认、实际回退或双端不一致均不能算所选模式通过。无该参数的旧设备检查保留兼容，但其格式证据明确缺测。

采样开始及各次连接／收音状态核对会重新读取实际格式，格式变化立即失败。报告只保存固定格式值、固定回退原因和时钟能力标记；能力标记不能代替硬件时钟验收。报告快照拥有独立副本，后续修改不改变检查器内部证据。原有超时、Home 停采、维护不开麦及收尾检查保持。

单轮和批次的默认调用仍只输出计划；实际执行仍需 `--execute`、空闲与身份检查及原前台权限。批次离线复核增加同名 `--expect-capture-frontend`，每个阶段都必须带相同的期望和实测回执；不能根据总状态、单一阶段或旧报告补判 paired。

离线回归覆盖实际启动检查、回退拒绝、连接后复核、报告所有权、两类批次逐阶段复核、非法类型、私有内容不外泄，以及最小 PATH 下无设备／模型副作用的计划。新版首轮已执行实际格式核对，独立声学门槛仍未通过，见下文；不作为 P0-04 的真人或节目声验收。

## 收音启动失败与 Home 停采

启动或校准检查失败时，报告在 Home 和维护重开前读取 Mac 与 CC8 各自的收音状态，以及设备阶段的固定枚举。无法读取的一侧记为空，原失败原因保留。该快照只能证明采样时的两端状态，无法单凭错误阶段证明某条拒绝消息已送达。

常规 Home 停采检查要在维护重开前观察到两端麦克风均关闭，并在两秒后核对两端收音帧数均未变化。若 CC8 状态不可读、仍在录音或计数变化，该步骤保留失败。之后仍走原有紧急 Home 与维护收尾，收尾成功不会改写先前失败。

## 清醒状态合成问答

后台 0.14.50 起，清醒和待机问答的 `acoustic_evidence.response_playout_timing` 记录本轮新回答的句尾、同一确认段的起播和播完回执，以及句尾到起播的间隔。报告只保留有界数字和固定状态，不保存请求 ID、音频或正文。独立检查将不完整证据标为 `missing` 或 `malformed`；固定批次要求清醒和三轮待机均有有效配对。时间是 Mac 收到播放回执的时间，不能用于认定扬声器实际起声或 P95 已达标。

`--awake-dialogue` 复用 180 秒前台限时收音，在 Home 停采前执行。先核对当前等待唤醒、USB 连接、设备前台与剩余收音时间，排除历史回执和未结束请求。Mac 只播一次固定公开问句，随后核对同一个新请求的唤醒、识别、Dot 任务完成、设备开始与结束播放回执。播完后再观察 20 秒。第二个准入请求、未决候选或拒绝后未恢复的暂停都会使检查失败；所有退出复用双端停采和维护重开流程。报告只保存计数和阶段，不写请求 ID、正文或音频。

清醒和待机问答在播完后还读取一次本机任务回执。只接受与新语音请求代次相同、唯一且已完成的任务，核对其识别标题为固定的“一加一等于几”。允许等价的数字、加号、等号和格式差异，以及保留固定唤醒词“大黄蜂”。历史实机识别出现过保留前缀的情况，仍须逐字核对剩下的问句。任务标题仅在内存中比较，报告只写 `recognized_stimulus_matches`，固定批次要求该字段为 `true`。这一项核对指定问句的识别归属，答案正确性及真人准确率另行验证。

报告也记录刺激前后的 Mac 收音帧增量、固定的拒绝原因计数及 ASR 开始次数。仅当本轮只有一个新话语候选且被本地唤醒门拒绝时，附上已校验的声学数值摘要。缺失或非法摘要单独标记，不输出原对象。收音帧增量包含静音，不证明麦克风听到了指定刺激。旧后台缺计数时保留缺测，原检查的通过条件不变。

这条用例与 `--standby` 分轮执行，共用当前实际运行目录的自动测试锁。它验证亮屏时的一次合成语音链路。黑屏唤醒、问句正文准确率、真人与远场仍各自验收。

后台 0.14.57 起，独立清醒测试和 [30 轮简单问答批次](MEASUREMENT_RUNS.md#30-轮合成简单问答采样) 可以显式加上 `--response-acoustic-evidence`。每轮探针只在已开启的限时收音中等待本轮的固定公开问句，最多等 120 秒。确认本地唤醒和识别问句后绑定本轮代次与设备输入时钟；后台 0.15.73 起，等待大脑/联网时只保留这些标量，在本轮开始输出、发送播放通知和 PCM 前才启动声音对照。录放样本仅在内存中保留，活动观察最多 20 秒，且不超过原 120 秒绝对截止；后续分句不重新计时。0.15.75 起，超过 20 秒、至多 120 秒的端到端区间还须附同次采集的连续时钟证据：从问句前的标量标记至确认输出块，包与采样时间必须连续、无重置或读取缺口，累计偏差不超过原 2 毫秒容差。证据只含版本、覆盖时长及零缺口计数；缺失或损坏时不得扩大旧 20 秒范围。活动缓存仍限 20 秒、绝对截止仍为 120 秒，声学相关性、前段匹配门槛和失败即停规则保持。时钟缺口不能降为仅缺声学样本的可继续状态。探针沿用正在运行的回声消除和识别流程。退出收音或切换通道时清理探针。缺失证据或回答代次不一致时检查失败。

报告的 `last_voiced_to_confirmed_output_block_ms` 使用设备时钟，记录最后一个连续有声输入帧的结束与第一个通过录放相关性确认的 20 毫秒输出块之间的间隔。这个数据受人声活动判定、录音时钟和房间声学影响，报告仍保留 `acoustic_latency_asserted: false`。报告只保存数值和状态。

## 同回合多段播报

`--multi-clause` 将短播报替换为固定 132 字、按 120 字分段的同回合播报。后台 0.14.41 候选只在同一播放标识的首个非零信号回执和帧数有效的结束回执均通过校验时增加计数。缺失的回执、旧段或重复回执无法增加计数。诊断报告只增加回合内确认段数，首段计时和旧设备的播放行为沿用原有逻辑。

设备检查要求恰好两段都有回执、USB 保持连接、Mac 麦克风关闭且录音帧数不变，并继续核对播报时的设备麦克风状态和字幕布局。未声明支持时，检查会在打开设备界面前结束。逐段回执验证已做离线协议回归，新入口的实机复跑待长稳观察后执行。回执对应设备播放头，声学起声时间仍另行测量。

## 录音时钟证据

从候选 APK 0.9.16 code51 起，`--capture-clock-evidence` 可在已有前台限时录音中读取 Android [AudioRecord.getTimestamp](https://developer.android.com/reference/android/media/AudioRecord#getTimestamp(android.media.AudioTimestamp,int)) 的单调时钟锚点。正常语音不执行这项采样。`--capture-clock-evidence` 需要同时指定 `--capture`，也可与播放时钟检查组合。设备未声明支持时，预检在打开应用或播报前失败。

工具在校准结束后读取本轮统计。至少两个帧位置和时间都递增的锚点才算观测到证据。重复锚点和接口暂不可用单独计数。越界和倒退使该次检查失败。报告只保存计数和偏移范围。偏移为同一帧的 Android 采集管线时间减去现有麦克风包时间，正值表示 Android 锚点更晚。缺少可用锚点时没有偏移字段。该偏移用于量化读缓冲推算的差异，实际麦克风到扬声器的声学延迟仍需独立验证。现有录音包时钟、回声消除与限时关麦路径沿用原行为。

后台 0.14.85／APK 0.9.35 已部署，为无效锚点补充八类计数：硬件帧范围、已读帧范围、帧距离、录音原点、硬件时间非正、硬件时间在未来、硬件时间过旧及帧时间偏移越界。每个无效锚点只计原有校验顺序中的首个失败原因，八项之和必须等于 `invalid`。不导出硬件帧位置或原始时间戳，不改变校验门槛和实际收音时间。新版工具接受不含原因组的旧报告；含原因组时必须完整、为有界整数且总数一致，缺项、布尔或额外字段仍拒绝。旧工具不能解释新版扩展统计，需用匹配版本的工具。

实际专项在 30 个样本上确认首个失败原因为 `invalid_frame_range`，仍将录音时钟记为未确认，结束停采。原因组已由实际 Java 生产端经设备状态送至 Python 校验器，独立复核与原统计总数一致；没有把原因明确当作时钟修复。详见 [当前部署](CURRENT_DEPLOYMENT.md)。

后续独立前台 QA 在同一录音器两段各六秒中取得 47 个样本：API 都返回成功，但帧位置不在本段范围，返回计数变化率约 48 kHz，且停止／再开始未观察到清零。原生产检查全部拒绝，不修改锚点或将专项改判通过。正常会话并不使用这组诊断锚点；方法与边界见 [录音时钟核对](CAPTURE_CLOCK_FORENSICS.md)。

## 分开记录声学和时钟检查

录音时钟、长窗口匹配、播放时钟和播报前段各有独立结果。所有播放证据来自同一次固定播报。录音时钟取第一次有界收音的状态，之后的待机检查不再重复这项取样。

录音时钟检查需要先确认有界收音，播放证据检查需要先确认固定播报已完成。满足这些前置条件后，证据不足只影响对应检查的结论。工具在播报前后核对同一个后台、USB、前台、相机关闭及有效收音时限。设备或会话状态不符、播报未完成和中断仍终止后续检查，并走原停采收尾。任何已选择的证据项失败，整轮仍记为失败，即使随后停采、待机和唤醒均通过。

## 播报前段声学证据

后台 0.14.30 候选新增 `--leading-acoustic-evidence`，复用前台限时麦克风与固定公开播报，不需要额外播报或开麦。

```sh
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture \
  --playback-evidence --leading-acoustic-evidence
```

原有 200 毫秒相关性先确定一个唯一匹配。随后在原播报的前 250 毫秒内找到首个达到参考电平的 20 毫秒块，核对该块与紧接的第二块是否都在原始麦克风流的对应位置达到电平和相关性门槛。前段缺失、两块不连续或渲染时间跳变时保留未确认原因。后段匹配可独立成立。报告只保存块长度、最低相关性及相对时间，不保存音频。

后台 0.15.30 在同轮播报的窗口匹配有歧义时，附带最高与竞争窗口的两项四位小数相关分数。该轮仍缺少确认出声块的时间，不进入声学时延统计。旧报告可沿用原有原因。固定工具题可识别准确的终端来源尾句，仍须整段算式通过并独立确认实际工具路由、播报和停采。

`capture_minus_render_origin_ms` 是检测到的第一块在麦克风流中的时间减去设备估算的渲染起点。它仍受设备时钟误差和检测门槛影响，低电平前导、真实第一个可听采样及真人端到端时延没有在此测量。实机证据按版本记录。 [0.15.30 固定工具新样本](MEASUREMENT_RUNS.md#01530code79-固定工具新样本)

## USB 写入超时与故障切换

后台 0.14.36 候选给每次写入 ADB 子进程 stdin 的完整协议包设置 5 秒单调时钟上限。管道可写时直接发送，遇到背压时短间隔等待并检查关闭。超时或断管后废弃原通道，避免在不完整包后追加数据。关闭会唤醒写入并终止本连接拥有的 ADB 子进程。接收线程仍负责在退出时释放描述符。

USB 激活失败由尝试激活的通道处理。即使触发路由复查的是 Wi-Fi 排队事件，也不会因此关闭备用 Wi-Fi。下一轮按既有就绪条件选择通道，音频和任务沿现有取消流程处理，不重发写入失败的旧请求。

隔离测试用真实子进程管道复现背压与断管，并用本地套接字验证备用路由仍可选。测试同时核对正常大包完整性、超时后拒绝再次写入，以及关闭能中断长时间等待。候选未部署，物理拔插和真实 Android 链路仍按实机矩阵核对。

后台 0.14.40 候选在激活消息成功发送后才选定新通道并切换语音会话。新 USB 管道断开时，已可用的 Wi-Fi 保留为活动通道，原播报、任务和录音代次得以继续。后续可用 USB 激活成功才执行一次实际切换，按既有规则取消旧播报和在途请求。若 Mac 会话绑定失败，释放候选连接并在下一轮重新核对路由。

本地真实断管与备用套接字回归验证失败尝试不增加切换次数，也不清理原任务。随后可用的 USB 切换只推进一次会话代次。验证范围为本地消息写入和主机会话切换，实机收到消息及物理拔插另行检查。

## USB 总线与路由观察

`watch-handover` 只读取 Mac 的 USB 注册树和已运行后台的健康、路由接口。默认只打印计划。执行需预先创建仅当前用户可访问的报告目录，CC8 已通过 USB 连接且配对 Wi-Fi 就绪。

```sh
./cc8 watch-handover --runtime-root /absolute/live/workspace --cycles 20 --seconds 1800 \
  --output /absolute/private/usb-handover.json --execute
```

每轮要求观察到同一个 CC8 离开 USB 总线、后台选用 Wi-Fi、设备在原 USB 端口以新注册实例出现、后台恢复 USB 优先。每次读取路由状态的前后都核对总线和后台健康。后台实例变化即停止，跨越总线或已选路由变化的采样分别计数并跳过。测试拒绝软件 USB 抑制与双通道抑制、换设备或端口、上游拓扑变化、超过 5 秒的采样间隙和可见的音频活动。等待任一通道路由恢复上限为 30 秒，报告保存四个阶段的相对时间，超时保留不完整的轮次。报告不保存设备序列号、端口或运行实例 ID。

新版还要求麦克风和渲染帧计数保持稳定，用于发现两次轮询之间的音频活动。USB 拔出后允许直接切到 Wi-Fi，或短暂经过无通道再切到 Wi-Fi。USB 恢复优先时须同时确认配对 Wi-Fi 仍就绪，轮次之间也持续核对两条通道。额外路由切换不能计为通过。报告按轮记录实际路由切换增量，保留两次或三次的合法路径。

此检查持有运行目录的排他测试锁，避免与新版长稳观察、设备故障或后台恢复检查重叠。启动时遇到锁冲突会在查询总线或写报告前退出。已有的无锁历史观察仍须先结束。

这项检查不操纵 USB，也不开麦、播报或拍照。它记录空闲时的 USB 总线重新枚举和路由行为。物理拔线和设备 USB 功能重置都可能导致重新枚举，报告因此不宣称验证人工拔线，也不涵盖任务、播报、相机或录音期间的切换。

补强后的工具在现场后台 0.14.20 上完成 6 秒最小 PATH 只读预检，确认 USB 和备用 Wi-Fi 就绪，获得 11 次稳定采样。期间没有总线变化，报告按期限结束，累计 0 轮。

## 门控与动作

- 唯一正常 Android USB AILABS_S6 / SDK 27 / shell UID 2000，原装电源连接。每次 Android 操作重核原 USB transport，不跟随被更换的目标。
- 已有 owner-private IPC，实际后台版本与指定源码声明一致；USB、已认证 Wi-Fi 都就绪。助手须在前台，麦克风、播放、校准、相机均空闲；拒绝接管正在使用的设备。
- execute 会通过现有 MiniMax TTS 播放固定公开文字。capture 明确启用**相关语音测试**，仅通过既有可见 MainActivity 和 auto_start_voice=true 开始；维护打开仍为 false，不增加远程开麦 IPC。
- 0.9.13/code48加入设备端测试时限，已于2026-11-04部署：普通采集检查180秒、包含真实待机时1200秒，均从本次启动计时；设备允许显式测试值1000～1500000ms。旧APK不会识别此约束，因此新版检查器在任何UI/播报动作前拒绝不支持它的采集测试；直接capture打开也核对能力和原采集关闭。
- standby 要求已选唤醒模式，临时防止 Mac 空闲睡眠。从发起新一轮限时录音开始计时，先确认亮屏，再接受满 900 秒后开始的黑屏轮询。轮询开始和返回各自记录，避免把一条跨过 900 秒的查询当作达标证据。报告保留最后亮屏和首次黑屏的观察时间；它们限定采样范围，设备实际切换时刻仍在两次观察之间。任何一次轮询发现失去前台、录音期限失效或双端收音中断，均判失败。
- acoustic 在 preflight 先核对 Mac 已安装且唯一的 Tingting 音色，缺失或歧义会在打开 UI 或采集前拒绝。刺激前核对黑屏、本地等待唤醒、USB 就绪和设备剩余录音时间，再用解析后的音色说一次“大黄蜂，一加一等于几？”。只接受同一新请求的唤醒、识别、任务完成和设备起播及播完回执。静音、距离、方向或噪声可能导致未确认。测试无需用户代读，失败后保留原回执。
- acoustic 检查区分任务完成与声音播完：同一新准入voice回合须有唤醒、ASR、大脑与播放完成阶段。播完再观察20秒，出现额外准入回合、原回合取消、断连或采集关闭即失败；不再次播放问句。VAD先于准入创建的记录单列为候选，不直接当作对话；窗口结束仍未判定、错误终态或已确认暂停却未恢复也失败。计数本身不证明声源。

### 两路全断后停采与重连

```bash
./cc8 verify-device --runtime-root /absolute/live/workspace --capture --all-route-loss
./cc8 verify-device --runtime-root /absolute/live/workspace --execute --capture --all-route-loss
```

## 英文唤醒的实机检查

从后台 0.15.0 候选起，检查器在 Mac 测试句播放前后各读取一次英文检测流的输入计数，分别计算主流和辅助流收到的样本数。旧后台显示不可用。读取最多等待解码锁 10 毫秒，过时返回缺测。单边缺测、计数倒退或主辅关系不一致显示无效。数据只含固定状态和整数。两次读取界定的是播放附近的采样窗口，未按录音时钟定位每个字，不能据此认定某条流听到了完整唤醒词。该观察不改变原有通过条件。

0.15.1 候选增加显式的 `--wake-input-shape`，用于亮屏英文检查或英文亮屏／待机配对。Mac 校验固定 Daniel WAV 的帧数及两个摘要，已有的前台收音处于等待唤醒时才可启动观察。每条流在检测器入口、关键词增益和限幅前最多收集四秒，未读取的窗口七秒到期。设备断线、采集断点、会话变化或命中唤醒会清除窗口。结果仅含计数、相关度和状态。先用后半句定位，再单独核对名字。辅助流中途缺输入会明确标记，完整录音、说话者身份和真人召回率仍需各自验收。

0.15.3 在两路都匹配固定测试语音时，用两条新建的独立英文解码流回放同一个四秒内的窗口。逐帧使用原始输入、原增益及各自词表。报告的 `fresh_replay` 只含状态和两路布尔结果。断线、唤醒或会话变化中止回放，结果过期作废，样本只在内存中清除。在线漏检而新流命中支持继续检查窗口起点和解码历史。两者都漏检时，仍须区分窗口外输入、解码状态与房间或前端处理。实时唤醒判定和音频阈值沿用原值。

0.15.33 候选在同一个英文定向探针里增加可选的 `live_decoder`。报告记录第一个实际观测帧提交前，两路各自从最近一次新建流开始收到的样本数，以及观测窗口内因播报门控被拒绝的英文关键词结果数。计数表示送入样本的位置，不能还原原生模型状态。辅助流断档仍单列，旧版缺少新字段表示未测。命中、取消与换线的缓冲清理规则沿用，报告不增加音频或文本。

0.15.50 候选补充英文 AEC 前输入的同窗对照。仍使用上述显式 `--wake-input-shape`，不在普通对话或启动时自动采样。新版回执标记 `language=en`，增加 `raw_frames`、`raw` 和 `raw_fresh_replay`：仅原始输入完整且独立匹配固定名字及问句时，才用新建本地英文流复放；处理后的两路匹配不是这项复放的前提，原 `fresh_replay` 两路条件保持。缺帧或带播放风险的原始帧记为 `input_gap`，不拼接、不送原始复放；旧版两路报告仍可校验。

### 全语料的PCM标签一致性（2026-11-04）

`verify-wake`的schema2报告先准备全部固定语料，再检查PCM格式/长度/摘要及相同PCM的标签一致性，通过后才导入NumPy/原生库、加载模型和逐条件评分。新研究实际发现两种音色将Bumblebee与Bumbleby合成为同一音频；这不是可以凭文字标签解释的模型误触发。冲突、缺音频或坏PCM均返回`input_invalid`和退出2，保留原标签、摘要、相关case及准备状态；整轮不评分，不静默删除、重标或减少分母。模型依赖/资源前置失败保存`model_unavailable`再退出2，取消仍保存cancelled/退出130。

相同标签的重复PCM可以保留，但报告重复组数，不冒充独立音色。`passed`也要求每条有效摘要和无跨标签冲突；输入完整性只检查字节一致性，`phonetic_correctness_asserted=false`，不证明不同PCM必然发音正确。原25条语料、八种条件、实际推理循环AST、模型、增益和门槛保持，旧报告不按新规则追认通过。默认计划仍不合成、不加载模型或创建文件。

## 中文唤醒与停止指令的数字回归

```sh
# 只计划；普通 Python 即可，不载入 numpy/模型，不查询设备或创建文件
./cc8 verify-local-speech --model-root /absolute/model/workspace
# 明确执行；使用已准备的隔离模型 Python，不修改正在运行的助手
/path/to/evaluation/python cc8 verify-local-speech --model-root /absolute/model/workspace --execute
```

固定44条公开合成输入：Tingting、Meijia两种已核对安装的音色，每种140/170/200三档语速，各含“大黄蜂”、名字加问句、三种停止词和名字加停止词；另有八条近音或普通负样本。共18条含唤醒词、24条含停止词，六条同时包含两者；这些数量相交，不能相加当作样本总数。没有把与“大黄蜂”同音的“大黄风”当作可区分的负样本。

每条直接馈入当前源码的 ChineseWake 和 FastStopDetector 独立流，使用同一模型/锁、原有增益与门槛；每次新建流，按20ms帧输入，检查0/60/140/160/480/1000ms前导及两秒尾静音。六种时点都必须与预定的唤醒/停止结果集合完全一致。没有初始化、降阈值或额外关键词补偿。44条数字音频的264个条件观察不是264个独立说话样本。

model-root仅提供缓存；两份模型清单须先与执行源码中的受审清单一致，再用既有归档/逐文件摘要校验。先准备并检查全部固定 PCM，再加载识别器。如果生成失败、PCM 格式异常，或者完全相同的 PCM 被标注为不同的唤醒或停止结果，整批不评分，并记录冲突编号。报告绑定模型清单、实际源码、固定语料、合成PCM及原生扩展/动态库SHA；包版本相同的本地补丁也能区分。临时合成文件在每条结束后删除，结果仅保留owner-private JSON，不读旧录音、不播放、不联网、不操作CC8、不调用Dot。生产安装与配置保持原样。

漏检、错词、意外另一流命中、少样本、缺时点或合成失败均不能通过。正常失败退出2，已开始测量时取消保存cancelled并退出130；前置失败输出固定指引，异常正文不写报告。默认计划退出0不算验收。数字输入不覆盖声学回声、VAD、远场、电视噪声、真人口音、停止指令的端到端延迟或自播报抑制。
