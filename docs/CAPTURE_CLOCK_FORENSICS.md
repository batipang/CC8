# CC8 录音硬件时间戳的独立核对

2026-11-05，在当前这台 AILABS_S6／SDK27 上完成两段限时采样。生产保持后台 **0.14.86／原签名 APK0.9.37 code74**、源码 `9a5798f`；没有替换生产 APK、重启后台或修改音频处理。结果只适用于本机当前固件，不外推其他 CC8。

## 方法与实际结果

独立前台测试包使用与生产相同的 `VOICE_COMMUNICATION`、16 kHz、单声道 PCM16、`max(min*2,6400)` 字节缓冲和三参数阻塞读取。每段六秒，在同一个 AudioRecord 上停止、等待 250 毫秒、再开始第二段。设备端另有独立于 UI／Mac 的 16 秒停止看门狗。输入缓冲每次读取后立即清零；程序不播放声音，不使用 AEC、识别、相机、网络或音频文件。

每 250 毫秒读取一次 API，原样送入未修改的生产 `CaptureClockStats`，同时将原始数字字段保存在私有研究报告，供独立复核。以下变化率为相邻返回帧位置差除以返回时间戳差，**不是麦克风真实采样率的测量**。

| 项目 | 第一段 | 停止后再开始的第二段 |
| --- | --- | --- |
| 读取 PCM 帧数 | 96,000 | 96,000 |
| 设备段时长 | 6,059 毫秒 | 6,051 毫秒 |
| 录音器声明采样率 | 16,000 Hz | 16,000 Hz |
| API 样本数／返回成功数 | 23／23 | 24／24 |
| 可用锚点／帧位置范围失败 | 0／23 | 0／24 |
| 返回计数变化率中位数 | 47,999.782 Hz | 47,999.682 Hz |
| 返回计数变化率范围 | 47,993.118～48,006.898 Hz | 47,992.702～48,005.572 Hz |

47 个帧位置均为百亿量级正数，远超本次已读帧数及诊断范围；第二段开始时计数比第一段更大，没有观察到按本段清零。最先触发的拒绝原因均为 `invalid_frame_range`，不是负数回绕。其余原因计数为零不表示后续检查已通过。

[AudioTimestamp 字段说明](https://developer.android.com/reference/android/media/AudioTimestamp#framePosition)区分录音的完整 64 位帧位置和播放的低 32 位回绕计数；[AudioRecord 时间戳约定](https://developer.android.com/reference/android/media/AudioRecord#getTimestamp(android.media.AudioTimestamp,%20int))说明停止后重新开始时帧计数应清零。本机返回值与本次流的声明速率、计数范围和重启行为不符；尚未定位到具体 HAL／框架实现，不能只靠截取低位、除以三、减去首值或放宽范围将其认定有效。

## 权限、停止与证据范围

首轮在启动测试 Activity 前失败：固件 `pm` 帮助列有 `grant`，实际执行却返回 unknown command。原失败报告保留，未开始录音，临时包已移除。第二轮对摘要固定、与原助手签名一致的测试包，通过正常 UID2000 的系统 PackageManager API 单独授予其唯一声明的 `RECORD_AUDIO`，仍接受系统权限检查。辅助程序先核对包名、APK 摘要、独立应用 UID 和声明权限，调用后再核对摘要及授权状态；没有改变原助手的权限或正式安装器。

完整测试 Activity 的 JVM 资源检查覆盖显式启动、缺少／变化的权限、阻塞读取中退出、构造中退出及真实 16 秒看门狗；错误地移除工作线程权限复核的版本被拒绝。授权辅助程序另有 12 项受控 API 检查，包括错误设备／UID／摘要、额外权限、共享 UID 和系统拒绝。这些是离线资源／边界证据，不冒充实机声学测试。

第二轮共 62.735 秒，包括安装、授权、两段采样、移除和恢复。结束后核对临时包已卸载，授权仅针对该包；原 APK 摘要、后台实例保持，助手恢复前台且不开麦，原助手权限未改动。程序没有保存录音、照片或对话。报告／源码／构建及首次失败保存在本机忽略的 `capture-clock-forensics-20261105` 研究目录，尚不是通用项目命令。第二轮报告 SHA-256 为 `5ecd1428955ce4102b5fa8ac9823ca7be01cc11a02f4936df01c6078d74d5401`，独立复核报告 SHA-256 为 `fafc94d6c37e01b542bd74ec7cd1bed490e900f3034eca337ea1c99fea2ea474`。

## 对现用方案的含义

生产代码只在显式有界诊断中查询这组硬件锚点，正常会话仍沿用原有软件帧时间线。本次解释了此前录音时钟专项为何失效，**没有证明听错或误打断的根因，也没有修复或改变正常会话时钟**。

硬件锚点继续记为未确认，P0 不关闭。下一步按 [统一 TODO](TODO.md) 的 P0-01／P0-04，用独立近端刺激和播放参考核对早期声学重叠，并验证软件时间线与实际声音的对应；不能把 API 返回成功或本次数字采样替代真实起声、全双工、真人准确率或长期验收。正式 72 小时观察仍留到功能稳定后。
