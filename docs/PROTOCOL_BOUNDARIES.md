# 协议与传输边界回归（F-20）

边界回归基础来自后台 0.12.3。0.15.45／APK 0.9.43 候选增加显式协商的成对参考输入，协议仍为 2；原头字段与类型 1～4 保持，新增类型 5 只在双方确认后使用。此文描述实现和离线测试范围，实际部署另见 [当前部署](CURRENT_DEPLOYMENT.md)。

## 固定资源预算

| 输入/资源 | 限制 |
| --- | --- |
| 二进制包 | 4 字节长度前缀；包体 29～65536 字节；先验长度再读取包体 |
| PCM | 小端 PCM16、偶数字节、每包最多 6400 字节 |
| 头字段 | 类型为已知整数；generation 为 uint32，其余计数/时间为 uint64；不把 bool 当整数 |
| 事件 JSON | 严格 UTF-8、对象根节点、最多 16 层 / 4096 节点、受包长限制；拒绝重复键、非有限数和孤立代理字符 |
| 会话关键字段 | epoch/generation 等严格有界整数；开麦/唤醒/控制等布尔字段严格 bool；必要字段在状态修改前校验 |
| 认证 / 发现 | JSON 分别最多 1024 / 2048 字节；同一 JSON 解析预算；令牌格式、HMAC 与证书 pin 机制保持 |
| 握手 / 连接 | 同时一个未认证握手，最多 3 秒；OS listen backlog 4；注册通道每种最多一条，USB 优先 |
| 事件队列 | 512 项；投递等待最多 0.2 秒，饱和关闭该通道，不能永久阻塞读线程 |
| 属性测试 | Hypothesis 6.170.14，固定 seed=20261101，每组最多 150 个有效生成例，单例 deadline=500ms，无持久 example DB；8 组约 1200 个生成例及显式边界例 |
| TLS 故障测试 | 仅临时自签名证书与 loopback socket，不访问设备；3 个并发客户端、20 轮认证替换，超出 OS backlog 的连接不承诺接收；关闭/握手回收窗口 4 秒 |

解析失败统一为 ValueError，由已有连接隔离路径关闭对应通道。未知但结构合法的事件名保留前向兼容；不把形似真值的字符串用于开麦/切换状态。transport_hello 必须为整数协议版本 2，旧版本或 bool 不能成为 ready 通道。重连仍不自行开始采集。

## 测试与最小复现

```sh
python -m pip install --require-hashes --only-binary=:all: -r requirements-dev.txt
python tools/test_all.py --suite host
python tools/test_all.py
python tools/quality.py check
```

新 `test_protocol_fuzz.py` 覆盖任意拆包、合法头范围、PCM 奇偶与长度边界、截断位置、非法包长、事件 framing 与 JSON 解码分层、非法编码/重复键/深层结构/节点预算、错误字段类型及调用前状态不变。依赖缺失是失败，不跳过这组核心回归。

明确保留的最小回归包括：`{"event":"session_start","epoch":true}` 不得启动会话；带重复 token 键的认证必须拒绝；UDP 收到 1000 层数组后，下一条合法签名发现仍须响应。深层 JSON 在旧入口可抛出 RecursionError 并结束发现线程或上层事件处理，新入口将其转换为有界的拒绝，不吞掉后续合法连接。

TLS 另验证认证失败后恢复、非法 hello 不就绪、并发替换后仅一条已注册 Wi-Fi、队列饱和读线程退出，以及不完整握手期间关闭 hub 后所有受管线程退出。原有旧代播放完成、交接时丢弃旧音频/字幕、全断后停止采集与重连不自启回归继续运行，不重建另一套协议。

Linux 首轮并发测试暴露 TLS 握手异常。关闭策略现明确区分 shutdown 与最终 close：外部线程仅标记关闭并 shutdown 唤醒读取，由读线程退出后释放描述符，并等已有发送退出；避免 SSL_read 仍持有文件描述符时将其释放并复用于后续连接。确定性阻塞流用例验证外部关闭不会提前释放描述符，20 轮并发替换继续作为真实 TLS 回归，不能以降低到串行或跳过 Linux 代替。

生成失败由 Hypothesis 输出可缩减复现信息，固定种子可复跑；生成内容均为测试字节，不含用户录音。上述有限样本和资源预算不证明所有输入安全，也不代替 20 次真实 USB/Wi-Fi 切换、声学插话、待机或 72 小时观察。严格边界类型检查继续由 F-08 推进。


## 成对参考输入（候选）

默认 `capture_frontend=mono` 沿用单声道。后台显式选择 `paired` 且设备宣告整数 `paired_capture_version=1` 时，hello 才请求成对模式。hello 仅选择格式，不能开始录音；设备仍需当前前台的显式开麦请求／已授权打开流程，限时等待当前路由的格式确认。等待硬件所有者或格式初始化期间也消耗原八秒启动确认期限，超期不获取／启动录音，已初始化对象走原释放路径。旧后台不发此选择、旧设备不宣告能力时，均保留原格式。路由选择重置能力，迟到确认不能恢复已停止的录音。

设备请求 VOICE_COMMUNICATION、48 kHz、PCM16、索引掩码 0xF，创建后复核实际格式；不支持时在启动录音前释放失败对象并回退 16 kHz 单声道。释放未确认不继续创建回退对象。session_start／session_rebind 声明实际 `capture_frontend`、逻辑 `sample_rate=16000`、物理 `capture_sample_rate`、`capture_channels`，paired 还要求 source=7、48000／4。请求 paired 却使用 mono 时必须声明回退原因，且只接受固定枚举。相同录音 epoch 的重连不能换格式，不兼容的路由拒绝原录音，不自行重开。

成对路径在设备选择第 0、2 路，经同一有限脉冲响应滤波器（95 taps，7200 Hz、Kaiser 8.6）和相同抽取相位转为 16 kHz。滤波器只读已收到的输入，两个输出有相同的 47／48000 秒名义群延迟。第 2 路仍称候选参考，不因 API 通道数而认定硬件用途或独立麦克风数量。任意短读和不完整四路输入帧保留到下一读；只发送完整 20 毫秒成对包。

二进制类型 `MIC_PAIRED=5` 的 PCM 载荷是每帧 microphone、reference 两个小端 int16，非空、字节数必须整除 4，仍不超过 6400 字节。正常每包 320 个逻辑帧／1280 字节；头中的 frame、nanos 和样本率按逻辑 16 kHz 计，不按输入短整数数目或 48 kHz 计。后端须先接受匹配的实际录音格式且重新确认当前路由的能力才接收该类型，并在 DSP 入口要求完整 10 毫秒单位；旧 epoch 丢弃，同 epoch 的混合 mono／paired 包拒绝，保持原 80 毫秒前看及丢包断句隔离。

后端对两路做相同的因果二阶 80 Hz 高通，参考固定增益 16，交给现用 AEC3／中度降噪和无额外降噪停止支路。原数字播放时间线继续用于代次、暂停和语音门控归属，候选参考不能自动成为可信的新回答或唤醒。成对 AEC 按共同采样网格预热，不对两路重新拟合偏移；数字时间线仍按原方法独立对齐供门控与证据使用。`reference_shift_scope=digital_gate` 明确标识此时的数字偏移不作用于成对 AEC，也不把共同网格冒充物理零时延。校准缓存最多保留 7.5 秒。Mac 在传输切换时撤销旧路由的成对能力确认，并清理旧前看队列及高通状态。设备在同一路由的同一 native 录音中保留连续 FIR 相位；停止及新录音清理其样本、滤波和拼包状态。已部署的 0.15.48／APK 0.9.45 还在路由激活改变后由录音 worker 清空 FIR／拼包历史，避免旧部分帧拼入新路由；跨激活的一次阻塞读取整块丢弃。

原 16 kHz AudioTimestamp 诊断在 paired 模式标为不支持，绝不将 48 kHz 原始硬件位置冒充 16 kHz 证据或简单缩放为已验证时钟。设备只读状态和后台健康状态分别报告实际格式；未启动的 native 录音不报告为已验证格式。此候选不改变正常自动开麦授权、后台退出停采、相机许可、MiniMax／Dot 选择或 UI。

离线覆盖实际 Java 转换器、录音工厂与 worker 的短读、抗混叠、饱和、格式／编码错误、回退释放、等待 hello 期间停止、迟到能力、不兼容重连、成对载荷与逻辑时钟边界，以及 Python 的协商、旧通道、校准失败所有权和有界缓存。组件声学记录见 [词语保留对照](ASR_EVALUATION.md#同一采样中的候选参考与外部语音)。新候选的实时语音、普通音量、传输切换和长时间运行仍需单独实测，离线结果不关闭 P0。

## 按线路激活隔离设备输入

已部署的 0.15.48／APK 0.9.45 在协议 2 上协商 `route_envelope_version=1`，新增类型 6，只用于设备向后台发送。包头保持，载荷为 16 字节本次激活随机值、1 字节原类型（1～5）及原载荷，禁止嵌套；原 PCM 和总包长预算保持，事件可用字节相应减少 17。每次激活同一连接也换随机值，MIC 在当前 Start／Rebind 被接受前丢弃。详见[录音线路准入](CAPTURE_ROUTE_ADMISSION.md)，实机验收仍单独推进，旧端兼容路径不计入新隔离保证。

## 协商后台输出的激活归属

0.15.49／APK 0.9.47 候选另协商 `route_output_version=1`，复用类型 6，只在双方支持时对后台应用消息启用。激活控制携带 32 个十六进制字符的进程标识及 1～2^63−1 的递增序号；设备拒绝乱序、重复或同一已协商连接降级，后台重启使用新进程标识。失败写入不复用序号，存活线路重新确认后才恢复应用就绪。LAN 配置同样受封套保护，诊断仅导出版本 0／1。完整兼容、资源边界和测试范围见[后台输出归属](HOST_ROUTE_OUTPUT.md)。
