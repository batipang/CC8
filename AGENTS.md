# CC8 development conventions

Keep APK installation in normal Android mode, through the verified engineering shell / stock PackageInstaller path. Require AILABS_S6, SDK 27, UID 2000, one unambiguous USB target, hash checks and actual installation completion. Do not introduce Root, flashing, partition writes, BootROM tools, network ADB or OEM service termination.

Keep private credentials, signing keys, pairing material, device identifiers, raw reports and user recordings out of Git. Build outputs, local SDK/JDK/config and model weights belong in ignored local directories. Preserve signature compatibility when updating existing apps; do not silently uninstall or clear data.

Android code uses Java and platform widgets, minSdk 21, with newer API guards. Camera capture requires explicit foreground user action and runtime permission. The user explicitly requested automatic voice on opening the assistant (2026-11-01); a visible MainActivity opening may arm one bounded microphone start after connection and permission. Stop resources on background or loss of every authenticated transport. Reconnect must never automatically enable capture. Never open a camera or microphone solely to verify an unrelated code change.

The assistant is 大黄蜂 / Bumblebee. Preserve its approved head-only avatar and separate particle waveform. USB has priority over paired TLS Wi-Fi. Reject stale audio, captions and results on cancellation / handover. Dot inherits owner-configured tools and permissions without automatic approvals. MiniMax is the default bounded utterance ASR and TTS; local AEC/VAD and interruption stay on the Mac.

Run meaningful host tests and Android compile/lint for changes to those components. Distinguish offline test coverage from physical-device validation; do not claim arbitrary firmware compatibility, proven AEC or complete full-duplex performance from API availability alone.

DesktopEntryService is a UI-only foreground service authorized for reopening the app from the OEM desktop. It may keep a silent notification and an explicitly permitted overlay after Home, but must never hold microphone/camera/audio/network resources; the entry may open MainActivity, whose user-requested opening flow can start voice. Hide its overlay inside assistant/camera pages. Close TLS sockets off the UI thread without relaxing StrictMode. Preserve the original signing certificate when deploying updates.

Automatic voice is one-shot per MainActivity creation or explicit new open intent, with a 30-second connection wait. Manual Stop cancels the request; transport reconnection and ordinary onResume alone cannot rearm it. Home still stops capture. For text-only announcements, maintenance or unrelated QA, use launch.py --no-auto-voice / --no-open or the auto_start_voice=false intent extra. Do not open an automatically recording UI merely to inspect status.

Vision integration (explicit user request 2026-11-01): a foreground Look button or accepted explicit camera/scene voice request may capture one visible bounded frame and send it over the existing authenticated channel to Dot for analysis. Never capture on startup, reconnect, unrelated look-up language or model tool inference alone. Stop/release on cancellation/background/transport change. Bind every frame to a bounded request ID and generation; reject stale/unsolicited/oversized data, never silently reuse a picture. Keep voice/button-analysis JPEGs in memory, out of application files/logs/Git; inline image input follows the owner's existing Codex configuration and model service. This does not authorize continuous video, recording or unattended vision.

Desktop control (latest explicit request 2026-11-01): an owner-requested desktop Dot photo may trigger one visible 5-second preview in the foreground assistant through owner-only local IPC, save the returned JPEG to device-access/private/photos/ (directory 0700, file 0600), and show it inline in the requesting Dot chat. This is the explicit exception to RAM-only image handling; voice/button analysis remains unchanged. Keep photos out of Git/logs/public links. Preserve mic state, cancel on background/disconnect/user Stop/client disconnect, reject stale generations, and never automatically retry an unconfirmed photo. No unattended camera or startup capture.

Task/reminder UI: preserve the approved reference composition in docs/design/bumblebee-orbit-v1.png, with the owner-requested local-time orbit clock and segmented playback rail documented in docs/WORKSPACE.md, and the owner-selected slanted energy-cell playback bar. The latest caption request supersedes 42sp: default 36sp, fit exactly three complete lines using actual layout metrics, never show clipped fourth-line fragments or overlap playback progress. Preserve the larger auxiliary type requested by the owner. Keep speaking status below the separate waveform, outside the entire orbit. Display real task receipts, never seeded demo tasks or fictitious progress. Completed work must remain completed when narration is stopped. Task history is memory-only; reminders are explicit owner requests saved atomically in owner-private storage, delivered only with a foreground authenticated CC8 connection and an idle audio pipeline. Do not start capture or silently launch background UI to deliver reminders. Stream only explicitly final_answer agent text, never commentary or reasoning; preserve completion fallback for servers without phase metadata.

Startup voice (user request 2026-11-01): the only normal spoken opening is “汽车人，变形！” in the current Bumblebee voice. Use that bounded PCM as the calibration reference, then wait silently for the calibration window; do not restore the old female reference or replay the greeting after calibration. Keep cancellation isolation and do not skip echo alignment.

Code quality (user request 2026-11-01): use docs/TODO.md as the single backlog for both functional P-IDs and engineering F-01 through F-20; docs/ToFix.md is an index, not a second live checklist. Apply its per-change quality requirements, including relevant regression tests and actual login/minimal-PATH checks for service/tool changes. Establish the test/CI baseline before broad feature expansion. Keep mass formatting and responsibility refactors separate from functional commits; document verification limits and do not close physical-device tasks with offline results. Public-release license/theme work is conditional, not authorization to change the current personal avatar, name, provider or credential storage.

Development checks: install requirements-dev.txt in a separate dev venv; run python tools/test_all.py and python tools/quality.py check with JDK 21+. Format only via the pinned tools, keep pure formatting commits in .git-blame-ignore-revs, and do not use the voice-runtime environment or device capture just to validate tooling. Optional private-audio replay requires explicit --with-private-audio; missing core dependencies must fail, not skip the suite.
